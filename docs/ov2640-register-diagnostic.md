# OV2640 노출 설정의 유한 레지스터 진단

실제 노출 구간 상한을 계산하기 전에 현재 센서 설정을 확인하는 진단이다. **레지스터 읽기 성공은 노출 상한 검증이나 학습 적격 판정이 아니다.** 기존 영상 100ms·M4 20ms·앵커 15초·원본 저장 250ms 조건은 변경하지 않는다.

## 전용 빌드와 범위

```bash
pio run -d firmware/esp32cam -e esp32cam_register_diag
python3 -m unittest tests.test_ov2640_register_native tests.test_ov2640_register_probe
```

기본 환경은 `esp32cam`이다. `esp32cam_register_diag`를 명시해야 진단 빌드가 생성된다. 두 환경은 빌드 산출물을 분리하며, 빌드는 업로드하지 않는다. 전용 환경은 기존 저장 Wi-Fi 설정만 사용하고 새 인증정보를 입력·저장하거나 실패 후 재부팅하지 않는다. 정상 카메라의 HTTP 기능을 대체하므로 기존 화면·서비스가 진단 노드를 호출하지 않도록 해야 한다.

기본 QVGA·JPEG quality 15·요청 XCLK 20MHz로 초기화한다. `/diagnostics/ov2640?nonce=<16자리 소문자 16진수>` GET만 처리한다. 일반 `/capture`, 프로필 변경, 스트림과 이미지 반출은 제공하지 않는다. **센서 초기화는 설정 쓰기와 내부 DMA 프레임 획득을 포함한다.** 이미지 요청·반출·저장이 0이라는 뜻이며 센서가 빛을 읽지 않는다는 뜻은 아니다.

## 읽는 값과 오류 보존

| bank | 레지스터 | 용도 |
|---|---|---|
| 센서 1 | `0A 0B 1C 1D` | 센서 식별 |
| 센서 1 | `03 0C 11 12 13` | 모드·클록·자동 노출/밴딩 |
| 센서 1 | `04 10 45` | 분할된 현재 노출 코드 |
| 센서 1 | `2A 2B 2D 2E 46 47` | 행/프레임 및 추가 타이밍 설정 |
| 센서 1 | `17 18 19 1A 32 48 49` | 센서 창·줌 관련 조건 |
| 센서 1 | `4E 4F 50` | 밴딩 단계 설정 |
| DSP 0 | `05 C2 D3 DA E0 86` | DSP 우회·AEC 선택·출력 클록·형식·리셋·축소 상태 |

데이터 34바이트와 bank 확인·복원으로 정상 경로는 41개 논리 작업이다. 각 읽기는 주소 단계와 데이터 단계의 I²C 오류를 따로 남긴다. 오류를 `0`이나 `255` 데이터로 바꾸지 않는다. 시작 bank를 읽지 못하면 쓰기를 하지 않는다. bank 선택이 실패해도 원래 bank 복원을 한 번 시도하고 다시 읽어 확인한다. 진단의 레지스터 쓰기는 bank 선택에만 한정된다. 초기화 때 드라이버가 쓰는 센서 설정은 이 범위와 구분한다.

기존 드라이버의 숨은 bank 캐시는 수정하지 않는다. 진단 빌드의 단일 루프만 SCCB를 사용하고 DMA 작업은 SCCB를 호출하지 않는다. 오류·bank 복원 실패 뒤에는 같은 부팅에서 재시도하지 않고 카메라를 해제·전원 차단 핀으로 정지시킨다.

## 시간·횟수 제한

- 같은 부팅에서 최대 3회, 새 nonce만 사용한다. 첫 유효 요청부터 30초, 진단 초기화 시작부터 60초가 지나면 닫는다. 새 읽기는 종료 여유 1초가 남아 있어야 시작한다.
- snapshot 예산은 750ms다. I²C 한 단계는 최대 10ms를 요청하며, 오류 뒤 bank 복원은 별도 정리 경로다. 실패 snapshot도 원본으로 남는다.
- HTTP 요청 전체를 250ms·1536바이트로 제한한다. 응답도 비차단 전송으로 250ms를 제한해 느린 입력·수신으로 루프를 계속 붙잡지 못하게 한다.
- 3회 완료·오류·기한 종료 시 카메라 드라이버 해제와 PWDN HIGH를 요청한다. 세 번째 성공 응답에는 `trialClosed=true`, `cameraDeinitStatus=0`이 필요하다.

위 제한은 소프트웨어 예산이다. MCU 스케줄링과 물리 전원 차단 시간을 측정한 보장은 아니다. 특히 초기 `esp_camera_init` 내부 호출을 이 루프가 선점하지 못한다. 실물 시험에서는 별도의 준비 대기 기한과 사용자 전원 차단 절차를 정해야 한다. 원시 응답의 종료 상태도 실제 전압이나 모터 OFF를 입증하지 않는다.

## 승인된 실행과 오프라인 감사

실물 실행에는 현재 장치와 구체적인 승인 범위가 필요하다. 업로드 명령을 자동 실행하는 기능은 없다. 아래 값은 승인된 장치 주소와 **바이너리 안에 저장된 app ELF SHA256**으로 대체한다. 전체 `.bin` 파일 SHA256과는 다른 값이다.

```bash
python3 tools/probe_ov2640_registers.py --execute \
  --url "$APPROVED_CAMERA_URL" \
  --expected-app-elf-sha256 "$APPROVED_APP_ELF_SHA256" \
  --output-dir .local/ov2640-register-run
python3 tools/probe_ov2640_registers.py --audit .local/ov2640-register-run
```

호스트는 최대 3회·총 30초·요청당 2초·응답 이후 간격 1초·재시도 0회로 실행한다. 요청 의도를 영속 저장한 뒤 전송하고, 실패·부분 응답·취소 원본 및 시도 분모를 보존한다. 저장 중 취소 신호는 해당 파일과 참조 기록을 마친 직후 처리한다. 첫 실패, 부팅·펌웨어·설정 변경이면 중단한다. 34바이트의 정확한 순서와 bank 복원, 종료 상태를 원본에서 다시 검사한다. 현재 노출 코드의 변화는 허용하되 `04`·`45`의 노출 외 상위 비트는 계속 비교한다.

감사의 `evidenceIntegrityOk`는 실패 기록에도 참일 수 있다. `successfulRun`은 세 요청의 진단 검사가 모두 통과했는지를 별도로 뜻한다. `exposureUpperBoundUs=null`, 광학 검증·학습·제어 적격 false는 유지한다.

## 남은 물리 근거

자동 AEC는 읽는 도중 분할 값을 바꿀 수 있으므로 `atomicSnapshot=false`다. 세 번 같은 값이 나와도 최악 노출 상한을 증명하지 않는다. `aec_value`는 µs 단위가 아니며 `ledc_get_freq`는 설정에 따른 주파수 계산값이지 실측 클록이 아니다.

현재 근거에는 전체 노출 구간을 계산할 센서 타이밍 모델, 실제 클록 오차, 설정 적용 시점, 센서 내부 처리의 과거 노출 기여 여부가 더 필요하다. 출력 행과 원시 행을 연결하려면 이 목록에 없는 DSP 창/축소 설정도 필요할 수 있다. 데이터시트와 설치 드라이버의 일부 모드 코드 차이 때문에 값만으로 상한을 자동 계산하지 않는다. 이 진단은 그 다음 판단에 필요한 입력을 보존한다.
