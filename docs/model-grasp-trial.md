# 고정 모델의 순차 접근·닫기 연결

[상대 상태 모델](relative-action-selection.md) · [수집 방법](manual-data-collection.md)

닫기 이후 들기는 [M4 위 방향 전용 경로](m4-up-commissioning.md)의 별도 고정 모델과 연결한다. 수동 식별·고정 평가·모델 선택을 구분한다. 기존 3점 관측 연결은 [2026-11-08 기록](evidence/2026-11-08-close-lift-integration.md), 별도 M1 scalar 코어의 실제 닫기·재선택과 관측 기한 실패는 [2026-11-13 기록](evidence/2026-11-13-model-selected-m1-close.md)을 따른다.

`learning/model_grasp_trial.py`는 저장된 물체·양턱 상대 상태 모델로 위치 조정 후보를 선택하고, 실제 새 관측으로 목표 도달을 확인한 뒤 닫기 후보 하나를 선택하는 제한 시험 코어다. 기존 `relative_action_learning.select()`와 `SequencePort`를 재사용한다. 생성자·모델 로드는 장치에 접근하지 않는다. 기본 실행 CLI나 장치 검색·자동 학습은 제공하지 않는다.

코어의 소프트웨어 검증은 합성 관측과 모의 컨트롤러로 수행했다. 관측 어댑터의 실제 원본·모델 계약 진단과 [별도 수동 수집의 구동 전 예측 확인](relative-action-selection.md#2026-11-07-자세를-분리한-학습과-구동-전-예측-확인)은 수행했지만, 이 코어가 선택한 명령으로 실물 순차 제어를 실행하거나 집기에 성공한 결과는 없다. 현재는 분석가 점 검토와, 별도로 등록한 고정 구도의 패치·원호 특징 관측을 구분한다. 범용 물체·턱 인식이나 파지 상태 인식의 완성은 아니다. 분석가 기준점·실제 구도와 현장 확인에 의존하므로 `observationAssisted=true`, `fullyAutonomous=false`를 유지한다. 방향·출력·기간의 선택은 고정 모델의 후보 비교 결과만 사용하며, 사람이 대신 고른 명령이나 규칙 기반 대체 명령을 끼워 넣지 않는다.

## 개발 관측기를 사용하는 비접촉 접근 실험

`learning/development_approach.py`는 별도 스키마
`motionbrain.development_noncontact_approach.v1`로 M3 위치 조정만 연결한다.
`ApproachModelBank`는 모델·관측기·현장 검토 원본의 해시와 현재 부팅·호스트 시계,
목표·후보·최대 4명령·요청 기간 합계 최대 2.6초·전체 최대 120초를 고정한다.
350/450/650ms 중 선택한 **한 모델의** 출력·시간 정책을 그대로 사용하며,
원래 모델과 고정 평가 결과는 수정하지 않는다. 기본 `FrozenModelBank`의 개발 모델
거절과 기존 접근·닫기 스키마는 유지한다. 새 계약은 제한된 실험의 범위이며
제어 적격·독립 추적 정확도·집기 성능을 검증 완료로 바꾸는 기능이 아니다.

현재 현장 검토의 외부·집게 원본 해시를 묶은 별도 admission이 필요하다.
카메라 재부팅을 연결할 때는 과거 모델의 관측 계약과 실제 현재 관측을 각각
보존하고 부팅 ID 하나의 차이만 명시적으로 연결한다. 구도·물체·관측기·영상 크기·
상태 의미가 달라지면 이 연결로 덮어쓰지 않는다. 새 외부 구도 등록은 해당 구도의
목표 좌표와 보호 경계도 함께 검토해야 하며 과거 수치를 자동 이식하지 않는다.

`ApproachObserver`는 기존 `observe_bound_frame()`의 fresh 원본 검사를 재사용한다.
상태의 세 번째 값은 보이는 두 턱끝의 **수평 폭**이며 유클리드 거리나 실제
개구폭으로 바꾸지 않는다. 부분 관측·기준 이미지 자체 재생·원본 변경·부팅 변경은
실행에 사용하지 않는다. `ApproachExternalGuard`는 별도 외부 원본에서 고정 자세·
물체·방향별 이동 범위를 확인하며 모델 대신 방향을 선택하지 않는다. 검토 거절과
근거 불일치는 정지한다. 이 보호 검사는 깊이·접촉·충돌 여유의 보정된 계측이 아니다.

새 구도에서 사용자가 수동 배치한 닫기 준비 자세를 기준으로 삼을 때는 별도
`CurrentSceneExternalGuard`와 `motionbrain.current_scene_external_guard.v1` 계약을 쓴다.
동일 정지 기준의 템플릿 중심·전완 중심·물체 중심을 정확히 결합하고, 기준 이미지에
편입하지 않은 fresh 프레임으로 정지 추적을 확인해야 한다. 기본 범위는 물체 박스
변화 3px·전완 기준 거리 10px이며, 명령 전 상대 변화는 UP 최대 6px·DOWN 최소
0px다. 이 방향별 사전 조건과 사후의 전체 범위 검사는 구분한다. 같은 기존 monitor
응답에서 M4 고정도 검사하며 추가 HTTP를 만들지 않는다. 현재 구도용 수동 선언
경계이며 과거 목표의 방향 한도 이식이나 충돌·접촉 보증이 아니다. 출력은 M3의
60%·350ms 고정 정책만 받는다. 처음부터 준비 목표 안인 경우는 수동 초기 배치로
기록하고 모델이 접근한 성공으로 세지 않는다.

`DevelopmentApproachTrial`은 기존 반복 코어의 매회 새 관측·OFF 후 3초 대기·
실패 무재송을 재사용한다. 실행 직전 모델 선택·관측 나이·결정 기한·계약 불변을
다시 확인하고, 실제 출력 receipt의 고정 시간 정책도 검증한다. 사전에 고정한
관측 개선 부족·이전 상태 재방문·예측 잔차·비접촉 범위·총 예산에서 중단한다.
최초 관측이 이미 목표 안인 경우와 명령 후 도달을 명령 수로 구분하며,
`observed_target_reached`는 접근 영상 목표 도달일 뿐 파지·들기 성공이 아니다.
닫기·들기·내려놓기·해제 명령은 이 경로에 포함하지 않는다.

관련 합성 시험은 다회 보정·미지원 무구동 보류·정체·왕복·실행 실패·계약 변조를
검사한다. 이 경로의 실제 움직임 추적과 실물 접근 성능은 별도 현장 검증 대상이다.

수동 시작 배치도 실행 전에 결과 범위를 검토한다.
`learning.manual_positioning_assessment.assess_manual_positioning()`은 고정 모델과
검토된 계약의 `expected_training_rows_sha256`와 원학습 행의 해시를 먼저
대조하고, 문맥·식별·저장 통계를 확인한 뒤 같은 명령의 관측 변화 최소·최대로
예상 도착 범위를 만든다. 현재 상태·도착 범위가 기존 보호 범위를 벗어나거나
명령 지원이 없으면 거절한다. 목표를 함께 주면 도착점이 이미 목표 안인지,
후속 모델의 지원·개선 후보가 있는지도 확인한다. 사후 범위 검사는 이 사전 검토를
대신하지 않는다.

이 함수는 순수한 계획 검사이며 장치 요청·재학습·실행 권한 부여를 하지 않는다.
`review_required`도 실행 승인이 아니다. 관측 변화의 경험적 범위는 미래 결과의
보장 범위나 신뢰구간이 아니며, 호출자는 명령 전 새 관측·고정 모델/원본 결합·
현재 현장 조건·실행 한도를 별도로 확인해야 한다. 기대 해시를 호출 직전 행에서
새로 만들어 검증을 대신하지 않는다. 범위 이탈 뒤의 자동 복귀나
실패한 준비 동작의 재전송 경로는 제공하지 않는다.

`OneWayManualRecoveryGuard`는 기존 접근 범위 밖에서 UP 한 번으로 복귀하는
별도 수동 실험 계약이다. 기존 접근 guard를 완화하지 않는다. 입력은
`[3,24,124]`~`[3.5,24.5,124]`, 외부 전완 반경은 최초 검토에서만 11px이며,
UP 60%·350ms 후에는 원래 집게 영상 범위와 외부 반경 10px로 복귀해야 한다.
원학습 UP 3건의 원본·관측 변화와 예상 도착점을 검사하되 실제 복귀를 보증하지 않는다.
별도 승인 파일을 요구하고 첫 검토부터 승인 범위를 영구 소비하며, 거절·실패 후
새 세션으로 다시 시도하지 않는다. 호출자는 승인 파일의 `fullPlanSha256`가
통합 실행 계획과 일치하는지도 확인해야 한다. 수동 복귀와 그 자료의 새 모델 학습,
고정 후 모델 선택 접근은 분리해 기록하며 원래 실패·고정 모델·평가를 보존한다.

M1의 `m1_shaft_ridge.v1`은 shaft 간격 1개만 예측하므로 3차원 모델 은행에
가짜 XY를 붙여 넣지 않는다. `m1_shaft_learning.select()`가 같은 scalar 계약에서
짧은 CLOSE와 정지를 비교하며, 지원 밖 후보·동률·최소 개선 조건을 보존한다.
shaft 목표는 접촉이나 파지 목표의 자동 판정이 아니다.

`m1_shaft_learning.fit_after(rows)`는 같은 입력·원본 검증을 사용하면서
명령별 **사후 shaft 간격 자체**를 표준화한 사전 간격으로 회귀하는 별도 API다.
정규화 계수 `alpha=1`의 ridge이며 모델 schema는
`motionbrain.m1_shaft_after_ridge.v1`, `regressionTarget=after`로 분리한다.
기존 `fit(rows)`의 delta 회귀와 등록·모델 해시를 바꾸지 않는다. 새 모델에도
명령별 평균 delta를 보존하여 입력 간격+평균 delta인 `commandMean` 기준선과
비교하고, 무변화 기준선도 따로 평가한다. 개발 자료에서 사후값이 비슷해 보이는
현상만으로 포화·상태 의존성이나 기준선 대비 우월성이 입증되지는 않는다.
고정 후 새 관측에서 평가해야 하며 `independentTest=false`와
`controlEligible=false`를 유지한다. 실물 연결은 명시적인
`geometryPolicy=observed95-grasp650-v1`에서만 가능하고, 기존 다른 정책에
자동 적용하지 않는다. 이 API는 실제 접촉·보유·들기 성공을 판정하지 않는다.

현재 M1 실험에는 `M1ShaftSceneGuard`와 `M1ShaftSourceObserver`를 사용한다.
원본 JPEG·메타데이터·부팅·shaft 등록을 재검사하고 외부 전완과 물체 경계를 각각
3px, M4를 196.17±0.5° 안에 고정한다. 기본 계약의 CLOSE는 40%·200/350ms 또는 기존 M1 수집 상한 안의 60%·650ms, 수동 준비
OPEN은 40%·350ms 또는 60%·650ms만 허용한다. OPEN은 모델 시험 후보가 아니며, 별도 수동 준비 예산과 이동 여유 검사를 요구한다. guard의 `m1-default-sequence-monitor-v1`은
계약 라벨이며 실제 전송에는 기존 기본 monitor(`monitor_policy=None`)를 쓴다.
관측 거절 뒤 이전 검토 cache로 출력하지 않는다. 실행 중 연속 접촉·힘 검사는 아니다.

턱이 물체를 가려 색 영역이 나뉘는 M1 구도는 새 설정의
`objectObservationPolicy=fixed_reference_two_fragment_occlusion_v1`로 명시해야 한다.
정확히 두 영역이 각각 원래 물체 박스의 3px 여유 안에 있고, 합친 외곽도
기준의 3px 안이며, 보이는 면적 합이 원래의 70–105%일 때만 고정 물체의
가림 가설로 취급한다. 다른 큰 영역·외곽 소실·면적 부족은 거절한다.
기존 기본 보호 검사와 이 필드가 없는 M1은 계속 큰 영역 한 개만 허용한다.
이 처리는 물체 동일성·접촉·깊이 검증을 대신하지 않는다.

`M1ShaftTrial`은 고정 모델에 실제 학습 근거가 있는 CLOSE 후보와 정지를 비교한다.
기본 정책은 최대 4명령·45초 안에서 OFF 후 3초가 지난 새 관측으로 재선택하며,
관측 3초·결정 0.25초 기한을 RUN 직전에 다시 검사한다. 예측 잔차 3px 초과,
목표 오차 감소 0.2px 미만 또는 관측·실행 실패에서 멈추고 자동 재송신하지 않는다.
포트·현장 보호·실행 원장·자원 정리는 호출자가 연결한다. 처음부터 목표 안인
0명령 종료와 모델 명령 후 shaft 목표 도달을 구분하고, 두 경우 모두 접촉·파지를
입증하지 않는다. 이 코어의 소프트웨어 검증과 실제 파지 검증은 구분한다.

새 `current_m1_close` 단면 preset은 오른쪽 탐색 ROI만 `[190,260]`으로 넓힌다.
기존 기본값 `[205,260]`과 대비·행 수·잔차·모호성 거절 기준은 유지한다.
새 등록 해시로 자료를 분리하고 별도 정지 원본을 확인해야 한다. 기존 모델의
지원 범위를 확대하거나 닫힘 추적·접촉 성공을 인증하는 변경이 아니다.

`current_m1_distal_shaft`는 기어 연결부를 피한 영상 행 70–90의 직선 shaft를
맞추고 그 중심선을 행 55까지 외삽하는 별도 등록이다. 행 55의 픽셀을 직접
검출한 값과 구분하며, 관측 구간의 가까운 끝에서 15px·중앙에서 25px 떨어진
외삽이다. 기존 대비·행 수·잔차·폭 변화 기준은 유지한다. 외삽 불확실성은
보정되지 않았으며 새 등록으로 원본을 모두 다시 관측하고 새 현재 정지 원본을
검사해야 한다. 사후 수정한 관측으로 원래의 실패 판정이나 실물 제어 성과를
소급 변경하지 않는다.

`current_m1_observed_shaft95`는 영상 행 95에서 직접 보이는 유일한 어두운
턱축 구간의 중심을 측정하는 별도 관측 계약이다. 행 70–115에서 같은 구간을
포함하는 주변 직선부가 기존 유효 행 수·관측 범위·대비·잔차·폭 변화 검사를 통과해야
한다. 주변 창이 여러 개라는 이유로 다른 측정값을 선택하지 않으며, 측정 행의
실제 복수 구간·누락·품질 부족은 거절한다. 여러 창의 합집합이 품질 검사를
통과했다고 바꾸지도 않는다.

이 상태는 기존 행 55 중심선 추정값과 다르므로 새 등록과 모델·목표·허용 범위를
따로 정해야 한다. 기존 118px 같은 실험 경계를 새 좌표에 자동 이식하지 않는다.
그 경계는 기구 안전 한도로 보정된 값이 아니다. 저장 원본의 사후 재관측과
합성 회귀 검증을 새 현장 검증·계측 정확도·접촉·실물 제어 성공과 구분한다.
같은 날 계약 고정 후 얻은 별도 정지 영상 2쌍에서도 턱축 관측과 고정 자세
검사가 통과했다. 모터 명령은 0회이며, 개폐 동작 중 추적·모델 닫기·접촉·
계측 정확도의 검증을 대신하지 않는다.

2026-11-13 같은 구도의 앞선 M1 수동 묶음은 총 4명령이었다. 40%·200/350ms는
각 1회로 영상상 변화가 미미했고, 60%·650ms는 2회 실행·OFF를 확인했다.
첫 650ms 이후 기존 관측이 거절돼 별도 distal 계약으로 원본을 사후 재관측했고,
다음 650ms 이후에는 그 계약도 사후 턱축 추적을 거절해 추가 출력을 중단했다.
이 앞선 수동 묶음의 모델 선택 M1 명령은 0회이며, 닫기·파지·들기의 성공 결과가 아니다.
새 관측 계약도 전체 닫힘 범위의 추적 검증을 마치지 못했다. 위 소프트웨어
검증을 실물 모델 제어의 성공이나 실패 없는 수집 결과로 해석하지 않는다.

## 직접 관측 행95의 국소 닫기 시험

새 `commandPolicy=observed95-local450-v1`은 정확한
`current_m1_observed_shaft95` 등록에만 결합된다. 모델 닫기는 60%·450ms만
허용하며, 별도 수동 준비는 OPEN 60%·450/550/650ms 또는 40%·250/350ms다.
이 필드가 없는 기존 계약의 허용 후보는 유지한다.

별도 `commandPolicy=observed95-lower-close-v1`은 같은 직접 row95 등록에서
CLOSE 60%·200/250/350/450ms를 허용한다. 수동 OPEN 후보는 위 local450
정책과 같다. 허용 목록은 수집·실행 계약일 뿐 학습 지원의 대체물이 아니다.
실제 모델에 해당 명령의 학습 항목이 없으면 모델 후보를 만들어 넣지 않는다.

`M1ShaftTrial`의 같은 이름 `geometryPolicy`는 새 등록 SHA와 명시적인 시작
구간을 모델 관측 계약에 결합한다. 이 실험의 영상 범위 84~139.5px,
수동 자세 참조 목표 85.3±1.5px는 기존 행55 값의 변환이나 접촉·기구 안전의
보증이 아니다. 첫 새 관측은 시작 구간·학습 입력 지원 안이며 목표 밖이어야 한다.
목표를 학습 결과의 최솟값으로 자동 정하지 않는다.

`geometryPolicy=observed95-lower-close-v1`도 같은 후보를 사용한다. 시작 구간의
하한은 목표+허용오차인 86.8px보다 커야 하며 상한은 137px 이하다. 최초 새
관측은 선언한 시작 구간과 실제 후보의 학습 입력 지원을 각각 만족해야 한다.

다회 local450 시험은 목표 미도달 예측 상태가 같은 닫기 명령의 입력으로도
지원될 때만 후보를 남긴다. lower 정책에서는 다른 CLOSE 후보로의 전환도
가능하다. 그 다음 상태에서 후보 자신의 학습 입력 지원, 예측 범위와 최소
예상 개선 0.25px 초과를 만족하는 후보가 하나 이상 있는지 한 단계 검사한다.
외삽이나 모든 미래 상태의 목표 도달 보장을 뜻하지 않는다. 실제 다음 명령은
예측 상태가 아닌 OFF 후 새 관측에서 다시 고른다.

명시적 `maxCommands=1` 독립 시험에서는 다음 명령을 계획하지 않으므로
그 후속 입력 검사만 생략한다. 최초 지원·예측 범위·실제 OFF·새 사후 관측·
잔차 3px·실제 영상 범위 검사는 유지한다. 다회 시험에 남은 예산이 1이라는
이유로 이 예외를 자동 적용하지 않는다.

에이전트의 시각 판독 시간이 필요한 별도
`geometryPolicy=observed95-reviewed-lower-close-v1`만 전체 기한 상한을
120초로 늘린다. 기존 기본·local450·lower 정책은 45초 상한 그대로다.
후보·84~139.5px 범위·85.3±1.5px 참조 목표·최대 4명령·등록 해시·후속 지원·
fresh 3초·결정 0.25초·OFF 후 3초·잔차 및 정지 기준은 바꾸지 않는다.
판독 대기 뒤에는 원본 시각을 바꾸지 말고 새 fresh 영상을 확보해야 한다.

이 기한은 촬영 세션 수명과 별개다. `ManualCollection(recording_seconds=120)`을
명시하면 기본 60초와 분리된 촬영·프레임·바이트 예산을 쓰며, 110초 초과 새
pulse 거절과 115초 자동 종료가 적용된다. 기본 세션의 50초 pulse 경계·55초
자동 종료는 유지한다. 코어의 실제 기한은 정리 여유를 포함한 세션의 남은
시간보다 길게 부여하지 않는다. 관련 196개 소프트웨어 회귀 통과와 새 120초
정책의 실제 완주는 구분하며 후자는 아직 검증하지 않았다.

[같은 날 두 고정 모델의 실제 닫기 시험](evidence/2026-11-13-model-selected-m1-close.md)은
첫 묶음에서 모델 CLOSE 1회를 실행·관측했다. 별도 17전이 모델의 후속 묶음은
첫 새 관측에서 재선택해 총 2명령의 실제 실행·OFF를 확인했으나, 두 번째 사후
관측 전 45초 기한이 끝나 실패했다. 두 번째 사후 정답은 미확정으로 보존한다.
이 결과는 목표 완주·반복 성공률·파지 성공이 아니다.

## 별도 접촉 폐합 프로파일과 조건부 단일 재현 코어

`commandPolicy=observed95-grasp650-v1`은 정확한
`current_m1_observed_shaft95` 파라미터의 새 등록에만 결합한다. CLOSE 후보는
**60%·650ms 하나**이며, local450·lower의 다른 CLOSE를 자동으로 합치지 않는다.
이는 기존 M1 하드 출력 상한 안의 별도 프로파일이고 출력 상한 증가는 아니다.
수동 OPEN은 local450과 같은 60%·450/550/650ms 또는 40%·250/350ms다.
이름의 grasp는 프로파일 식별자이며 접촉·보유 성공을 뜻하지 않는다.

접촉 폐합에서 생길 수 있는 작은 물체 재배치·가림은 별도
`objectObservationPolicy=contact_closure_bounded_fragments_v1`로 선언한다.
이 정책은 grasp650 명령 계약과만 함께 쓸 수 있다. 외부 영상에서 면적 500px
이상의 연결 영역이 1~3개여야 하고, 각 영역과 합친 경계상자 모두 고정 참조
경계의 각 방향 ±8px 안에 있어야 한다. ROI 경계에서 잘린 영역은 거절한다.
합친 가시면적은 **고정 참조 bbox의 폭×높이 대비 0.40~1.05**여야 한다.
기준이 가려졌다가 OPEN으로 드러나는 경우를 위해 원래 참조 가시면적을 분모로
쓰지 않는다. 원본 `objectArea`는 바꾸지 않고 근거에
`visibleAreaBasis=reference_projected_box_area`, `referenceProjectedBoxAreaPx`,
`referenceVisibleAreaPx`를 함께 남긴다. 단일 영역에도 같은 면적 검사를 적용한다.

기존 기본·고정 물체 2영역 정책의 3px 경계와 가시면적 기준은 그대로다.
전완 3px·M4 ±0.5° 검사도 유지한다. 새 8px 범위는 접촉 단계의 작은
재배치·가림을 허용하는 사전 가설이며, 물체 동일성·양턱 접촉·파지력·기구 안전을
검증하는 한도가 아니다. 양턱과 물체의 관계는 새 두 카메라 원본에서 따로 판독한다.

동명의 `geometryPolicy=observed95-grasp650-v1`은 자동 발행되지 않는
양턱 접촉 참조를 사용하는 **기본 비활성 단일명령 재현 코어**다.

| scope 항목 | 새 정책의 조건 |
| --- | --- |
| `shaftMinimum`, `shaftMaximum` | 66~139.5px. 다른 정책의 범위를 바꾸거나 기계 안전 한계로 승격하지 않음 |
| `targetShaftPx`, `tolerancePx` | 참조 manifest에 결합된 실제 수동 after 값, 유한한 66~139.5px·허용오차 1.5px |
| `goalSemantics` | `onsite_bilateral_contact_reference_not_retained_grasp` |
| `goalReferenceSha256` | 필수 SHA-256. scope 전체 해시와 함께 고정 |
| `observationRegistrationSha256` | 모델 context의 shaft 등록 SHA와 정확히 일치 |
| `startIntervalPx` | 두 유한 수. 하한은 목표+허용오차보다 크고, 하한<상한≤137px |
| `maxCommands`, `totalRemaining`, `maxSeconds` | 최대 명령은 정확히 1, 남은 예산은 0~1, 전체 상한 45초 |

실제 학습 항목이 있는 CLOSE60%650ms와 정지만 비교한다. 최초 fresh 상태는
시작 구간과 해당 명령의 학습 입력 지원 안이며 목표 밖이어야 한다. 다음 명령이
없는 단일 시험이므로 사후 상태의 후속 입력 지원 검사는 요구하지 않지만,
예측·실제 범위, 관측 3초·결정 0.25초, OFF 후 최소 3초, 잔차 3px와 실패
무재송은 유지한다. 이 정책은 reviewed-lower의 120초를 물려받지 않는다.

외부 실행기의 `verify_assets()`는 manifest SHA뿐 아니라 원본 수동 after 값,
실제 명령·OFF 근거, 동일 관측 context·등록, 현장 양턱 접촉 확인 근거를 목표와
정확히 결합해야 한다. 코어는 manifest를 만들거나 단순 after 값을 접촉 목표로
자동 승격하지 않는다. 양턱 접촉 근거가 확인되기 전에는 실행할 수 없다.
재현 시험 뒤에도 숫자 목표 도달과 실제 접촉·물체 보유·들기를 각각 판독하며
코어의 `contactVerified`, `graspVerified`, `liftVerified`는 긍정하지 않는다.

접촉 근처에 물체 패치 자기 일치가 모호한 경우의
`register_shaft_only()` 등록은 [별도 관측 계약](development-gripper-observer.md#단면-전용-등록과-접촉-단계-외부-관측)을 따른다.
관련 영향 회귀 152개와 기존 수동 촬영·서버 회귀 60개의 유효 결과를 재사용한다.
이는 위 기본 비활성 기능의 소프트웨어 검증이며 새 계약의 실제 모델 파지·들기
검증은 아니다. 진행 중인 수동 접촉 준비를 모델 선택 성과에 합치지 않는다.

## 준비와 모델 재사용

1. 시작 자세는 ㄱ자처럼 반복하기 쉬운 자세를 후보로 삼되 현재 영상에서 물체·양턱·이동 여유를 확인한다. 물체와 초기 자세를 사람이 배치했다면 개입으로 기록한다. 영상만으로 가장 성공하기 쉬운 자세를 보증하지 않는다.
2. `FrozenModelBank`에 `{id, path, sha256}` 목록을 넣어 상대 상태 모델 파일을 고정한다. 팔 표식 네 상태 모델을 물체·양턱 세 상태 모델로 바꾸지 않는다.
3. 위치 조정 단계 0~3개와 마지막 닫기 단계 1개를 지정한다. 현재 위치에서 파지에 진입할 수 있음을 확인한 경우에는 닫기 단계 하나만 지정할 수 있다. 필요한 관절만 포함하며 여러 관절을 동시에 구동하지 않는다. 각 단계는 `modelId`, 영상상 `target`, 좌표별 `tolerancePx`, 명령 후보와 횟수 한도를 가진다. 목표와 허용오차는 명시한 시험 조건이며 학습된 정확도나 물리 안전 한계가 아니다.
4. 각 단계의 실제 관측이 해당 모델의 **전체** 관측 계약과 같아야 한다. 카메라·구도·물체·표식·자세 조건을 모델에 맞추려고 덮어쓰지 않는다. 기존 관절별 모델은 `poseRegime`이 서로 다르고 현재 자세의 적용 가능성도 미확인이다. 파일이 정상 로드된다는 사실만으로 여러 모델을 연속 사용하도록 허용하지 않는다.

부족한 조건은 새 자세·관측 계약에서 별도 자료로 보강해야 한다. 한 명령 전이 2개는 기존 모델의 최소 지원 조건일 뿐 충분한 학습량이 아니다. M2의 상세 원인 분석이나 전 관절 수집을 이 연결의 선행 조건으로 두지 않는다.

## 실행 범위와 흐름

`ModelGraspTrial(scope, bank, observer, port, store, evidence_root=..., clock=...)`에 이미 확인한 관측 어댑터와 기존 `SequencePort`, 새 `ArtifactStore`를 주입한다. `run(confirmed_scope_sha256=plan_digest(scope))`는 정확한 범위 해시가 맞는 경우 한 번만 실행한다. 해시 일치 자체가 사용자 승인이나 현재 장치 조건을 대신하지 않는다.

`scope`의 스키마는 `motionbrain.model_grasp_trial.v1`이다. 필수 항목은 다음과 같다.

| 항목 | 의미 |
| --- | --- |
| `trialId`, `hostClockId`, `controllerBootId` | 새 시험 식별자, 동일 호스트 시계, 현장에서 확인한 제어기 부팅 ID |
| `modelHashes`, `stages` | 고정 모델 목록과 단계별 목표·후보·한도 |
| `maxCommands`, `maxRequestedMs`, `maxSeconds` | 총 명령 시도 수·요청 기간 합계·호스트 전체 기한 |
| `maxObservationAgeSeconds`, `maxDecisionAgeSeconds` | 관측과 전송 판단의 나이 상한 |
| `postOffSeconds`, `retentionSeconds` | OFF 후 최소 관측 대기 3초와 별도 보유 확인 기간 |

코드는 총 12명령·요청 기간 합계 12초·전체 600초보다 큰 범위를 받지 않으며, 실제 시험에는 필요한 더 작은 범위를 정해야 한다. 이 소프트웨어 상한은 이동 여유나 실물 안전의 보증이 아니다. 마지막 닫기는 최대 한 명령으로 제한한다. 일반 실행기의 어깨 위 방향 제외와 기존 관절별 출력·기간 제한은 유지한다. M4 위 방향은 별도 단발 코어에서만 해당 모델·관측·각도 조건을 검사한다.

닫기 단독 시험도 같은 고정 모델의 후보와 정지 비교, 입력 범위·관측 계약·전송 직전 검사, 현장 깊이·이동 여유 근거와 별도 보유 검증을 거친다. 입력이 범위 밖이면 무구동 보류하며, 이미 닫힌 것으로 보이는 영상만으로 파지를 인정하지 않는다. 닫기 단독 경로는 합성 관측으로 소프트웨어 검증했으며 실물 집기 성능을 검증한 결과가 아니다.

각 위치 조정 단계는 실제 관측→모델 후보와 정지 비교→한 명령→OFF→새 관측 순서다. 예측한 다음 상태로 현재 상태를 대체하거나 다음 단계에 진입하지 않는다. 정지가 선택돼도 아직 실제 목표 범위에 도달하지 않았다면 보류한다. 지원 명령이 없거나 관측 계약·학습 상태 범위가 맞지 않으면 기록을 남기고 종료한다.

RUN 전송 직전에는 원래 선택을 다시 검사한다. `SequencePort.execute(..., before_run=guard)`는 RUN 의도를 내구 저장한 뒤 실제 요청 직전에 검사를 한 번 호출한다. 모델 선택이 바뀌거나 관측·저장 판단이 오래됐거나 입력이 전송 0.1초 전에 저장되지 않았으면 전송하지 않는다. guard 내부에서 HTTP 조회나 새 촬영을 하지 않는다. 요청 기한과 전체 시험 기한을 검사하며, 실패·인터럽트·응답 유실 뒤에는 새 명령 ID나 대체 명령으로 재시도하지 않는다.

## 관측 어댑터 계약

`learning/grasp_observation.py`는 집게 위 카메라 원본을 연결하는 `GripperObservationSource`와 분석가 검토를 받는 `ReviewedGraspObserver`를 제공한다. 기존 `gripper_camera_dataset.read_frame()` 검증을 재사용하며, 현재 실물 구도의 점 정의·정착·깊이·이동 여유는 별도 확인이 필요하다. 외부 카메라 원본을 이용하는 경우 기존 `ActionRecorder`의 원본·시계 검증을 유지하는 별도 어댑터가 필요하다. 저장 점을 자동 추정하거나 최신 시각을 붙여 새 관측처럼 취급하지 않는다.

`GripperObservationSource(url, session_id, expected_boot_id, scene_context, store, ...)`는 생성·시작만으로 촬영하지 않는다. 명시적으로 `capture(deadline=...)`를 호출할 때만 `/capture?fresh=1` GET을 한 번 보낸다. 리다이렉트·프록시·자동 재시도 없이 최대 6초·2MB의 응답을 받고 JPEG·메타데이터·시각·실제 부팅 ID·원본 해시를 검사한다. 오류 응답과 실패 원본도 보존하며 실패한 소스로 다시 촬영하지 않는다.

`scene_context`는 실제 확인한 `physicalView`, `object`, `poseRegime`, `landmarks`이며 요청한 단계나 모델에서 복사하지 않는다. 카메라 부팅 ID·영상 크기는 캡처 원본에서 파생한다. 카메라를 재부팅했거나 실제 구도·자세가 바뀌어 기존 모델과 계약이 다르면 자동 적용하지 않는다.

`ReviewedGraspObserver(source, reviewer, retention_reviewer=..., ...)`는 `reviewer(record, deadline=..., tick=...)`에서 명시적으로 받은 프레임별 주석과 정착 확인만 사용한다. 보유 검토 콜백도 `(observations, deadline=..., tick=...)`를 받는다. 콜백은 즉시 반환하거나 대기 중 주기적으로 `tick()`을 호출하고 기한을 지켜야 한다. 콜백 전후 기한·출력과 원본 바이트를 다시 검사한다. 오래된 주석의 시각을 갱신해 새 영상으로 올리지 않으며, 실패 후 새 촬영으로 자동 복구하지 않는다. 닫기·보유 확인값을 어댑터가 생성하지 않는다.

- `start(deadline=...)`: 해당 시험의 제한 촬영 준비.
- `observe(stage, after_off=..., deadline=..., tick=...)`: 새 원본과 분석가 검토를 연결한 관측 반환. 대기 중 `tick()`을 정기적으로 호출해 전체 기한과 예상하지 못한 출력을 감시한다.
- `latest(stage)`, `check()`: 이미 검증·준비된 관측과 정착 상태의 비차단 검사. RUN 직전 검사에서는 파일 주석 대기·장치 조회·중첩 HTTP 기한을 시작하지 않는다.
- `verify_grasp(stage, after_off=..., deadline=..., tick=...)`: 별도 보유 확인 결과 `held`, `failed`, `unknown` 반환. 대기 중 출력 감시를 유지한다.
- `close()`: 원본 촬영과 시계 기록을 마무리하고 `status=completed`를 반환. 미완결 촬영은 성공으로 올리지 않는다.

관측은 `frame={frameId,pixelSha256,width,height}`, `annotation`, 실제 `context`, `hostClockId`, `sourceEarliest`, `sourceLatest`, `receivedAt`, `persistedAt`, `stable`을 가진다. `annotation`은 `analyst_points` 또는 아래 별도 등록의 `registered_template_points`·`registered_scene_template_points` 계약을 따른다. 등록한 관측은 `annotation.landmarkContract`와 실제 `context.landmarks`가 정확히 같아야 하며 수동 점 계약과 자동 혼합하지 않는다. 시각은 동일한 Python monotonic 영역의 원래 캡처/요청 근거이며 새 시험 시작 이후여야 한다. 집게 카메라는 정확한 노출 시각을 발명하지 않고 요청 시작~수신 범위를 사용한다. OFF 이후 상태는 최소 3초 뒤의 새 프레임이어야 한다. 원본 바이트·메타데이터·실제 구도·정착 검증은 관측 어댑터의 책임이며 플래그만으로 인증되지 않는다.

## 등록 특징과 원호를 사용하는 새 관측 계약

`learning/registered_gripper_landmarks.py`는 분석가가 기준 이미지에서 지정한 물체·양턱 점에, 새 원본의 등록 특징 이동을 더한다. `register(reference_jpeg, points, parameters)`로 기준 이미지와 점·영역·탐색·품질 조건을 고정하고 `RegisteredGripperLandmarks.observe(jpeg, frame_id)`로 새 원본을 측정한다. 이 모듈에는 장치 접근·모터 실행·학습 기능이 없다.

기본 방식은 물체와 양턱의 패치를 NCC로 대응한다. 현재 원통 구도에 한해 `default_parameters(object_arc=True)`로 별도 원호 방식을 등록할 수 있다. `learning/object_arc.py`는 고정한 중앙 영역의 위·아래 원호를 함께 사용해 중심 이동을 계산한다. 물체 점은 **분석가 기준점 + 기준 이미지 대비 원호 중심 이동**이며, 원 적합의 절대 중심을 보정된 물리 기준점으로 취급하지 않는다. 양턱은 기존 패치 대응을 계속 사용한다.

등록은 기준 원본 SHA-256, 점 정의와 파라미터 SHA-256을 포함한다. 새 주석은 `frameId`, 복원 BGRA의 `pixelSha256`, `method=registered_template_points`, `registrationSha256`, `parametersSha256`, `referenceImageSha256`, `landmarkContract`를 갖는다. 모델의 `context.landmarks`는 `registered-template-points-v1:<등록 SHA-256>`에 묶인다. 원호 방식을 추가하면 등록·파라미터 해시가 달라지므로 기존 패치 계약이나 수동 주석 모델에 자료가 자동 합쳐지지 않는다.

추출기는 NCC·후보 유일성·탐색 경계·턱의 기하 관계를 검사하고, 원호 방식은 윤곽 수·대비·잔차·반지름·중심 범위를 함께 검사한다. 실패한 대응은 채택된 주석을 내지 않는다. 사후 결과를 보고 기준을 낮추거나 다른 최고 후보를 골라 모델 입력 범위에 맞추지 않는다. 실패 원본을 다른 관측 방식으로 연구할 때도 원래 실패와 새 계약의 재감사 결과를 별도로 보존한다.

빠른 특징 계산과 입력 신선도는 각각 확인해야 한다. `ReviewedGraspObserver`는 기본 2초의 관측 나이 안에서 콜백과 원본 재검증을 마쳐야 하며, 새 GET이나 영상 처리는 RUN 직전 `latest()`·`check()` 안에서 수행하지 않는다. 과거 주석 복사·시각 갱신이나 기한 확대를 관측 실패의 우회책으로 사용하지 않는다.

등록 특징의 일치는 깊이·접촉·이동 여유·정착·정확도를 인증하지 않는다. `stable`과 닫기 진입의 현장 확인을 NCC 점수만으로 만들지 않으며 외부 카메라·시간순 관측·현장 근거를 별도로 연결한다. 현재 계약은 특정 원통·고정 구도의 개발 범위다. [최신 실물 기록](evidence/2026-11-08-close-lift-integration.md)에서는 새 계약으로 4건을 학습·고정했으나 고정 후 평가와 모델 선택 닫기는 아직 0회다.

새 외부 구도에는 `learning/registered_scene_landmarks.py`의 별도 등록을 사용할 수 있다. 분석가가 물체·양턱 점의 실제 정체성과 패치·검색 영역을 동작 전에 지정하고, 기준 원본과 장면 문맥을 함께 고정한다. 주석은 `registered_scene_template_points`, 모델의 특징 계약은 `registered-scene-template-points-v1:<등록 SHA-256>`이다. 기존 모델의 문맥이나 입력 범위를 새 영상으로 바꾸지 않는다. 기본은 패치의 평행이동 관측이며, 선택 사항인 `rotationDegrees`로 특징별 영상 패치 방향 후보를 등록할 수 있다. 이 후보와 `templateRotationDeg`는 영상 정렬용 값이며 실제 관절 회전각이나 그 발생 원인의 측정이 아니다. 후보를 추가하면 등록 해시가 바뀌므로 기존 계약의 학습·평가 결과와 분리한다. 위치별 최고 점수로 경쟁 위치와의 차이를 검사하고 기존 품질 문턱을 유지한다. 가림·유일성·품질 실패 시 중단하며, 접촉·깊이·제어 적격을 부여하지 않는다.

M4 접근처럼 다른 축을 고정한 제한 시험에는 선택 사항인 `jawPair`로 두 턱의 위치 후보를 쌍으로 비교할 수 있다. 개별 패치의 NCC 하한과 전체 검색 영역은 유지하고, 미리 등록한 투영 간격 안의 쌍을 평균 NCC와 경쟁 쌍의 점수 차이로 구별한다. 후보·간격으로 배제한 쌍·선택 근거를 기록하며, 후보 예산 초과나 쌍의 모호성에서는 중단한다. 이는 개별 패치 유일성 검사와 다른 새 계약이다. 기존 실패를 통과로 바꾸지 않고 기존 수집을 별도로 재주석·모델 고정한 뒤 새 평가를 해야 한다. 투영 간격 범위는 현재 구도의 관측 제약이며 물리 턱 간격 불변·M1 개폐·접촉을 증명하지 않는다.

관측과 모델 선택을 연결하는 실행기는 `ManualCollection.pulse(..., before_run=guard)`로 기존 전송기의 RUN 직전 가드를 사용할 수 있다. 가드는 캐시된 관측과 사전 선택을 비차단으로 확인해야 하며, 실패하면 재시도하지 않는다. 기본 수동 수집 경로와 출력·정지 검사는 유지한다.

`learning/m4_approach_transfer.py`는 기존 M4 아래 방향 모델의 명령별 센서 변화 평균을 현재 등록 구도의 영상 변화와 연결하는 별도 실험 코어다. 두 낮은 출력 조건의 새 전이로 국소 대응과 센서 효과 보정을 구하고 모델을 고정한다. 후보별 별도 평가를 통과한 조건만 정지 후보와 비교하며, 무변화·보정 전 기존 평균·현재 명령 평균의 지원 여부를 함께 기록한다. 선언한 센서·한 번의 변화량 한도는 실행 범위이며 학습 입력 범위나 정확도 보증이 아니다. 새 하단 자세의 진행은 전향적 범위 확장 실험으로 구분한다. 기존 모델의 가중치·문맥·범위는 변경하지 않으며, 영상에 의한 행동 효과 예측 개선이나 접촉·집기 성공을 주장하지 않는다. 이 모듈에는 장치 접근이나 기본 활성 실물 실행기가 없다.

반복 명령의 실제 반응이 다르면 `learning/m4_empirical_approach.py`의 별도 경험적 결과 모델로 그 차이를 보존할 수 있다. 같은 관측 계약의 명령별 센서·영상 변화 쌍을 유지하고, 현재 상태에 각 실측 결과를 적용했을 때 가장 불리한 목표 오차를 정지와 비교한다. 평균 예측과 기존 전이 모델도 비교용으로 남긴다. 사후에는 같은 실측 쌍에 대해 기존 영상·센서 오차 조건을 동시에 만족하는지 검사한다. 이는 평균 오차 문턱을 넓히는 처리가 아니며, 관측한 표본의 결과 집합은 미래 포함률이 보정된 신뢰구간이 아니다. 기존 실패는 그대로 남기고 새 모델의 개발 자료와 새 고정 후 평가를 분리한다. 학습 2건 미만인 명령이나 별도 평가를 통과하지 않은 명령은 선택하지 않는다. 실제 기구·출력·정지 보호와 접촉 확인은 별도로 유지한다.

## 닫기와 집기 확인

M4만 움직이고 집게와 다른 관절을 고정하는 구도에서는 `registered_rigid_scene_landmarks.py`의 별도 강체 관측 계약을 사용할 수 있다. 기존 영상 계측기의 정방향·역방향 광류, 강체 적합, 두 고정 배경 검사를 그대로 사용하며 물체는 기존 NCC 품질 조건으로 확인한다. 보이는 강체 특징으로 턱끝 기준점을 옮기므로 가림과 반복 무늬를 피할 수 있지만 M1 개폐에 사용하지 않는다. 새 method와 계약 해시는 기존 패치 계약과 구분되며, 실패한 원본의 재주석은 새 모델의 개발 자료로만 사용한다.

패치 대응 방식에서도 명시적인 `trackingAnchors`를 등록하면 같은 강체의 보이는 패치를 사용하면서 기준점은 패치 밖에 둘 수 있다. 강체 대응 여부는 분석가가 확인하고, 영상 회전은 계속 해당 기준점 중심으로 처리한다. 기존 품질 하한을 낮추거나 실제 접촉·관절각 보정을 뜻하지 않는다.

닫기 진입에는 현재 프레임에 묶인 `closeEntryEvidence`가 필요하다. 필드는 `frameId`, `pixelSha256`, `method=onsite_observation`, `objectBetweenJawsVerified`, `depthVerified`, `clearanceVerified`, `evidenceFile`, `evidenceSha256`다. 세 확인값은 모두 `true`여야 하며, 물체 중심이나 턱 간격만으로 만들지 않는다.

`held` 결과에는 `method=analyst_retention_review`, `contactVerified`, `retentionVerified`, `supportDistinguished`, 두 개 이상의 시간순 `observations`, `evidenceFile`, `evidenceSha256`가 필요하다. 처음과 마지막 관측의 간격이 지정된 보유 확인 기간 이상이어야 하며 마지막 관측은 최신이어야 한다. 바닥에 놓인 물체와 실제 집게에 유지되는 물체를 구분하지 못하면 `unknown`이다. 닫기를 추가 반복해 목표 턱 간격을 억지로 맞추지 않는다.

두 검토 기록은 비공개 `evidence_root` 아래의 실제 JSON 파일로 보존한다. 파일은 `evidenceFile`, `evidenceSha256`을 제외한 제출 내용과 같아야 하며 읽은 바이트의 SHA-256을 검사한다. 상대 경로 이탈·심볼릭 링크는 거절한다. 해시는 기록 변경 검사용이며 사람의 판단이나 물리 상태의 진실성을 인증하지 않는다. 보유 확인을 받아도 관측 보조를 받은 결과이며 학습 인식만의 자율 집기나 들기 성공으로 표현하지 않는다.

모델·관측·선택·전송 직전 판단·실제 명령 영수증·미실행/실행 불명·마지막 OFF를 기존 증거 저장소에 남긴다. 종료 직전까지 예상하지 못한 출력 이력을 검사하며 촬영 마무리나 OFF 확인이 실패하면 집기 성공을 보고하지 않는다. 원본과 별도로 학습을 자동 시작하거나 중단된 시험을 재개하지 않는다.

## 무출력 원본·모델 진단

`tools/check_grasp_observation.py`는 카메라 원본과 기존 모델의 계약을 확인한다. 제어기 주소나 모터 실행 옵션은 없다. `--capture`는 카메라 영상 한 장만 읽으며, `--source-binding`은 이미 저장한 원본을 다시 검사한다. 두 경로 모두 `controlEligible=false`이며 실물 실행 준비가 완료됐다는 뜻이 아니다.

설정 JSON은 `schemaVersion=motionbrain.grasp_observation_check.v1`, `sessionId`, `cameraUrl`, `expectedCameraBootId`, `sceneContext`, `modelBindings`, `captureTimeoutSeconds`를 가진다. `modelBindings`의 각 항목은 `{id,path,sha256}`이며 실제 모델 파일을 해시로 고정한다. 장치별 주소와 설정·원본·주석·진단 출력은 `.local/` 아래에 둔다.

```sh
python3 tools/check_grasp_observation.py \
  --config .local/grasp-observation/config.json --capture \
  --output-dir .local/grasp-observation/source-check-01

python3 tools/check_grasp_observation.py \
  --config .local/grasp-observation/config.json \
  --source-binding .local/grasp-observation/source-check-01/capture-0001/source-binding.json \
  --source-binding-sha256 '<원래 source-binding.json의 SHA-256>' \
  --annotation .local/grasp-observation/points.json \
  --annotation-sha256 '<원래 주석 파일의 SHA-256>' \
  --output-dir .local/grasp-observation/point-check-01
```

주석은 기존 `analyst_points` 형식이다. 주석을 제공하지 않거나 승인하지 않은 경우 상태를 생성하지 않는다. 전체 관측 계약이 일치하고 점 주석도 승인된 경우에만 지원 명령별 저장 상태 예측을 계산한다. 계약이 다르면 변경된 필드만 보고하며 모델이나 원본을 바꾸지 않는다. 재생 중 원래 시각은 그대로 보존한다. 오래된 저장 영상의 예측을 최신 실물 판단이나 새 독립 평가로 세지 않는다.

```sh
python3 -m unittest tests.test_model_grasp_trial tests.test_supervised_transport \
  tests.test_relative_model_bundle tests.test_relative_action_learning \
  tests.test_grasp_observation tests.test_check_grasp_observation
```

## 저장 영상의 관측 방식 진단

`tools/audit_grasp_observations.py`는 저장된 집게 카메라 영상에서 점의 소수점 표현과 정수 반올림이 입력 범위 판정에 미치는 영향을 비교한다. 장치 조회·촬영·제어·전이모델 학습은 하지 않는다. 원래 고정 모델과 분석가 주석을 바꾸거나 범위 거절을 해제하지 않으며, 모든 결과는 `trainingEligible=false`, `controlEligible=false`다.

진단기는 고정 구도의 원통 윗면 오른쪽 윤곽을 원으로 근사하고, 좌우 ROI의 어두운 연결 성분 끝부분을 턱 점으로 측정한다. 원통·조명·구도가 다른 영상의 범용 검출기가 아니다. ROI 경계에 닿는 성분이나 원 근사 잔차 등 품질 플래그가 있는 측정은 범위 계산에서 제외하되 원본·플래그·분모를 남긴다. 검출 성공이 물체 중심이나 접촉 위치의 정확도를 입증하지 않는다.

설정은 `motionbrain.grasp_observation_study.v1`이며 `.local/` 안에 다음 항목을 둔다.

- `frozenModel={path,sha256}`, `manifestPath`, `manifestSha256`: 기존 고정 모델과 같은 학습 세션을 가리키며 평가 그룹은 비워 둔다. 원본 수집 감사와 프레임 해시·부팅 ID 검사를 다시 거친다.
- `sceneContext`, `expectedCameraBootId`: 실제 관측 계약과 예상 부팅 ID. 다른 구도로 계약을 바꾸지 않는다.
- `parameters`: `imageShape`, `grayThreshold`, `objectRightArcRows`, `objectRightArcColumns`, `jawRois`, `jawDistalRows`. 원 윤곽의 행·열 끝값은 포함하며 턱 ROI는 `[x0,y0,x1,y1]`의 뒤 끝값을 제외한다. 결과를 보고 범위를 통과하도록 조정하지 않는다. 기존 진단에서 가져온 경우 `parameterOrigin={path,sha256}`로 원래 보고서의 `parameters`와 동일한지 검사한다(`imageShape` 제외).
- `rejectedQuery={source,annotationPath,annotationSha256}`: 학습 프레임과 겹치지 않는 거절 입력 한 장과 원래 분석가 주석. `source={root,label,sessionId}`이며 `label=before`만 허용한다.
- 선택 항목 `stationarySources`: 같은 `source` 형식의 과거 정지 영상 목록. 시각을 갱신하거나 새 동기 관측으로 취급하지 않는다.

```sh
python3 tools/audit_grasp_observations.py \
  --config .local/grasp-observation/study.json \
  --config-sha256 '<고정한 설정 파일의 SHA-256>' \
  --output-dir .local/grasp-observation/study-01

python3 -m unittest tests.test_grasp_observation_diagnostic
```

`inputCoverage`는 품질 검사를 통과한 동작 전 입력만으로 명령별 최소·최대를 계산한다. `pairedInputCoverage`는 동작 전후 모두 통과한 쌍만 사용하며, 두 결과 모두 실패 입력의 분모를 보존한다. 원본 감사 실패로 명령을 신뢰할 수 없으면 `unknownCommand` 그룹에 남긴다. 동작 후 정답으로 입력 범위를 넓히지 않는다. `originalAnalystModelQueryCoverage`는 기존 모델의 원래 판정과 분리한다.

소수점과 정수 표현의 판정 차이, 정지 영상의 반복 변동, 원래 분석가 점과의 차이는 관측 계약을 검토할 근거다. 어느 것도 독립적인 정확도·예측 성능·물리 안전의 측정값이 아니다. 새 관측 방식을 채택하려면 점 정의와 실패 처리를 먼저 고정하고 별도 모델·보류 평가에서 검증해야 한다.
## 닫기에서 들기로 넘기는 별도 연결

`learning/close_lift_trial.py`의 `CloseLiftTrial`은 새 `motionbrain.model_close_contact_trial.v1` 닫기 코어와 별도 짧은 M4 모델을 연결한다. 닫기 코어는 최대1명령 뒤 정상 OFF를 `closed_off`로 반환하며, 이 결과를 파지·공중 보유 성공으로 표시하지 않는다. 기존 파지 코어의 보유 검증 경로는 그대로 유지한다.

연결은 정상 닫기 종료 뒤 최소3초가 지난 새 양 카메라 관측2쌍을 요구한다. 두 쌍은 최소1초 떨어져 있어야 하며, 원본·시각·카메라 계약·탁자 지지·양턱 접촉·깊이·이동 여유·같은 물체 확인을 검증한다. 기존 M4 입력 범위를 유지하고, 원본에서 측정한 집게 위 상대 이동은 가로·세로 각각4px 이하여야 한다. 접촉은 `table_supported_contact_ready`이며 공중 보유와 구분한다.

새 모델의 선택으로 들기 최대1회를 실행하며 중간 출력 이력 변경, 원본 변경·노화, 실패·불명확한 명령은 후속 단계를 막는다. RUN 직전에는 검증한 원본 바이트를 재검사하고 기존 M4 사전 검사를 유지한다. 들기 실행 완료 뒤에도 별도 영상의 물체-탁자 공극·보유 판독 전에는 `liftVerified`를 참으로 만들지 않는다. 위치 조정·복귀·재학습·자동 재시도는 이 연결기의 기능에 포함하지 않는다. 이 연결 코어의 검증은 모의 환경에서 수행했다. 2026-11-08 실물 묶음은 M1 관측·입력 범위에서 중단돼 연결 실행은 0회이며, 준비 명령의 정상 종료를 연결 성공으로 세지 않는다.
