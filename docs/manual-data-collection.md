# 관절별 수동 데이터 수집 화면

[운영 안내](../OPERATIONS.md) · [기존 감독 수집](supervised-action-collection.md) · [2026-11-04 수집·평가 결과](evidence/2026-11-04-m4-action-prediction.md)

기존 Control Console의 관절·방향 선택 방식을 참고한 Mac 로컬 화면이다. M1~M5 중 한 관절을 선택해 짧은 동작을 요청하고 영상·명령·실제 드라이버 출력·센서 응답을 보존한다. 완료·실패·중단 기록의 프레임과 이력을 다시 확인할 수 있다. 서버 실행과 기록 조회만으로 촬영·구동하지 않는다.

물체가 없는 장면의 팔 움직임은 [외부 영상 표식 학습](projected-arm-learning.md)의 별도 관측 계약으로 분석할 수 있다. 기존 물체·턱점 모델의 입력을 빈 점이나 다른 기준점으로 대체하지 않는다.

촬영별 첫 프레임을 기준으로 영상과 M4 센서를 대조하는 기능은 [감독 수집의 선택적 등록 경로](arm-calibration.md#촬영별-첫-프레임-기준-등록)를 따른다. 이 수동 수집 화면에 같은 등록 옵션이 자동 적용되는 것은 아니다. 저장된 두 카메라 평가와 모델 지표를 함께 보는 방법은 [시각화 안내](robot-visualization.md)를 참고한다.

## 실행

저장소 루트에서 촬영기를 빌드한다. 빌드는 카메라를 열지 않는다.

```sh
mkdir -p .local/bin
bash tools/macos/build_action_recorder.sh .local/bin/mac_action_recorder
```

카메라 연결 후 `.local/bin/mac_action_recorder --list`로 장치 식별자를 조회한다. 기존 운영 방식으로 `MOTIONBRAIN_HTTP_TOKEN`을 환경변수에 설정하고 아래 값은 현재 주소·식별자로 바꾼다. 토큰을 명령 인수·문서·기록에 넣지 않는다.

```sh
python3 tools/manual_collection_server.py \
  --controller-url 'http://<현재 ESP32 주소>' \
  --device-id '<카메라 uniqueID>' \
  --helper .local/bin/mac_action_recorder
```

브라우저에서 `http://127.0.0.1:8765`를 연다. 서버는 루프백에서만 수신한다. 기본 저장 경로는 `.local/manual-collection/`이며 `--output-dir`도 저장소 `.local/` 아래만 허용한다. macOS 카메라 권한과 iPhone 연결은 준비되어 있어야 한다.

## 사용

1. 관절·시작 자세·하중 메모를 입력하고 현재 연결·모터 전원·이동 여유를 확인한 뒤 **수집 시작**을 누른다.
2. 저장 중인 최신 영상을 확인하고 방향·요청 출력·시간을 지정해 **한 번 조작**한다. 요청과 정지 확인이 끝나야 다음 동작을 받는다.
3. **완료·저장**으로 종료한다. **수집 중단**은 중단 사유를 보존한다. 다른 관절은 새 수집에서 선택한다.
4. 기록을 선택하고 재생·슬라이더로 프레임과 이력을 확인한다. **전체 이력**은 마지막 영상 뒤 수신한 정지·종료 기록도 표시한다.

조작은 기존 `SequencePort`의 유한 단발 요청으로 처리한다. 기존 방향·출력 상한을 적용하며 M4는 과거 큰 이동 때문에 아래 방향 1회/기록만 허용한다. 다른 관절은 최대 20회/기록이다. 이 상한은 현재 자세의 안전한 이동 거리를 보장하지 않는다.

촬영 예산은 최대 60초이며 기본 8fps·500프레임, `--sample-fps 4` 선택 시 4fps·260프레임이다. 서버 시작이 아닌 **수집 시작 후** 50초를 넘으면 새 동작을 받지 않고 55초부터 종료한다. 준비·통신 시간도 포함되어 실제 촬영은 더 짧을 수 있다. 최대 저장 예산과 2GiB 여유 공간을 요구한다.

## 저장과 시간

형식은 `motionbrain.manual_collection.v1`이며 기존 정착 전후 자료·M2 고정 출력 자료와 자동 혼합하지 않는다.

| 내용 | 파일·의미 |
| --- | --- |
| 설정 | `plan.json`: 관절·자세·카메라 설정·촬영기 해시 |
| 영상 | `native-camera/`: 무손실 프레임·PTS·메타데이터·해시·호스트 시계 대응 |
| 명령 | `command-*-intent.json`, `command-*-result.json`: 전송 전 의도와 결과 |
| 통신·센서 | `http-*` 기록: 요청·원본 응답·오류와 호스트 시작·수신 시각 |
| 종료 | `session.json`: 프레임 색인·이력·종료 상태·출력 정지 확인 |

M4 각도와 공통 센서는 수집 전용 `/collection_status` 응답을 보존한다. 기존 기록의 `/status`도 재생할 수 있다. 센서 없는 관절의 각도를 만들지 않는다. 최근 수신 각도와 오래된 값 여부는 화면에, 전체 센서는 기록 원문에 표시한다.

영상 PTS는 기존 촬영기의 호스트 시계 구간으로 대응한다. HTTP 이력은 호스트 요청·응답 구간이며 출력 `atMs`는 ESP32 부팅 시계다. 정확한 장치 간 시계 동기화나 광학 노출 시각은 검증하지 않았다. 함께 보는 것은 근거를 비교하기 위한 것이며 수신 시각을 실제 출력 발생 시각으로 바꾸지 않는다. 학습 전 필요한 시간 정렬·품질 검증은 별도다.

실제 출력은 드라이버에 적용한 소프트웨어 PWM 기록이다. 전기적 파형·실제 이동·물리적 정착을 보증하지 않는다. 실행 전 예측 입력은 현재 영상과 예정 명령이며 이후 센서·실제 출력은 학습 목표·평가·실행 검증 용도로 구분한다.

## 실패와 검증 범위

수집을 시작할 때 장치 식별 GET과 첫 `preflight`의 요청 기한은 2초다. 초기 출력 이력 로딩은 전체 8초·16페이지로 제한한다. 시작 검사가 성공하거나 실패하면 기본 요청 기한을 0.8초로 복원하며, 아래에 설명한 비구동 대기 감시의 별도 기한은 그대로 적용한다. 이 변경은 명령 재전송이나 구동 제한 확대를 추가하지 않는다.

같은 서버가 소유한 `session_start_failed` 기록이 촬영·명령·쓰기 전에 끝난 경우에는 인증된 로컬 API `POST /api/recover-readonly`에 빈 JSON 객체를 보내 읽기 전용 복구를 한 번 요청할 수 있다. 서버는 실행 가능성이 없는지, GET 원본과 실패 세션·저널 결과가 일치하는지 먼저 검사하고, 별도 `readonly-recovery/` 폴더에 새 GET으로 전축 OFF·빈 큐 증거를 저장한다. 검증이 끝나면 해당 세션의 저널 단계만 해소한다. 원본 실패·결과와 명령 이력은 보존하며 촬영·구동·정지 명령은 보내지 않는다. 이미 촬영이나 쓰기를 시작했거나 구동 결과가 불명확한 경우에는 거부한다. 복구 실패는 차단 상태를 유지하고 자동 재시도하지 않는다. 성공 후에도 새 수집은 별도로 시작해야 하며, 서버를 재시작한 뒤에는 이 API로 이전 서버의 기록을 해소할 수 없다. 실물 시작 실패 기록에서 새 명령 없이 이 복구를 확인했다. 이는 해당 무쓰기 실패의 저널 해소 검증이며 통신 장애 해결이나 다른 실패 상태의 복구를 입증하지 않는다.

프로세스가 종료되어 원래 수집기 객체가 사라졌다면 별도 Python API
`ManualCollection.recover_failed_start_readonly(session_id, source_sha256)`를 사용한다.
새 수집기의 경로·제어기·기기 설정은 원본 계획과 일치해야 한다. 이 경로는 원본
세션 SHA, 계획과 공유 원장 결과의 일치, 모든 HTTP 의도가 허용된 GET인지,
촬영·명령 흔적이 없는지와 유일한 미해결 세션인지 검사한다. 새 포트의 기본값을
원래 포트가 실행하지 않았다는 증거로 사용하지 않는다. 고정된
`readonly-failed-start-recovery/` 폴더에서 한 번만 새 OFF·빈 큐 근거를 수집하며,
원본 실패 결과를 보존한 채 원장 단계만 해소한다. 기존 API의 재로딩 거절은 유지한다.
이 별도 복구 역시 실패하면 재시도나 동작 재개를 허용하지 않는다.

명령을 자동 재전송하지 않는다. 촬영 정지·부팅 변경·예상 밖 관절 출력·출력 순번 누락·저장 오류 시 추가 동작을 차단하고 부분 기록을 보존한다. 기존 수집기와 같은 전역 저널을 사용하며 출력 정지 미확인·종료 기록 누락은 재시작으로 자동 해제되지 않는다. 삭제나 새 ID 재실행으로 해소하지 않는다.

출력 OFF가 확인된 수동 수집 대기 감시의 기본 1.5초 GET 기한과 초기 이력 로딩 예외는 [수집 통신 응답 축소](#수집-통신-응답-축소)에 모아 설명한다. 이 감시 경로는 이전 전축 OFF 증거가 있고 활성 동작이 없을 때만, 일시적인 GET 시간 초과·연결 종료에 대해 세션당 한 번 상태와 출력 이력을 새로 확인한다. 최초 조회와 재확인의 전체 기한은 4.5초다. 새 응답은 계속 IDLE·센서 최신성·부팅 ID·출력 순번 연속성·비영 출력 검사를 통과해야 한다. 명령 재전송이나 불명확한 동작 결과 복구가 아니다.

기존 HTTP 제한 시간을 유지하기 위해 주 스레드에서 단발을 처리한다. **수집 중단은 진행 중인 단발 처리 이후 실행될 수 있으며 즉시 비상 정지가 아니다.** 브라우저가 사라져도 요청은 유한 시간이고 수집 예산은 유지된다. 강제 종료 시 다음 실행에서 미완료 저널을 보존한다.

저장 완료는 학습 적격 판정이 아니다. `datasetEligible=false`, `trainingPerformed=false`를 유지하며 자동 라벨 생성·학습·모델 배포는 하지 않는다.

### 종료된 세션의 무손실 보관

macOS와 `ffmpeg`가 있으면 종료된 수동 수집 세션을 FFV1으로 별도 보관할 수 있다. 촬영이나 구동 없이 실행하며 `create`는 원본을 삭제하지 않는다. 보관·복원 대상 폴더는 새 경로여야 한다. 원본 세션 내부에 보관본을 만들 수 없다.

```sh
python3 tools/archive_manual_session.py create \
  .local/manual-collection/<세션> .local/session-archives/<세션>
python3 tools/archive_manual_session.py verify .local/session-archives/<세션>
python3 tools/archive_manual_session.py restore \
  .local/session-archives/<세션> .local/restored-sessions/<세션>
```

프레임은 BGRA 픽셀을 보존하는 FFV1으로, 나머지 파일은 원래 바이트로 복사한다. 원래 프레임 경로·파일 해시·픽셀 해시를 별도 명세에 남긴다. 영상의 재생 시각은 프레임 색인용이며 실제 PTS와 명령 시각은 복사된 원래 JSON을 사용한다. 복원 시 LZBITMAP 파일을 다시 생성하고 **기존 압축 파일의 바이트 해시까지 일치**해야 성공한다. macOS 압축 구현 차이 등으로 같은 파일을 재현하지 못하면 실패하며, 기존 자료를 덮어쓰지 않는다.

보관 생성은 전체 영상 복호화·파일 복원 해시 확인과 원본 변경 검사를 통과해야 완료된다. 종료 상태는 `completed` 또는 `failed`여야 하며 실패 세션을 학습 적격으로 바꾸지 않는다. 보관본 생성만으로 디스크 공간이 줄지는 않으며, 다른 디스크의 백업을 대신하지 않는다. 보관 중에는 변환본을 위한 추가 공간이 필요하다.

공간을 확보하려면 다음 명령을 **별도로 실행**한다. `prune`은 보관본 전체의 파일·폴더를 `fsync`하고 전체 프레임을 복호화·재인코딩하여 기존 압축 파일 해시를 다시 검증한다. 원본 메타데이터와 남아 있는 모든 파일이 명세와 같은 경우에만 `.bgra.lzbitmap` 사본을 제거한다. 제거 직전에 각 프레임을 다시 확인하고 복원 경로·해시를 보관본의 `.prune-journal.jsonl`에 영속 기록한다. 실패·중단 기록과 명령·센서·시각 JSON은 원래 경로와 보관본에 모두 남긴다. 중단 후 같은 명령을 다시 실행할 수 있으며 보관본과 원본을 동시에 사용하는 촬영·편집 작업은 종료해야 한다.

```sh
python3 tools/archive_manual_session.py prune \
  .local/session-archives/<세션> .local/manual-collection/<세션>
python3 tools/archive_manual_session.py restore-missing \
  .local/session-archives/<세션> .local/manual-collection/<세션>
```

**정리된 세션을 기존 재생·학습·감사 도구에서 사용하기 전에는 `restore-missing`으로 원래 경로를 복원해야 한다.** 이 명령은 전체 보관본을 임시 폴더에 복원·검증한 뒤 누락된 프레임만 원래 경로에 추가하며, 이미 있는 파일이나 바뀐 메타데이터를 덮어쓰지 않는다. 완전 복원용 임시 공간이 필요하고, 중단 후 재실행할 수 있다. 보관본 직접 읽기는 지원하지 않는다. 보관·정리·원래 경로 복원은 같은 보관본의 작업 잠금으로 중복 실행을 막는다.

```sh
python3 -m unittest tests.test_manual_collection tests.test_manual_collection_server tests.test_manual_collection_ui
```

모의 장치·카메라의 성공·실패·누락·재시작, 루프백 API, 원본 무결성 및 브라우저 스크립트를 검사한다. 브라우저 스크립트 검사는 Node.js가 필요하다. 모든 관절의 구동 검증을 뜻하지 않는다. 실측 분모·실패·평가 결과는 [M4 수집·행동 예측 기록](evidence/2026-11-04-m4-action-prediction.md)에 구분한다.

## 수집 통신 응답 축소

Pi를 경유하는 HTTP 연결은 `learning.pi_http_tunnel.PiHttpTunnel`의 공통 준비
경로를 사용한다. SSH 인증과 loopback 포워드 설치 뒤 원격 `READY`를 확인하며,
준비 검사 목적으로 제어기에 빈 TCP 연결을 만들지 않는다. 최대 6초의 준비 기한과
선언한 수명 안에서만 사용하고 자신이 만든 SSH 자식만 정리한다. 터널 준비 성공은
장치의 HTTP 응답·OFF·실물 실행 허가를 대신하지 않는다. 별도의 현재 상태 검사와
기존 원장·부팅 검사는 계속 적용하며 터널이 GET이나 동작 요청을 재전송하지 않는다.

기본 `SequencePort`의 최초 `/actions` GET은 연결·전송·헤더·본문 구간을
`http-000001-phase.json`에 남긴다. 기존 첫 요청의 기한과 요청 수를 유지하고
헤더·본문·인증값은 계측 기록에 넣지 않는다. 주입한 별도 opener, 일반 조회,
동작 요청과 허용된 quiet 재연결은 이 단일 요청 계측의 적용 대상이 아니다.
실패 원본과 구간 기록으로 이후 장애 위치를 분리하며, 구간 기록이 없던 과거
시간 초과를 새 시험만으로 같은 원인이라고 판정하지 않는다.

비구동 대기의 조회 간격과 허용된 재확인 플래그는
`QUIET_IDLE_POLL_SECONDS`·`check_quiet_idle()`로 공유한다. 수집기와 제한된 개발
접근 경로는 0.5초 간격의 상태 조회를 사용하며, 사이의 관측 검사와 전체 기한
확인은 생략하지 않는다. 구동 중 검사·전송 직전 확인·OFF 확인에는 이 대기 주기를
적용하지 않는다. 이는 불필요한 조회를 줄이는 변경이며 통신 장애 제거 보장은 아니다.

수동 수집은 `collection.v1` 상태 응답을 사용한다. 기존 안전 검사에 필요한 상태·5축 출력·센서 최신성·M4 경계와 각도·IMU 값을 유지하면서 응답 본문을 최대 1,200바이트로 제한한다. 기존 제어 화면의 `/status`는 유지한다.

출력 이력은 `/action_outputs?after=N&limit=8`로 최대 8개씩 읽는다. 최초에는 보존된 이력을 읽어 5축의 마지막 출력을 확인하고, 이후에는 순번·부팅 ID·시간 연속성을 검사한다. 누락이나 덮어쓰기로 현재 수집의 근거가 끊기면 중단한다. 촬영·쓰기 이전 최초 이력 로딩은 최대 8초·16페이지 안에서 페이지당 기본 1.5초를 허용한다. 원래 더 긴 요청 기한으로 구성했다면 그 값을 유지하되 남은 전체 예산을 넘지 않는다. 첫 스냅샷 확인 뒤의 일반 조회·구동·종료 처리에는 이 초기 로딩 예외를 적용하지 않는다. 이후 기본 페이지 묶음은 전체 0.8초·16페이지로 제한하되, 이전 OFF 증거를 갖춘 수동 수집 대기 감시의 상태·출력 이력 GET에는 아래의 기본 1.5초 예외를 함께 적용한다. 원본 페이지와 실제 기한을 모두 저장하며, 초기 로딩 실패도 자동 재시도하지 않는다.

서버의 첫 요청 바이트 대기는 100ms에서 500ms로 조정했다. 이는 관측된 239ms TCP 재전송 대기보다 여유를 주는 제한이며 통신 성공을 보장하지 않는다. 빈 연결이 다른 HTTP 요청을 늦출 수 있는 시간도 늘어나므로 HTTP 중단 버튼을 즉시 비상 정지로 해석하지 않는다. 명령 자동 재전송과 실행 제한 확대는 추가하지 않았다.

수집 중 구동하지 않는 상태 감시에서는 이전 전축 OFF 증거가 있고 활성 펄스가 없는 경우에 한해 상태 GET과 출력 이력 페이지 묶음의 기본 기한을 0.8초에서 1.5초로 늘린다. 원래 더 긴 기한으로 구성된 경우 그 값을 유지한다. 요청 기록에 실제 기한과 실패 원본을 남긴다. 이 조용한 구간의 일시적인 조회 실패만 위의 제한된 재확인을 적용하며, 새 상태·연속 출력 이력으로 OFF를 다시 확인해야 촬영을 이어간다. 사전 구동 검사·구동 명령·종료 검사에는 이 재확인을 적용하지 않는다. 재확인 실패, 잘못된 응답, 새 출력이나 이력 누락은 수집을 종료한다. 네트워크 지연 자체가 없어졌다는 의미는 아니며 실제 장비에서의 연속 운전은 별도 검증해야 한다. 종료 정리 요청이 실패한 뒤에는 새 정지 조회가 성공해도 같은 정리 요청을 자동 재전송하지 않는다.

[2026-11-05 관절별 확대 결과](evidence/2026-11-05-multi-joint-relative-learning.md)에서는 전체 초기 로딩 예산에 도달하기 전 개별 출력 이력 GET의 0.8초 제한에서 실패했다. 초기 로딩의 페이지 기한 보완은 이 제한을 조정한 것이며 응답 지연 원인을 규명하거나 장기 안정성을 입증한 것은 아니다. 초기 로딩과 비구동 감시의 예외는 각각의 조건에서만 적용하며 구동·종료 검사에는 적용하지 않는다.

## 수집 기록의 오프라인 데이터셋 변환

현재 데이터셋 변환기는 M4 센서 변화량을 대상으로 한다. 수집 화면의 M1~M5 선택 지원과 모든 관절의 자동 라벨·학습 지원은 다르다.

수동 수집 기록은 기존 M2 finite-profile 데이터셋과 계약이 달라 직접 섞지 않는다. 명시한 세션 목록만 읽어 영상·명령·센서·실제 출력을 검증하고, 새 파생 데이터셋에 묶는다. 원본 `session.json`의 `datasetEligible=false`는 변경하지 않는다.

예측 입력은 **명령 전에 확보한 현재 영상과 예정 명령**이다. 실제 출력 파형·출력 기간·동작 후 센서값은 사후 근거와 정답으로 분리한다. 촬영 PTS만 이전인 프레임은 충분하지 않다. 원시 영상의 호스트 수신·저장 근거도 명령 이전이어야 입력 후보로 선택한다.

라벨 기준은 명령 의도 시각의 −3~−0.1초 구간과 출력 정지 확인의 +3~+6초 구간이다. 각 구간의 센서 중앙값 차이와 원시 표본·범위를 함께 보존한다. 영상 PTS의 호스트 시계 변환 구간과 센서 조회의 요청·응답 및 값 나이 구간을 사용한다. 정지 후 지연을 두는 것이 실제 정착을 보장하지 않으며, 장치 시계를 정확히 동기화했다거나 광학 노출 시각을 검증했다는 뜻은 아니다.

촬영 그룹과 제외 사유를 색인에 명시한다. 프레임을 무작위로 나눠 독립 시험 자료처럼 사용하지 않는다. 다음은 첫 동일 명령 4건을 사용한 예시이며, 실제로 준비한 색인·새 출력 경로로 바꿔 실행한다. 변환 작업은 촬영·구동·학습을 실행하지 않는다.

```sh
python3 tools/manual_collection_dataset.py \
  --index .local/manual-collection/first-dataset-index.json \
  --output-dir .local/manual-dataset-20261104/dataset-v2 \
  --export-png
```

색인 형식은 `motionbrain.manual_dataset_index.v1`이며 `captureGroup`, `split: "development"`, 세션별 상대 경로와 원본 `session.json` SHA-256을 명시한다. 결과 폴더는 새 경로여야 하고 비공개 `.local/` 아래에 둔다. `dataset.json`의 `inputs`는 입력 영상·명령, `targets`는 이후 영상·센서 변화, `evidence`는 실제 출력·시간·원본 해시다. `--export-png`는 선택된 입력·목표 영상을 PNG로 내보낸다. 원본 촬영을 다시 실행하거나 원본 파일을 수정하지 않는다.

## 첫 영상·명령 기준 모델

수동 데이터셋의 현재 영상과 예정 명령으로 M4 센서 변화량을 예측하는 작은 모델을 오프라인에서 학습한다. 사후 영상·실제 PWM·출력 기간·명령 전후 센서값은 예측 입력에 넣지 않는다. 센서는 정답을 제공하며, 이 정답을 독립적인 영상 각도 정밀도 검증으로 해석하지 않는다.

전체 입력 영상을 고정 8×4 회색조로 축소하고 예정 명령을 함께 사용하는 ridge 모델을, 변화 없음과 학습 자료의 평균 변화량 기준에 비교한다. 이 거친 영상 표현은 작은 움직임을 잃을 수 있다. 해상도·정규화·정규화 강도를 평가 결과에 맞춰 탐색하지 않으며, 영상 모델의 우위를 전제하지 않는다.

각 기록을 한 번씩 제외하고 나머지 세 기록으로 학습하는 진단과 전체 네 기록으로 학습한 모델을 저장한다. 전처리의 학습 통계와 평균 기준은 각 회차의 학습 기록만 사용한다. 같은 촬영 그룹에서 연속된 자세를 관측한 네 기록이므로 이 진단은 독립 시험이나 미래 구동 성능이 아니다. 네 기록의 명령이 모두 같아 다른 출력·시간·방향의 효과와 후보 명령 선택 능력을 학습할 수 없다. 모델은 관측하지 않은 명령을 거부하며 `controlEligible=false`를 유지한다.

센서 원시 표본·구간 범위와 예측 잔차를 함께 남긴다. 관측된 센서 범위는 센서 정확도나 예측 신뢰구간을 뜻하지 않는다. 표본 네 개로 보정된 예측 구간을 만들었다고 주장하지 않으며, 남은 측정 불확실성과 모델 불확실성을 별도로 기록한다.

```sh
python3 tools/train_manual_collection.py \
  --index .local/manual-collection/first-dataset-index.json \
  --dataset .local/manual-dataset-20261104/dataset-v2/dataset.json \
  --output-dir .local/manual-learning-20261104/run-02
```

학습 전에 원본 색인에서 데이터셋을 재구성해 저장된 파생 자료와 대조하고, 입력·목표 PNG의 파일 해시와 복원 픽셀 해시를 확인한다. 새 결과 폴더에는 `model.json`과 `development-evaluation.json`을 저장한다. 평가 파일에는 회차별 학습 기록·모델·예측·잔차와 원시 센서 요약이 포함된다. 원본 데이터셋의 `trainingPerformed=false`는 원본 생성 시점의 사실로 보존하며, 학습 결과에서 별도로 실행 여부를 기록한다.

## 다조건 M4 모델의 개발 학습

`tools/train_manual_multi.py`는 명시한 `(INDEX, DATASET)` 쌍을 각각 원본까지 재검증해 연결한다. 최소 3개 자료 쌍·3개 적격 기록·2종 명령이 필요하며, 카메라 식별·영상 크기·라벨 정책이 다르거나 세션·명령 실행·데이터셋이 중복되면 거부한다. 실패·제외 항목도 출처에 남긴다. 서로 다른 수집 계약을 이름만 바꿔 혼합하지 않는다.

여섯 조건을 사용할 때는 먼저 각 조건의 세션·해시를 색인에 명시하고 위 `manual_collection_dataset.py`로 각각 변환한다. 아래 `.local/my-m4/`는 준비할 자료의 예시 경로다. 각 `dataset.json`에는 `--export-png`로 내보낸 입력·목표 영상이 필요하며, 학습 출력은 아직 없는 폴더를 사용한다.

```sh
python3 tools/train_manual_multi.py \
  --source .local/my-m4/20-350/index.json .local/my-m4/20-350/dataset/dataset.json \
  --source .local/my-m4/20-500/index.json .local/my-m4/20-500/dataset/dataset.json \
  --source .local/my-m4/25-350/index.json .local/my-m4/25-350/dataset/dataset.json \
  --source .local/my-m4/25-500/index.json .local/my-m4/25-500/dataset/dataset.json \
  --source .local/my-m4/30-350/index.json .local/my-m4/30-350/dataset/dataset.json \
  --source .local/my-m4/30-500/index.json .local/my-m4/30-500/dataset/dataset.json \
  --output-dir .local/my-m4/multi-development
```

출력은 전체 자료의 `model.json`과 기록 하나씩 제외한 `development-evaluation.json`이다. 개발 진단은 영상·명령 ridge, 학습 평균, 무변화의 세 기준을 비교하며 독립 시험이 아니다. 예측 함수는 학습에서 관측하지 않은 명령을 거부하고 `controlEligible=false`를 유지한다. 이 명령은 촬영·구동하지 않는다.

공개 도구의 위 개발 진단과 [실측 18건 고정 평가](evidence/2026-11-04-m4-action-prediction.md)는 구분한다. 후자의 다섯 기준선 비교는 별도 실험 실행기로 수행했다. 위 CLI만으로 해당 고정 학습·후속 평가 전체가 재현되는 것은 아니다.

## 고정 모델의 후속 기록 평가

첫 모델을 저장한 뒤 새 기록을 별도 촬영 그룹으로 수집하고, 기존 모델과 기존 학습 평균을 고정해 비교한다. 새 기록의 정답으로 모델을 다시 학습하거나 평균 기준을 갱신하지 않는다. 명령 전 영상과 예정 명령으로 저장 모델을 호출하는 사후 재생 평가이며, 구동 전에 실시간 예측을 제시하거나 모델이 명령을 선택한 실험은 아니다.

새 기록의 원본·영상 검증과 함께 학습 기록과의 중복, 촬영 조건·라벨 정책·명령의 일치를 확인한다. 성공 기록이 적어도 전체 시도·거부·제외 분모를 보존하며, 유효 자료가 없으면 성능 수치를 생성하지 않는다. 같은 장치·카메라 설정에서 뒤이어 얻은 자료이므로 독립 일자·시점·하중 일반화 성능으로 표현하지 않는다.

```sh
python3 tools/evaluate_manual_collection.py \
  --index .local/manual-followup-20261104/index.json \
  --dataset .local/manual-followup-20261104/dataset/dataset.json \
  --training-index .local/manual-collection/first-dataset-index.json \
  --training-dataset .local/manual-dataset-20261104/dataset-v2/dataset.json \
  --training-report .local/manual-learning-20261104/run-02/development-evaluation.json \
  --model .local/manual-learning-20261104/run-02/model.json \
  --plan .local/manual-followup-20261104/locked-plan.json \
  --output-dir .local/manual-followup-20261104/evaluation
```

이 명령은 후속 수집 색인과 검증된 데이터셋을 만든 뒤 실행한다. 고정 계획에는 기존 모델 SHA-256, 예정 명령, 최대 시도 수, 실패 시 중단과 재학습 금지를 명시한다. 출력 폴더는 새 경로여야 한다. 학습은 최소 3건 조건을 유지하고, 고정 모델 평가는 유효 1건부터 가능하다. 전건 거부라면 `unavailable`과 거부 분모를 기록한다.

평가 도구 자체는 그룹·원본·실행의 중복 여부를 검사하지만, 계획 파일 작성 시점과 실제 촬영 순서를 독립적으로 증명하지 않는다(`temporalOrderVerified=false`). 실제 후속 수집 순서는 별도의 실행 기록으로 확인해야 한다. 실측 결과와 한계는 [날짜별 평가 기록](evidence/2026-11-04-m4-action-prediction.md)에 정리했다.

## 목표 변화량 기준 오프라인 후보 비교

`learning.manual_action_selection.rank_actions(model, image, target_delta_deg, candidates)`는 고정된 다조건 영상·명령 모델의 지원 명령만 예측한다. 명령 전 BGRA 영상과 음수 아래 방향의 목표 센서 변화량을 받아 각 예측의 목표 잔차 절댓값을 비교한다. 정지(변화량 0)를 자동 포함하며 동률에는 정지를 먼저, 나머지는 입력 순서를 따른다. `rank_predictions(predictions, target_delta_deg)`는 사전에 고정한 명령별 평균 등에서 계산한 `command`와 `predictedDeltaDeg` 목록을 같은 기준으로 비교한다. 각 후보의 예측·잔차와 선택 결과를 반환한다.

이 계산은 오프라인 전용이고 제어 허용 상태를 변경하지 않는다. 같은 시점에 실제로 실행하지 않은 후보의 결과는 관측되지 않았으므로 순위나 선택이 실제로 가장 좋았다는 증거가 아니다. 센서 변화량 목표는 물체 거리나 파지 성공으로 검증된 값이 아니며, 이 함수만으로 물체 접근·집기를 실행하지 않는다.

## 물체·집게 상대 전이의 오프라인 재사용

센서 라벨과 별도로 `build_visual_session`에서 기존 단일 명령의 영상·출력·시각 근거를 재감사할 수 있다. 물체와 양 턱의 프레임 주석을 연결하는 [상대 상태 학습·선택](relative-action-selection.md)은 별도 CLI이며 수집 UI의 자동 제어로 연결되지 않는다. 관측 계약과 학습·평가 그룹을 분리하고 가림·구도 변경·미지원 명령은 보류한다.

## 대량 수집의 저장 예산

기본 기록은 8fps다. 원본을 보존하면서 수집량을 늘려야 할 때 서버에 `--sample-fps 4`를 지정할 수 있다. 해상도와 BGRA 무손실 저장은 유지하고, 60초 세션의 프레임 예산은 500개에서 260개로 줄인다. 선택 프레임의 최대 간격 0.3초 등 기존 감사는 유지하므로 실제 간격이 초과하면 부적격이다. 4fps 서버에는 같은 설정으로 촬영한 새 참조가 필요하며, 각 세션은 남은 저장 공간과 예비 공간을 확인한다.
