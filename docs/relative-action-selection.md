# 물체·집게 상대 상태의 오프라인 행동 선택

[현재 학습 단계](visual-action-learning.md) · [수집 사용법](manual-data-collection.md) · [기존 선택기](offline-action-selection.md)

고정 구도의 물체 기준점과 양 턱 끝의 주석 또는 별도 등록 특징에서 상대 위치를 만들고, 예정 단일 관절 명령의 결과를 학습해 정지와 비교한다. [구현](../learning/relative_action_learning.py)은 장치·서버에 접근하지 않는다. 자동 영상 인식이나 실물 집기 정책의 완성을 뜻하지 않는다.

물체 없는 장면은 [외부 영상의 팔 표식 상태](projected-arm-learning.md)로 별도 학습할 수 있다. 그 네 픽셀 상태를 이 문서의 세 물체·턱점 상태와 같은 모델에 섞지 않는다.

[순차 접근·닫기 시험 코어](model-grasp-trial.md)는 이 선택기를 제한된 단일 명령과 실제 재관측에 연결한다. 현재 검증은 모의 환경이며, 자동 인식이나 실물 집기 성공을 추가한 것은 아니다.

## 상태·예측·선택

상태는 `[물체−양턱 중점 x, 물체−양턱 중점 y, 두 턱점 거리]`의 세 픽셀 값이다. 물체 실루엣의 중심은 파지점이 아니며 투영된 턱점 거리는 물리적 개구폭이 아니다. 깊이·접촉·충돌 여유·물체 지지 여부를 알 수 없으므로 이 세 값으로 닫기나 들기 성공을 판정하지 않는다. 첫 고정 자세 밖의 회전·가림은 별도 관측 계약이 필요하다.

명령별로 현재 상태에서 다음 상태의 변화량을 예측하는 ridge(계수 1 고정)를 학습한다. 동일 명령 전이 2개 미만은 지원 명령으로 승격하지 않는다. 이 최소 수는 계산 경로 확인용이며 충분한 학습량이나 정확도 기준이 아니다. 학습자료만으로 중심·척도를 구하고, 같은 자료의 명령별 평균과 무변화 기준을 함께 평가한다. 세 상태값의 유클리드 거리를 목표 잔차로 사용하며, 목표는 호출자가 명시한 영상상 목표다. 모델이 파지 목표를 자동 추정하지 않는다.

후보는 지원한 단일 명령과 정지다. 예측 후 상태가 목표에 가장 가까운 후보를 선택하고 동률이면 정지를 우선한다. 미학습 명령, 학습 상태의 각 좌표 범위 밖, 음수 턱점 거리 예측은 보류 이유를 보존한다. 좌표별 범위 검사는 자세·충돌 안전 보증이나 예측 신뢰구간이 아니다. M4 위 방향은 일반 수집 프로필에서 제외된 상태를 유지하며, [별도 고정 모델·단발 경로](m4-up-commissioning.md)와 구분한다. 결과는 항상 `controlEligible=false`, `graspVerified=false`다.

## 원본과 주석의 연결

기존 [영상 전이 감사](../learning/manual_collection_dataset.py)의 `build_visual_session`은 단일 명령·실제 출력 OFF·명령 전 영상의 수신 및 저장·고정 관측창·원본 해시를 재검사한다. 센서값은 상대 상태 모델의 입력이나 정답으로 쓰지 않는다. 기존 M4 센서 데이터셋의 시간창과 라벨은 `build_session`에 그대로 유지한다. 여러 명령을 포함한 세션을 자동 분할하지 않는다.

주석은 각 전후 프레임의 `frameId`, `pixelSha256`, `accepted`, `method=analyst_points`, `inputFrameOnly`, `points={object,jawLeft,jawRight}`를 갖는다. 각 점은 `[x,y]`다. 전후 프레임을 각각 보고 표시한 사후 분석가 주석이며, `inputFrameOnly` 선언 자체가 실제 구동 전 추론이나 주석자의 독립성을 인증하지 않는다. 가림·중첩·대응점 불명확은 `accepted=false`로 남긴다.

각 기록에는 `sessionRoot`(저장소 기준 상대 경로), `sessionSha256`, `annotation`을 둔다. `annotation`은 `sessionId`, `captureGroup`, `before`, `after`, `context`를 갖는다. `context`의 `physicalView`, `object`, `poseRegime`, `landmarks`는 실제 동일 구도·물체·자세 조건·대응점 의미를 식별한다. 감사된 카메라 설정·영상 크기도 모델에 묶는다. 설정 ID가 같아도 카메라를 옮겼으면 물리 구도 ID를 바꿔야 한다. 외부 카메라와 집게 위 카메라 좌표는 합치지 않는다.

세션·명령 실행·프레임 중복과 서로 다른 관측 계약은 거부한다. `captureGroup`은 인접한 전이를 묶으며 학습·평가에 겹칠 수 없다. `evaluationGroups`에 지정한 그룹 전체만 평가하고 평가가 없으면 `unavailable`로 기록한다. 원본 오류·주석 부적격 수를 따로 보존하며 평가 불가 행을 오차 분모에서 조용히 지우지 않는다. 이 도구는 평가 촬영의 시간 순서·사전 고정·일반화를 인증하지 않으며 결과는 개발 재생 진단이다.

```sh
python3 tools/replay_relative_actions.py \
  --manifest .local/relative-state/manifest.json \
  --output-dir .local/relative-state/replay-01
```

매니페스트 최상위는 `records` 배열과 `evaluationGroups` 배열이다. 평가자료가 없으면 후자는 빈 배열로 두고 개발 학습만 확인한다. 선택을 시험하려면 `query={state,target,commands,context}`를 추가한다. `context`는 모델의 전체 관측 계약과 일치해야 한다. 출력은 새 디렉터리의 `model.json`, `report.json`이며 원본·주석·모델은 `.local/`에 둔다. 실제 출력·센서값·사후 영상은 선택 질의에 넣지 않는다.

## 저장 모델을 고정한 평가와 질의

`--frozen-model`과 원래 모델 파일의 `--model-sha256`을 함께 지정하면 재학습 없이 새 자료를 평가한다. 명세의 모든 기록은 `evaluationGroups`에 속해야 한다. 기록이 없는 명세에 `query`만 넣으면 저장 상태의 후보 비교만 수행하며 새 평가 표본으로 세지 않는다.

```sh
python3 tools/replay_relative_actions.py \
  --manifest .local/relative-state/evaluation-manifest.json \
  --frozen-model .local/relative-state/train/model.json \
  --model-sha256 '<고정한 모델 파일의 SHA-256>' \
  --output-dir .local/relative-state/frozen-evaluation-01
```

고정 경로는 파일 해시·모델 차원·유한 계수·지원 표본 수·학습 출처 구조를 검사하고, 기존 원본 재감사와 학습/평가 중복 검사를 유지한다. 파일 해시는 원본 심사를 대신하지 않는다. 관측 계약은 카메라·구도·물체·표식·다른 관절 자세 조건까지 전체가 같아야 하며, 다른 모델에 맞추려고 관측 계약을 바꾸지 않는다. 고정 모델은 복사·덮어쓰기하지 않고 새 출력 폴더에 `report.json`만 기록한다. 결과는 실물 실행 허용이나 집기 검증이 아니다.

## 집게 위 카메라 자료의 연결

외부 카메라로 전체 팔·물체 배치를 확인하면서, 양 턱이 구별되는 집게 위 카메라의 상태로 별도 모델을 만들 수 있다. 두 카메라 좌표를 합산하거나 동일 프레임으로 취급하지 않는다. 매니페스트 기록에 `observationCamera=gripper`, `gripperObservationRoot`(저장소 기준 상대 경로)를 추가하면 [결합기](../learning/gripper_camera_dataset.py)가 원래 외부 영상·출력 감사를 유지한 채 ESP32-CAM의 사전·사후 주석 프레임을 연결한다.

별도 수집 기록은 `esp32-before.jpg/json`, `esp32-after.jpg/json`이다. JSON은 `sessionId`, `hostClockId`(수집 세션 ID), `clockDomain=python_monotonic`, `requestStartedAt`, `receivedAt`, `persistedAt`, `sha256`, 원본 `headers`를 보존한다. `fresh=1`의 요청 뒤 캡처 근거·부팅 ID·프레임 ID·시각 증가·실제 JPEG 복원 해시를 검사한다. 카메라의 `first_dma_buffer` 시각은 정확한 노출 시각을 보증하지 않는다.

이 카메라의 관측 계약은 외부 영상의 센서 라벨창과 다르다. 사전 요청은 명령 전 최대 40초 이내, 저장 완료는 명령 전 0.1초 이전이어야 한다. 사후 요청은 OFF 확인 후 3초 이후이고 저장 완료는 30초 이내다. 두 요청·저장은 단일 명령의 전체 출력 이력과 외부 촬영 감사 구간 안에 있어야 한다. 이 넓은 창은 영상 검토와 별도 HTTP 촬영 시간을 허용하기 위한 것으로 정착·상태 불변·정확한 동시 촬영을 뜻하지 않는다. 전용 정책을 모델의 관측 계약에 저장하며 외부 카메라 자료와 혼합하지 않는다. 실제 모델에 두 영상을 함께 입력해 성능이 좋아지는지는 별도 비교가 필요하다.

## 2026-11-04 저장자료 개발 확인

접근 완료 기록 3개를 재감사하고 프레임을 복원했다. 같은 구도·명령(M4 아래 20%·350ms)의 2개 전이만 근사 수동 주석에 적격이었다. 나머지 1개는 구도 변경·턱 중첩으로 보류했다. 두 전이의 상대 y 변화는 −19px, −16px였다. 점별 약 ±4px는 분석가의 근사 표시 수준이며 측정 정확도나 신뢰구간이 아니다.

2개로 학습한 모델에 첫 학습 입력과 가상의 y 방향 20px 감소 목표를 넣어 단일 명령과 정지의 순위 계산을 확인했다. 이는 학습 입력에서의 계산 확인이며, 다른 명령 중 최적 선택이나 목표 도달 근거가 아니다. 마지막 사후 상태는 학습 입력 범위 밖이어서 추가 선택을 보류했다. 별도 평가 적격 0건이므로 예측 성능 수치를 보고하지 않는다.

기존 센서 평가자료의 추가 입력 3개에는 목표 물체가 없어 상대 상태 라벨로 전환하지 않았다. 따라서 기존 학습18/평가18의 센서 예측 성능을 이 경로의 영상 예측 성능으로 재사용하지 않는다. 기존 M5 수동 정렬 5건과 M1 수동 닫기 2건도 영상·출력 감사는 통과했지만, 변경 후 측면 구도의 실제 전후 영상 14장을 확인한 결과 턱 끝이 중첩되어 현재 3점 주석 계약에서는 7건 모두 보류했다. M1 두 건은 초기 개방으로 복귀한 독립 반복도 아니다. 감사 통과를 대응점 주석 적격이나 모델 선택 성과로 표현하지 않는다.

당시에는 해당 구도에서 필요한 정렬·접근·닫기 명령의 작은 묶음으로 기록→원본 감사→상대 주석 경로를 확인한다. 이후 시작 상대 위치·자세/하중을 기록하면서 명령별 반복과 분리된 평가 그룹을 늘린다. 모든 관절이나 동시 동작을 먼저 수집하지 않는다. 기존 수치는 과거 요청 조건이며 새 실물 실행안이나 현재 이동 여유의 확인을 뜻하지 않는다. 실제 구도·전원·센서·이동 여유를 확인한 뒤 명령별 출력·기간·횟수를 정한다. 미실행·중단·헛닫기·사람 개입도 분모에 남긴다.

## 2026-11-04 첫 M1 수집·학습 결과

[집게 위 영상의 첫 M1 학습·후속 평가](evidence/2026-11-04-gripper-relative-learning.md)는 첫 8시도 중 5완료·3실패를 보존하고, 4건 학습 후 새 1건을 고정 평가했다. 무변화 기준이 이 1건에서 가장 잘 맞았으며, 근사 수동 주석에 대한 개발 확인으로 제한한다. 이후 별도 350ms 시도는 동작 전 중단돼 학습자료가 되지 않았다.

## 후속 관절별 자료

[2026-11-05 관절별 수집·고정 모델 평가](evidence/2026-11-05-multi-joint-relative-learning.md)는 기존 관측 계약으로 M1·M5·M2 자료를 각각 재감사·학습한 결과다. 관절별 계약을 합치지 않았고, 원본 적격·명료한 움직임·예측 가능 범위를 구분한다.

## 2026-11-07 자세를 분리한 학습과 구동 전 예측 확인

2026-11-06~07에는 실제 관측 계약을 다시 확인해 M1과 M4를 별도로 학습했다. M1은 닫기·열기 각각 40%·350ms의 중복 없는 전이 2건씩, 총 4건이며 M4는 아래 35%·350ms의 중복 없는 전이 2건이다. 두 모델의 다른 관절 자세 조건(`poseRegime`)은 서로 다르므로 하나의 연속 집기 정책으로 연결하지 않았다. 이 수는 채택된 학습 전이 수이며 전체 수집 시도의 성공률이 아니다. 이전 자세의 M1 자료나 다른 관절·관측 계약의 자료를 섞지 않았다.

M1 모델을 고정한 뒤 수동으로 계획한 닫기 40%·350ms 한 번에 대해, 수집기의 명령 의도 기록 시각보다 4.105초 먼저 예측을 저장했고, 실제 RUN 전송 전에도 입력·모델을 재검사했다. 이 후속 확인은 1시도·1구동 완료·1평가이며 실패는 0건이다. 전후 점은 모델 예측을 보지 않은 분석가가 각 원본 영상에서 따로 확정했다. 원래 모델의 SHA-256은 유지됐고 재학습하지 않았다. 턱점 거리는 입력 119px에서 111.516px로 줄어들 것으로 예측했지만 사후 주석은 116px였으며, 절대오차는 4.484px였다.

| 고정 후 새 전이 1건의 비교 | 세 상태 벡터의 유클리드 오차 |
| --- | ---: |
| 상대 상태 ridge | 5.383px |
| 명령별 학습 평균 | 5.414px |
| 변화 없음 | **3.640px** |

표의 오차는 세 상태 차이의 유클리드 거리이며 턱점 거리 한 성분의 오차와 다르다. **이 1건에서는 무변화 기준이 가장 잘 맞았다.** 점별 약 ±3px는 분석가의 근사 표시 수준이며 측정 정확도나 신뢰구간이 아니다. 구동 전 예측을 저장했더라도 1건의 근사 주석 개발 비교이며 정식 독립 시험·다른 자세 일반화·파지 성능을 입증하지 않는다.

사후 상태 `[-4, -15, 116]`으로 기존 모델의 다음 예측을 질의하면 학습 상태 범위 밖으로 거절된다. 이를 우회해 추가 명령을 선택하지 않았다. 이 확인에서 모델이 선택한 실물 명령은 0회, 파지 검증은 0회다. 수동 수집 명령 1회의 사전 예측과 [순차 접근·닫기 코어](model-grasp-trial.md)의 실물 폐루프 실행을 구분한다. 원본·주석·모델은 비공개로 보존하며 다음 단계는 바뀐 자세 범위의 자료 보강과 별도 고정 평가다.

## 2026-11-08 현재 접촉 자세의 별도 M1 계약

[닫기→들기 연결 실험](evidence/2026-11-08-close-lift-integration.md)에서는 이전 수동 주석 모델의 입력 범위를 강제하지 않고, 등록한 양턱 패치와 물체 원호의 별도 계약으로 4건(열기 2·닫기 2)을 학습·고정했다. 원래 특징 실패 1건은 실패를 보존한 채 새 계약에서 원본부터 다시 감사했다. 이전 자세의 7건 모델이나 준비 동작의 사후 결과를 자동 혼합하지 않았다.

이번 실물 분모는 수집 4회와 준비 열기 3회다. 준비 뒤 범위 거절과 대응점 모호함으로 고정 후 평가·모델 선택 닫기·닫기→들기 연결은 모두 0회다. 새 계약의 입력 범위는 실제 학습 전이의 각 좌표 최소·최대이며, 거절된 후보값·사후 정답·클램프로 넓히지 않는다. 등록 주석의 필드와 현재 구도 한계는 [관측 어댑터 계약](model-grasp-trial.md#등록-특징과-원호를-사용하는-새-관측-계약)을 따른다.
