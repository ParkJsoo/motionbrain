# 화면 표식의 오프라인 시간 검증

기존 M4·물체 박스 데이터 계약의 광학 노출 조건을 검토하는 선택적 **합성 실험 도구**다. 카메라 촬영·화면 표시·장치 연결·모터 출력을 하지 않는다. 기존 영상 100ms, M4 20ms, 앵커 15초, 원본 저장 250ms 조건과 적용 범위를 변경하지 않는다. [새 시각 행동 학습](visual-action-learning.md)의 선행 필수 단계가 아니며, 이 도구의 기준을 새 관측 계약에 자동 적용하지 않는다.

## 설치 드라이버에서 확인한 범위

2026-10-18 검토한 ESP32-CAM 앱은 JPEG와 XCLK 20MHz를 요청하며 기본 프로필은 QVGA였다. 수동 노출을 고정하지 않았다. 당시 설치된 Arduino 2.0.17 카메라 라이브러리의 OV2640 및 CAM HAL 실행 코드는 고정 소스 [`f0bb429`](https://github.com/espressif/esp32-camera/tree/f0bb42917cddcfba2c32c2e2fb2875b4fea11b7a)에서 재컴파일한 해당 오브젝트의 실행 섹션 바이트와 일치했다. 전체 라이브러리나 현재 장치 펌웨어·실제 센서의 동일성을 주장하지 않는다. 이후 실물 진단에서 관찰한 OV3660 식별과 OV2640 전용 가드의 불일치는 [레지스터 진단 결과](ov2640-register-diagnostic.md)에 별도로 남겼다.

- [`ov2640.c`](https://github.com/espressif/esp32-camera/blob/f0bb42917cddcfba2c32c2e2fb2875b4fea11b7a/sensors/ov2640.c)의 `aec_value` 0–1200은 µs가 아닌 레지스터 노출 코드다. 초기화는 자동 노출을 활성화한다. 실제 노출 상한은 현재 센서 설정·행/프레임 타이밍·클록 오차·설정 적용 시점이 없으면 숫자로 확정할 수 없다.
- 공통 enum의 `PIXFORMAT_RAW`와 달리 이 OV2640 구현의 포맷 설정에는 RAW 지원 분기가 없다.
- 센서 JPEG → I2S/DMA → 프레임 큐 → `esp_camera_fb_get` → HTTP 본문 경로다. 앱은 받은 JPEG를 그대로 전송한다. 센서 DSP의 과거 프레임 기여 부재까지 입증한 것은 아니다.
- QVGA에는 센서 window 및 DSP 축소가 적용된다. JPEG/DSP 출력 행을 센서 원시 행과 동일시할 수 없다.
- [`cam_hal.c`](https://github.com/espressif/esp32-camera/blob/f0bb42917cddcfba2c32c2e2fb2875b4fea11b7a/driver/cam_hal.c)의 framebuffer timestamp는 DMA 시작 및 VSYNC 처리 뒤 MCU 시계를 읽은 값이다. 광학 노출 시작이 아니다.

현재 물리 노출 상한은 **미검증**이다. status의 AEC 값만 읽어 노출 시간으로 바꾸는 방식도 불충분하다. 특히 DSP AEC 선택 비트는 setter와 초기 status 해석이 반대일 수 있고, SCCB 실패를 값으로 축소하는 경로가 있으므로 향후 읽기에는 원시 bank/register와 성공·실패 상태가 필요하다.

## 화면 표식으로 제한할 수 있는 시간

새 임의 표식을 만들기 **전** 호스트 시각을 `t0`로 기록하고, 화면에서 나온 그 표식의 빛을 촬영한 원본을 받는다고 가정한다. 표식의 실제 광자가 `t0` 이후라는 인과 관계를 이용한다. 화면에 그리라고 요청한 시각을 실제 발광 시각으로 간주하지 않는다.

필요한 폭 `W`는 **노출 시작부터 노출 종료까지 전체 구간의 상한**이다. 어두운 동안의 적분, 여러 부분 노출 사이의 간격도 포함한다. 200ms 노출의 마지막 1ms만 표식이 빛났더라도 폭을 1ms라고 할 수 없다.

다음 중 하나를 별도로 입증해야 한다.

1. 각 원시 행에 새 표식의 광자가 있고, 각 행의 전체 노출 구간 폭이 `W` 이하다.
2. 새 표식 광자가 적어도 하나 있고, 영상 전체에 기여한 모든 노출의 가장 이른 시작부터 가장 늦은 종료까지 폭이 `W` 이하다. 롤링 셔터의 행간 차이와 처리 경로의 과거 노출도 이 폭에 포함한다.

원본 전체 수신 시각을 `tr`, 동일 호스트 시계에서의 보수적 오차 예산을 `U`라 하면 가정하의 구간은 `[t0-W-U, tr+U]`다. 소비 시각에서 이 구간의 시작을 뺀 값이 100ms 이하여야 한다. 행동 전 영상은 행동 시작 구간의 마지막 시각에서도 100ms를 만족하고, 노출 구간의 끝이 행동 시작 구간보다 엄격히 앞서야 한다. 행동 후 영상은 노출 구간의 시작이 OFF 구간 끝+50ms보다 엄격히 뒤여야 한다. 저장은 노출 상한 뒤 시작하고 소비 전에 완료해야 하며, 원래 저장 트랜잭션은 250ms 이하여야 한다.

`U`는 이 모델의 경계 확장에 필요한 전체 오차 예산이다. 미확인 시계 변환 오차를 생략하거나 호스트 시계 연결만으로 광학 동시성을 주장할 수 없다. `W`나 `U`가 없으면 검사기는 구간을 만들지 않는다. 단일 프레임 처리 및 표식의 신선성도 가정으로 명시하며, 검사기는 그 주장을 실측 사실로 인증하지 않는다.

## 재현 방법

저장소 루트에서 실행한다. 출력 폴더는 새 경로여야 한다.

```bash
python3 tools/check_optical_challenge.py --synthetic-example \
  --output-dir .local/optical-example
python3 tools/check_optical_challenge.py --root .local/optical-example \
  --output-dir .local/optical-recheck
python3 -m unittest tests.test_optical_challenge
```

`case.json`은 가상의 나노초 시각과 합성 픽셀을 포함한다. `manifest.json`은 입력·보고서 해시와 크기를 보존한다. 재검증은 원래 case의 해시를 검사한 뒤 결과를 다시 계산한다. 실패한 case도 새 출력 폴더에 그대로 남긴다. 해시만으로 manifest까지 함께 바꾼 조작을 인증할 수는 없다.

표식은 64비트 값과 CRC32를 Manchester 방식으로 표현한다. CRC는 오류 검출용이며 인증이나 신선성 증거가 아니다. 기본 셀 너비 2픽셀에서 가로 416픽셀이므로 현재 QVGA 320픽셀에 그대로 적용할 수 없다. 모든 행은 분모에 남으며 오래된 행·흐린 셀·부분 셀·잘못된 크기를 자동 보정하지 않는다. 검사기는 위치가 이미 정렬된 회색조 합성 픽셀만 검사한다. 실제 화면의 원근·모아레·JPEG·센서 잡음에서의 검출 능력은 검증하지 않았다.

`modelConsistent=true`와 종료 코드 0은 **입력한 합성 가정 사이의 모순이 검출되지 않았다는 뜻**이다. `modeledBoundsNs`는 가상 구간이다. 물리 출처는 입력으로 거부하며, `opticalExposureVerified`, `trainingEligible`, `controlEligible`, `executionAllowed`는 항상 false다. 이 출력은 기존 `opticalCalibration` 형식이 아니고 학습 수집기에 연결되지 않는다.

기존 계약에서 요구하는 M4 물리 측정 시각·20ms 나이, 립밤 의미 앵커·15초 연결, 실제 출력/OFF 이력, 정착 영상의 비중첩과 전체 팔의 시각 정착, 실제 원본 저장 영수증은 별도 [수집 적격성 검사](data-pipeline.md)의 근거로 남는다. 이 도구의 통과가 실물 적격 전이의 확보를 뜻하지 않는다.
