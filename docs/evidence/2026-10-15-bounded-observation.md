# 유한 관측 시험 — 2026-10-15

[데이터 계약](../data-pipeline.md)

행동 수집 전 영상 소비와 영속 저장을 고정 기준으로 평가한 비구동 시험이다. **사용성 기준을 통과하지 못했다.**

## 고정한 조건

- 독립 요청20개, 모두 완료하고16개 이상이 유효 소비·저장을 마쳐야 통과.
- 요청마다 같은 앵커로 현재 영상 최대5회, 앵커 준비 뒤 운영 예산3000ms. 성공 후 추가 촬영 없음.
- 영상 나이100ms, 앵커 나이15000ms, 소비 검사→핵심 증거 저장250ms.
- 앵커 획득은 최대8회·1초 간격이며 별도 시간으로 기록한다. GET 타임아웃4초, 블로킹 I/O를 강제 취소하지 않는다. 늦게 반환하면 실패로 기록한다.
- 신선도 초과만 요청 안에서 재촬영하며 직전 저장 성공을 요구한다. 외관·식별 손실, HTTP 오류, 취소, 시간 역행, 저장 실패·지연은 요청 종료다. 안전·출력 불변 확인 실패나 저장 오류는 묶음도 중단한다.

## 결과

20개 중7개를 실행한 뒤 저장 지연으로 중단했고13개는 실행하지 않았다. 실행한 요청은1/7 성공(14.3%), 예정 수 대비 확인된 성공은1/20이다. **1/20은20회 실측 성공률이 아니다.**

| 항목 | 결과 |
| --- | ---: |
| 소비·저장 성공 | 1요청 |
| 촬영5회 소진 / 운영3초 초과 | 3 / 2요청 |
| 저장250ms 초과 | 1요청,268.89ms |
| 앵커 획득 실패 / 감사 오류 | 0 / 0 |
| 현재 영상 신선도 거부 / 소비 | 30 / 1 |
| 영상 소비 검사 나이 p50 / p95 / 최대 | 140.31 / 182.41 / 183.95ms |
| 저장 p50 / p95 / 최대 | 73.55 / 86.33 / 268.89ms |
| 요청→핵심 종료 p50 / p95 / 최대 | 9.481 / 10.632 / 10.969s |

저장 초과 요청의 마지막 영상도 신선도에서 거부됐다. 소비 성공 뒤 저장 지연을 관찰한 것으로 해석하지 않는다. 늦은 저장을 보존한 뒤 추가 촬영과 후속 독립 요청은0회였다. 3초는 운영 예산이며 시스템 호출 강제 취소 기한은 아니다.

원본45 JPEG와 대응 기록은 로컬에 보존했다. 이 시험에서 모터 명령은 없었으며 `trainingEligible=false`, `controlEligible=false`다. 병목은 영상 신선도, 앵커 대기, 간헐 저장 지연이었다. 자동 조작이나 학습 수집 준비 완료의 근거로 사용할 수 없다.
