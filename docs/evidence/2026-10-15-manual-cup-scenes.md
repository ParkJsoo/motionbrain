# 컵 수동 이동·가림 비구동 검증 — 2026-10-15

**실제 컵의 작은 이동·복귀 영상은 이미지 조건을 만족했고, 큰 이동과 일부/완전 가림 영상은 각각 범위 초과·외관 불일치로 거부 조건에 해당했다.** 각 자세 6장씩 확인했다. 이는 저장 이미지의 대응·거부 조건 검증이며 실시간 제어, 정확한 위치 오차, 가림 후 자동 추적 복구를 입증한 결과가 아니다.

## 진행 조건과 데이터

사용자가 배터리함→XL4015 분리, USB·Pi 연결 유지, 컵과 종이 준비를 확인했다. 카메라 고정 상태에서 컵과 종이만 사용자가 움직였으며 모터 명령은 보내지 않았다. 초기 장치 IDLE·motorEnabled=false·5개 모터 출력 0을 확인한 뒤 단계별 완료 응답을 받고 수집했다.

1. 정지 기준: 기존 `probe_fast_observation.py`로 anchor 원본 1개와 camera 표본 6개 저장. anchor는 실제 detector의 cup/confidence 0.888, box `(146,125,103,87)`이다.
2. 왼쪽 이동: 요청한 이동보다 화면상 크게 이동하여 약 57픽셀 범위 초과 표본으로 보존했다.
3. 중간 위치: 사용자가 절반 되돌려 약 28픽셀 이동 표본을 추가했다.
4. 일부 가림: 컵을 유지하고 종이로 컵 왼쪽 약 1/3을 가렸다. 손잡이·오른쪽 부분은 보였다.
5. 완전 가림: 종이로 컵 몸통과 손잡이를 가렸다.
6. 복귀: 종이를 치우고 컵을 처음 위치 근처로 되돌렸다. 약 8픽셀 수평 차이가 남았다.

2~6단계는 기존 `probe_action_collection.py`를 그대로 재사용했다. 각 단계에서 perception 원본 6개와 직접 camera 원본 6개를 저장했으며, 이미지 진단에는 해당 단계의 **직접 camera 원본**을 사용했다. 종이·이동 상태는 각 단계 첫 원본을 육안 확인했다. 사용자의 완료 응답은 단계 설명이며 픽셀 단위 정답 라벨로 취급하지 않는다.

모든 코드는 Pi `/tmp/motionbrain-http-timing-20261015`에서 실행했다. 운영 서비스 저장소는 `559db54` 그대로이며 배포·재시작·펌웨어 업로드·카메라 설정 변경은 없었다. 수집 후 Pi 임시 코드 hash와 로컬 코드를 대조했다.

## 실시간 판정과의 구분

정지 기준의 실제 `measure()` 결과 6개는 전부 `source_age_exceeds_policy`였다. 보수적 계산 완료 나이는 **111.01~153.80ms**로 기존 100ms 기준을 초과했다.

사람이 단계별로 준비하는 동안 기준 anchor의 15초 유효기간이 지났다. 따라서 후속 30개는 `analyze.py`에서 **이미지 조건만 독립적으로 진단**했다. 원래 boot/source ID/JPEG hash를 검증하고 같은 고정 template, 전체 장면 후보·경쟁 후보, scale probe, score/margin/translation 기준을 사용했다. timestamp나 policy를 바꾸지 않으며, 각 결과에 실제 `anchorAgeMs`, `anchorExpired`, `liveAcceptanceEvaluated=false`, `controlEligible=false`, `trainingEligible=false`를 남겼다. 좌표도 `diagnosticCandidateBox`로 구분한다.

복귀 영상이 다시 닮았다는 것은 새 live anchor 없이 기존 추적 상태를 복구해도 된다는 뜻이 아니다. 기존 제어용 측정은 identity/appearance 상실 후 `new_anchor_required`를 유지한다. 이번 사람 속도의 독립 이미지 분석은 그 상태 전이·실시간 stale·실물 동작을 대신 검증하지 않는다. 학습용 실제 행동 transition 수는 여전히 0개다.
