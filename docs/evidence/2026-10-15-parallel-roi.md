# 원본 비교를 유지한 ROI 병렬 계산 — 2026-10-15

**Pi에서 이번 컵 이동·가림 원본 36장을 각각 3회 비교하여, ROI 계산 중앙값을 33.59ms에서 21.25ms로 36.7% 줄였다.** 108쌍의 비교에서 세 크기의 전체 점수 배열·후보 순서·최대 후보·경쟁 후보 결과가 완전히 같았다. 검색 영역이나 거부 조건을 줄인 최적화가 아니다.

최종 전체 소프트웨어 테스트 **461개 통과(18.746초)**. 실제 카메라 GET 12개에서는 계산 중앙값 24.24ms, 보수적 계산 완료 나이 103~137ms로 여전히 전부 100ms 정책을 초과했다. 모터 명령 0회, 제어/학습 적격성 false다.

## 변경 범위

- `learning/fast_observation.py`: 기존 세 크기의 `cv2.matchTemplate(..., TM_CCOEFF_NORMED)`와 각 `minMaxLoc` 호출을 한 프레임 안에서 병렬 실행한다. `_match_candidates`는 입력 순서대로 결과를 반환하여 같은 점수일 때의 선택 순서도 유지한다. 전체 장면·전체 크기의 경쟁 후보 검사와 기존 score/margin/scale/translation/나이/latch 판정은 그대로다.
- 작업 수는 1~3으로 제한하며 기본값은 3이다. 각 프레임의 executor context가 완료·예외·중단 시 모든 제출 작업을 기다리고 종료한다. 영속 pool, 다음 프레임 큐, 백그라운드 capture는 없다. 다른 서비스에 영향을 주는 전역 `cv2.setNumThreads()`는 호출하지 않는다. 프레임별 생성·종료 비용까지 비교에 포함했다.
- 기존 probe의 `--match-workers 1`은 직렬 기준 실행, 기본값/`--match-workers 3`은 병렬 실행이다. session에 `matchWorkers`를 기록한다. 운영 서비스 배포·재시작이나 펌웨어 수정은 하지 않았다.

이는 계산 결과를 보존하는 실행 방식 변경이다. 실제 물체 위치의 정답 정확도 향상, 학습 효과 또는 모든 하드웨어에서의 성능 향상을 주장하지 않는다. CPU 경쟁과 스케줄링에 따라 지연이 달라질 수 있고, executor join도 정해진 시간 안에 끝난다는 실시간 보장은 아니다. 최종 실제 경과시간은 기존 신선도 판정에 포함된다.

## 동일 원본 비교

[수동 컵 실험](2026-10-15-manual-cup-scenes.md)의 정지·큰 이동·작은 이동·부분 가림·완전 가림·복귀 각 6장, 총 36개 **직접 camera 원본**을 사용했다. 모든 JPEG hash와 boot/source ID를 확인했다. 두 실행 순서를 프레임·반복별로 교차하고 양쪽 warmup은 제외했다. 입력 디스크 읽기와 anchor 초기화는 제외했지만, JPEG hash/디코딩·작업 생성·전체 매칭·경쟁 후보 검사·join을 포함했다.

| 환경/실행 | 비교 수 | 중앙값 | 최소~최대 |
|---|---:|---:|---:|
| Pi 직렬 | 108 | 33.59ms | 30.53~47.36ms |
| Pi 병렬 3개 | 108 | 21.25ms | 17.01~39.93ms |
| Mac 직렬 | 36 | 2.42ms | 2.34~2.60ms |
| Mac 병렬 3개 | 36 | 1.11ms | 1.07~1.17ms |

Pi OpenCV 4.12.0의 기존 thread 설정 4, Mac 설정 12를 유지했다. Mac은 반복 1회이므로 Pi 결과와 합쳐 통계를 만들지 않는다. Pi는 같은 프로세스·같은 원본에서 직렬/병렬 결과를 직접 비교했으며 하드웨어가 다른 Mac/Pi의 부동소수 점수가 비트 단위로 같다고 주장하지 않는다.

점수 배열 전체와 후보 순서가 같으므로 기존 이미지 거부 판정도 보존된다. 작은 이동·복귀는 이미지 조건 통과, 큰 이동은 범위 초과, 부분/완전 가림은 외관 불일치라는 기존 결과를 유지한다. 과거 원본의 촬영 timestamp를 고치거나 anchor 유효기간을 늘리지 않았고, 이 비교는 과거 영상의 live 승인이 아니다.

## 실제 GET 검증과 남은 나이 문제

Pi 별도 `/tmp/motionbrain-roi-parallel-20261015`에서 실제 컵을 정지 상태로 12회 읽었다. 실행 ID는 `b0db7fec3b654d73bb5eb601b5199d8f`이며 기존 카메라 설정과 운영 서비스를 유지했다.

| 항목 | 중앙값 | 최소~최대 |
|---|---:|---:|
| 실제 `measure()` 계산 | 24.24ms | 19.73~27.30ms |
| 보수적 계산 완료 나이 | 122.58ms | 103.01~136.65ms |
| 원본/측정 durable 저장 후 나이 | 166.05ms | 143.82~356.52ms |

**12/12은 `source_age_exceeds_policy`로 거부했다.** anchor age는 모두 15초 이내다. 같은 원본 벤치마크의 36.7%는 계산 시간 개선이며 실제 전체 영상 나이가 36.7% 감소했다는 뜻이 아니다. 카메라 원본 나이·전송과 저장 지연이 남는다. 저장 이후 소비하는 경로는 계산 완료 시각보다 더 오래된 데이터를 사용하므로, 계산 시점만 보고 신선도를 통과시키면 안 된다.

최종 JPEG 13개·artifact 108개·event 26개를 Mac에 보존해 hash, terminal report, 실행 소스 hash를 검증했다. 시작/종료 출력 로그 동일, 장치 IDLE·출력 0·motorEnabled=false, CAM boot 유지·captureFailures=0, Pi 서비스 3개 active·NRestarts=0을 확인했다. Pi 운영 코드 `559db54`는 유지했다.

## 테스트·리뷰와 다음 단계

새 6개 테스트는 전체 점수 배열 일치·동점/완료 순서·좌표와 거부 및 latch 상태 전이·작업 수 제한·예외/KeyboardInterrupt 후 join·정상 처리 후 잔여 worker 없음 등을 검증한다. 기존 source-age·계산 시간 포함·중단/원본 저장 테스트도 통과했다. [전체 461개 테스트](roi-parallel-2026-10-15/tests.log)를 통과했고, 별도 리뷰 에이전트가 관련 41개 테스트와 Mac 실제 원본 비교를 재실행했다. 최종 코드·통계·실측 무결성·문서에서 P0/P1/P2 문제 없음. 소프트웨어 및 비구동 관측 결과이며 실물 모터 구동 검증은 아니다.

**다음은 기존 HTTP 계측을 활용해 원본 나이의 보수적 상한을 더 정확하게 계산할 수 있는지 검증하는 작업이다.** 요청 준비/TCP 연결 시작과 실제 GET 전송 시작은 다르므로, 서버의 age 샘플 이벤트보다 확실히 앞선 로컬 시각을 근거로 사용할 수 있는지 회귀 테스트부터 만든다. 전송 완료를 촬영 시각으로 간주하거나 100ms 기준을 완화하지 않는다. 물리 시계 교정·미래 drift·M4 시간 정합성과 실제 소비 시점 검증은 별도로 남는다.

컵·카메라는 현재 위치를 유지하고 배터리함은 분리, USB/Pi는 연결한 상태면 된다. 다음 소프트웨어 검증에는 수동 컵 이동이 필요 없다. 펌웨어/카메라 설정 변경이 필요해지면 구체적인 변경과 비구동 실험을 먼저 준비하고 업로드 승인을 받는다.
