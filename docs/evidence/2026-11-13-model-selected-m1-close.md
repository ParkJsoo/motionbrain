# 새 고정 모델이 선택한 M1 닫기 실물 시험

2026-11-13의 별도 고정 모델 시험 세 묶음에서 **모델 선택 CLOSE 총 4명령의 실제 실행과 OFF를 확인했다.** 최신 새 정렬 시험은 한 명령 후 등록한 접촉 참조의 허용오차에 도달했고, 사용자가 현장에서 양쪽 턱의 접촉을 확인했다. 물체는 탁상 지지 상태이며 보유·들기는 미검증이다. 앞선 목표 미도달과 2명령 시험의 관측 기한 실패·미확정 사후값은 그대로 보존한다.

첫 묶음에서는 고정 구도에서 **모델이 CLOSE와 정지를 비교해 선택한 M1 닫기 1명령을 실제 실행하고 OFF 후 새 영상으로 닫힘을 확인했다.** 영상상 턱축 간격은 **126.677 → 113.767px**로 줄었다. 수동 등록 참조 목표 **85.3±1.5px에는 도달하지 못했다.** 아래의 단일명령 수치·분모는 이 첫 묶음의 결과다.

## 관측과 실행 조건

집게 영상은 320×240이다. 영상의 row95에서 양 턱축의 유일한 어두운 구간 중심을 직접 측정하고, 주변 직선 구간의 품질 근거를 요구했다. 기존 row55 외삽 관측과 다른 등록 계약이며 이전 모델·수치 범위를 변환해 사용하지 않았다. 이 값은 영상 단면 간격으로, 실제 턱끝 간격·깊이·접촉·파지력의 측정이 아니다. 외부 영상으로 물체·전완의 고정 상태를 함께 검사했다.

목표 85.3px는 사람이 준비한 닫힌 자세의 **보이는 턱 구성 참조**다. 물체를 잡았다는 정답이나 기계적 닫힘 한계가 아니다. 새 관측의 실험 범위는 84~139.5px로 별도 선언했으며, 이 범위를 기계 안전 한계나 미래 결과의 보장 범위로 해석하지 않는다.

명령 요청은 CLOSE 60%·450ms였다. 드라이버 이력에서 실제 최대 PWM 크기는 **80/255**, 0이 아닌 출력 구간은 **582ms**였다. 램프와 정지 과정을 포함하므로 요청 비율·기간을 실제 출력과 동일시하지 않는다. 다섯 모터 OFF와 세션의 정상 종료를 확인했다.

## 예측·실측·기준선

고정 모델은 영상 간격 한 값과 예정 명령으로 간격 변화를 예측하는 ridge 모델이다. 실행 전에 CLOSE의 예상 목표 오차 29.731px와 정지의 41.377px를 비교해 CLOSE를 골랐다. 정지의 실제 반사실 결과를 관측한 비교 실험은 아니다.

| 항목 | 값 |
| --- | --- |
| 새 영상의 실행 전 간격 | 126.676957px |
| ridge의 실행 후 예측 | 115.031415px |
| 명령 평균의 실행 후 예측 | 114.756007px |
| OFF 후 새 영상 실측 | 113.766699px |
| ridge 절대오차 | 1.264716px |
| 명령 평균 절대오차 | 0.989308px |

| 실제 목표 오차 | 41.376957 → 28.466699px |

**이 한 사례에서는 명령 평균이 ridge보다 정확했다.** 상태 입력의 추가 효과나 모델 우위를 입증하지 않았다. 모델이 선택한 실제 닫힘과 예측 모델의 기준선 대비 우위는 구분한다.

학습에 제공한 전이는 9건이며 OPEN 6건·CLOSE 3건이다. 명령별 최소 2건 조건에 따라 CLOSE450 3건, OPEN350 2건, OPEN450 2건의 모델 항목이 만들어졌고, 나머지 단일표본 명령은 실행 후보로 승격하지 않았다. CLOSE의 학습 입력 범위는 **125.823631~129.898706px**다. 고정 모델 SHA-256은 `1e884df2ce1d0c731d2d2e2772372edab4fe2b9cbb158d96535ebbaac63e1821`이며, 시험 중 재학습하지 않았다.

## 수동 준비·모델 시험·이전 실패의 분모

## 종료와 남은 한계

실제 시험은 처음부터 **최대 1명령**으로 고정했다. 최초 입력은 학습 지원 범위와 선언한 시작 구간 안이었다. 출력 OFF 후 3초 이후의 새 프레임으로 사후 상태를 측정했고, 학습 프레임을 재사용하지 않았다. 예측 잔차 3px와 실제 영상 범위 검사를 유지했다. 오류·자동 재전송은 0건이며 종료 상태는 `budget_reached`다.

사후 상태 113.767px는 다음 CLOSE의 입력 지원 범위 밖이다. 이를 새 명령 입력으로 재사용하거나 지원 범위를 늘리지 않았다. 따라서 **한 번의 모델 선택 닫힘은 확인했으나 목표 도달·다회 재관측 보정·반복 성공률·접촉·집기·들기는 검증하지 않았다.** 수동 준비를 포함한 전체 집기 동작을 모델이 완료했다고 주장하지 않는다.

[M3 실물 접근 1회](2026-11-13-bounded-m3-approach.md)와 [기존 M3 고정 평가의 15/16 미통과](2026-11-12-m3-goal-prediction.md)는 별도 결과로 유지한다. 아래 후속 묶음도 이전 평가의 통과 판정으로 합산하지 않는다.

첫 사례에서는 ridge가 명령 평균보다 정확했지만, 위 첫 묶음에서는 평균이 더 정확했다. 서로 다른 모델·입력 조건의 단발 오차를 합쳐 상태 입력의 우위나 일반화를 주장하지 않는다.

원인은 에이전트의 두 카메라 시각 판독 대기 약 16초와 19초를 **전체 45초** 시험 기한에 반영하지 못한 실행 계획이었다. 두 번째 OFF 뒤 사후 영상 확인 전에 기한이 끝났다. 드라이버 OFF 확인과 사후 상태 확정을 구분하며, 원래 실패 시험·미확정 사후값을 수정하거나 명령을 재전송하지 않았다.

종료 후 모터 명령 없는 GET 관측 두 쌍에서 간격 **93.4711px·93.5111px**를 확인했다. 이는 첫 사후값과 비교해 추가 닫힘 진전을 확인하지 못한 별도 진단이다. 원래 시험의 두 번째 정식 사후 정답으로 채우거나, 두 번째 예측 오차·목표 도달을 계산하는 데 쓰지 않는다.

이 두 종결 시험의 모델 명령 분모는 **첫 묶음 1 + 후속 묶음 2 = 총 3명령**이다. 첫 후속 관측 뒤 모델이 다시 선택·실행한 연결은 확인했지만, 다회 닫기의 목표 완주·반복 성공률·파지·들기는 검증하지 못했다. 진행 중인 후속 수동 준비나 접촉 판독을 이 종결 시험의 모델 성과에 합치지 않는다.

## 새 정렬 묶음: 모델 선택 닫기와 현장 양턱 접촉 확인

물체의 접촉면·높이·앞뒤 정렬을 사람이 다시 준비했다. 새 등록·관측 context로 자료를 분리하고, 이전 배치의 모델이나 자료를 자동 승계하지 않았다. 수동 CLOSE 2건과 OPEN 2건의 실행·OFF·관측을 보존했으며, 이 중 CLOSE 2전이로 **사후 간격 자체를 예측하는 별도 ridge 모델**을 고정했다. 기존 delta 모델의 예측을 잘라내거나 기존 모델을 수정한 것이 아니다.

목표는 첫 수동 닫기 뒤 사용자가 양쪽 접촉을 확인한 원본의 **68.060189px**로 고정했다. 두 번째 수동 닫기는 115.160042→79.154412px의 부분 폐합 자료이며 양턱 접촉 성공으로 바꾸지 않았다. 모델 SHA-256은 `64e5afbaf0626ae797f8581e5428f21e2b8679cd492d1420dfb4169d325228c9`다.

사후 관측은 OFF 후 3.074초 이후 요청한 새 프레임이며, 시험의 두 프레임은 학습에 사용한 네 프레임과 겹치지 않는다. 모델 고정 후 재학습하지 않았다. 코어의 숫자 목표 판정과 현장 접촉 판독은 별도 근거다. 코어의 `contactVerified`·`graspVerified`·`liftVerified`는 자동으로 긍정하지 않았으며, 사용자 확인을 결합한 별도 기록으로 양턱 접촉만 확인했다.

| --- | --- |
| 이번 새 정렬 묶음 | 수동 4명령(CLOSE 2·OPEN 2) + 모델 선택 1명령 = 실제 5명령 |
| 더 닫힌 구간 수집부터 이번 정렬 시험까지 연결한 실행 원장 | 21시도 중 출력 전 거절 1건, 실제 20명령(수동 17·모델 3) |

21시도 원장에는 앞선 기한 실패 시험의 모델 2명령이 포함되며, 이 문서 첫 묶음의 모델 1명령은 포함되지 않는다. 프로젝트 전체 과거 M1 실험 누계와도 다르다. 수동 준비·접촉 수집, 미시작, 실패한 시험을 모델 성과로 합치지 않는다.

이 한 새 사례에서는 직접 사후값 모델의 오차가 위 두 기준선보다 작았다. 회귀 표현을 바꾼 효과와 상태 입력의 기여를 분리해 입증한 것은 아니며, 반복 성공률·일반화·파지 유지·들기 성공으로 확대하지 않는다. 확인한 진전은 **모델이 선택한 닫기 후 참조 자세 도달과 현장 양턱 접촉**이다.

## 후속 수동 M4 보유 확인: 미시작·완료·사후 판독 실패 구분

모델 닫기와 현장 양턱 접촉 확인 뒤, 별도의 수동 M4 UP 16%·200ms 검증을 1회 시도했다. 컨트롤러 상태·OFF 증빙의 최신성 검사에서 중단돼 **실제 UP 실행은 0회**다. 원결과는 `not_started`, `mayHaveRun=false`이며 다섯 모터 OFF를 확인했다. 이 수동 1시도는 위 M1 실행 원장 21시도나 모델 선택 명령 수에 합산하지 않는다.

성공한 GET 응답으로 증빙을 갱신한 직후에도 오래된 증빙의 나이는 약 244ms였다. 이어지는 RUN 의도 저장과 최종 원본 검증을 거치며 약 269ms가 돼 기존 250ms 한도를 넘었다. 증빙 준비 단계가 최종 검사 시간을 위한 여유를 확보하지 못한 연결 결함이며, 최신성 검사가 출력을 막았다. 실패 원장과 단발 소비를 보존하고 명령을 재송신하지 않았다. 동작 뒤 사후 영상은 없으며, 물체 보유 실패나 성공을 판정한 시험이 아니다. **실물 들기·보유는 여전히 미검증**이다.

이후 성공한 GET 근거만 최대 4회 갱신하고 저장 뒤 나이 200ms 이내를 요구하는 준비 경로를 추가했다. 서비스가 복원된 조건에서 GET 전용 **IDLE 진단 3/3건**은 통과했지만 ARMED 실행 검증은 아니었다. 사용자의 별도 새 1회 승인으로 같은 16%·200ms 시험을 수행했으나, 실제 ARMED 상태의 네 증빙 갱신 구간이 각각 약 0.22·0.23·0.09·0.14초였고 제한 횟수 안에 두 증빙을 200ms 이내로 맞추지 못해 다시 출력 전에 중단됐다. 두 번째 시험은 RUN 의도 저장에도 이르지 않았고 `not_started`·`mayHaveRun=false`·다섯 모터 OFF를 보존했다.

이 시점까지 후속 수동 M4는 **별도 2시도·실제 UP 0회**였다. 이전 명령을 자동 재송한 것이 아니며, 두 원실패와 각각의 승인·단발 소비를 유지한다. IDLE 진단 통과를 ARMED 연결 성공이나 재발 방지 완료로 확대하지 않는다. 이 두 미시작은 M1 원장 21시도와 별개이며, 물체 보유·들기 판정도 여전히 미완료다.

펌웨어 적용과 새 단발 시험을 묶은 별도 승인 뒤, 동일 부팅·출력 순번으로 상태와 출력 근거를 결합하는 경로를 적용했다. 세 번째 수동 16%·200ms 시험은 **명령 출력과 OFF를 완료**했고 오류는 없었다. RUN 직전 두 근거의 나이는 각각 약 **92ms**, 실제 드라이버 출력은 최고 **30/255**·비영 구간 **312ms**였다. 이는 요청한 출력·기간과 구분한 사후 실측이다. 다섯 모터 OFF를 확인했지만 관측 각도는 전후 모두 **195.99°**였고 물체는 탁상 지지 상태로 남아, 상승·보유를 판정할 수 없었다.

세 번째 시험까지 후속 수동 M4의 분모는 **3시도: 2회 미시작·1회 실제 출력 완료**였다. 앞선 두 실패를 그대로 보존하며 이 한 번의 연결 완료를 반복성이나 보유·들기 성공으로 확대하지 않는다. 세 시험 모두 M1 원장 21시도와 모델 선택 명령 수에서 제외한다.

다음에는 현재 양턱 접촉·탁상 지지와 별도 **50%·500ms 단발·관측 중단 기준3°** 범위를 확인받아 수동 시험을 수행했다. 명령 receipt와 OFF는 확인했으나, 사후 영상의 판독 결과 제출이 기한을 넘겨 **시험은 실패로 보존**했다. HTTP 최신성 실패나 출력 미시작과는 다르다. 실제 드라이버 출력은 최고 **90/255**·비영 구간 **619ms**, 관측 각도는 **195.99 → 196.17°**였다. 요청127/255·500ms와 실제 출력을 구분하며, 명령을 재송하지 않았다.

실패 뒤 별도 GET 전용 현재 관측은 두 카메라2쌍을 **1.265초 이상** 분리해 확보했고 OFF와196.17°를 확인했다. 물체는 탁상 지지 상태였으며 보유는 미확정이다. 이 시간외 관측은 원시험의 정식 사후 관측이나 완료로 소급하지 않는다. 현재 M4 분모는 **별도4시도: 2회 미시작·1회 완료·1회 출력/OFF 뒤 사후 판독 실패**, 실제 출력2회다. M1 원장21시도와 모델 선택 성과에 합산하지 않는다.

## 판독 시간을 반영한 별도 소프트웨어 정책

기존 45초 모델 시험과 기본 60초 촬영 수명은 유지했다. 새 명시 정책 `observed95-reviewed-lower-close-v1`만 전체 시험 상한을 **120초**로 허용하며, 별도 `recording_seconds=120` 선택에서 촬영·프레임·바이트 예산을 함께 늘린다. 이 촬영 세션에서는 시작 후 **110초 초과 새 pulse 거절**, **115초부터 자동 종료**를 적용해 정리 여유를 둔다. 코어 기한도 세션의 실제 남은 수명에 맞춰 제한해야 한다.

관측 3초·RUN 직전 결정 0.25초·OFF 후 최소 3초·고정 모델과 원본 결합·실제 범위·예측 잔차·실패 무재송은 그대로다. 시각 판독 뒤에는 새 fresh 영상을 다시 확인해야 하며, 오래된 영상의 시각만 갱신하지 않는다. 관련 **196개 소프트웨어 회귀**가 통과했지만, 이 결과는 새 120초 정책의 실물 완주 검증이 아니다. [정책과 호출 계약](../model-grasp-trial.md)을 따른다.
