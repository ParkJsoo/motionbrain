# M4 수집과 행동 예측 평가 (2026-11-04)

[수집·데이터셋·학습 사용법](../manual-data-collection.md) · [문서 색인](../README.md)

M4 아래 방향 여섯 명령 조건에서 **기존 18건으로 모델을 고정하고 새 18건을 평가**했다. 명령별 평균의 MAE는 **0.367°**로, 명령 전용 ridge(0.595°)와 영상·명령 ridge(0.605°)보다 작았다. 이번 거친 영상 표현의 추가 기여는 확인되지 않았다. 같은 날 순차 자세의 센서 변화량 예측 결과이며, 독립 일반화·모델 기반 제어·물체 집기 성능을 입증하지 않는다.

## 고정 모델의 후속 18건 평가

학습자료는 최초 다조건 6건과 반복 12건으로, 조건마다 3건씩 총 18건이다. 새 평가자료를 수집하기 전에 비교 모델을 학습·고정했고 평가 정답으로 재학습하지 않았다. 후속 묶음은 **18시도·18완료·18적격**, 원본 영상 **1,935프레임**이며 마지막 기록의 IDLE·전 관절 출력 0을 확인했다.

| 고정 비교 기준 | 새 18건 MAE | 새 18건 RMSE |
| --- | ---: | ---: |
| 변화 없음 | 2.154° | 2.264° |
| 전체 학습 평균 | 0.624° | 0.778° |
| 명령별 학습 평균 | **0.367°** | **0.435°** |
| 명령만 사용하는 ridge | 0.595° | 0.743° |
| 영상·명령 ridge | 0.605° | 0.757° |

이 다섯 기준의 고정 학습·후속 평가는 별도 실험 실행기로 수행했다. 공개 `tools/train_manual_multi.py`는 원본 검증·다조건 학습과 기록 제외 개발 진단을 제공하며, 이 고정 평가 전체를 그대로 재현하는 CLI는 아니다.

명령별 평균은 조건당 학습 3건으로 계산했다. 30%·500ms 조건의 후속 3건에서도 명령별 평균 MAE는 0.553°, 영상·명령 모델은 1.326°였다. 이 결과는 특정 표현·고정 설정의 비교이며 영상 자체가 도움이 될 수 없다는 결론은 아니다.

## 입력·정답과 평가 조건

- 대상은 M4 아래 방향, 예정 명령은 **20·25·30% × 350·500ms** 여섯 조합이다. 요청 기간·예정 PWM과 실제 출력 기간·PWM은 구분한다.
- 예측 입력은 명령 전 현재 영상과 예정 명령이다. PTS뿐 아니라 호스트 수신·저장 근거도 명령 이전이어야 한다. 사후 영상·실제 PWM·출력 기간·센서값은 입력에서 제외한다.
- 정답은 명령 의도 시각 **−3~−0.1초**와 출력 정지 확인 **+3~+6초**의 M4 센서 중앙값 차이(이후−이전)다. 원시 표본·구간 범위를 보존하며 물리적 정착·센서 정확도·정확한 장치 시각 동기화를 보증하지 않는다.
- 영상 특징은 전체 프레임을 **8×4 회색조**로 축소한 값이다. 작은 움직임을 놓칠 수 있다. 영상 모델의 우위를 전제하지 않고 명령만 쓰는 모델과 단순 기준선을 함께 비교했다.
- 모델·원본·데이터셋 해시를 확인하고 학습·후속 자료의 중복을 검사했다. 평가 도구 자체는 계획 작성 시점과 촬영 순서를 독립 인증하지 않으며(`temporalOrderVerified=false`) 별도 실행 기록으로 순서를 확인했다.
- 같은 날·한 장치·카메라 설정의 연속 자세를 사용했다. 최종 후속 묶음 전 시작 자세를 복귀했지만, 각 명령마다 같은 시작 자세로 되돌린 반복 정밀도 시험은 아니다.
- 기존 M2 32개, 정착 전후 M2 17개, finite-profile 자료는 이 M4 자료와 자동 혼합하지 않는다. 아래 단일 명령 개발자료와 최종 다조건 학습 18건도 별도다.

## 시도·실패·미시작 분모

아래 행은 서로 다른 수집 단계이며 한 번의 독립 시험으로 합산하지 않는다. 실패 기록을 성공으로 바꾸거나 명령을 자동 재전송하지 않았다.

| --- | --- | --- |
| 초기 통신 검증 | 2기록·RUN 전송 0회 | 첫 기록은 출력 이력 GET 연결 종료, 둘째는 ARM 응답 연결 종료. 둘째 세션 내 정지 확인 실패는 그대로 보존하고 별도 조회에서 전축 출력 0·빈 큐 확인 |
| 응답 축소 뒤 20%·250ms | 1시도·1저장 완료 | 센서 45점 모두 223.68°로 변화 미검출. 동일 명령 4건 데이터셋에서 제외 |

| 최종 별도 18회 | 18시도·18저장·18적격 | 시작 자세 복귀와 현장 감독 후 진행. 네 중단 이후의 조건부 재개이며, 위 성능표는 이 18건만 평가 |

선행 실패 네 묶음 중 한 건은 묶음 기록과 개별 수집 세션의 대응을 독립적으로 입증하지 못했다. 실패·미시작 분모에서 제외하지 않으며, 최종 18건 원본 검증과 이 선행 기록의 연결 한계를 구분한다.

초기 통신 실패의 원본은 35·138프레임, 센서 총 27점이며 프레임·메타데이터 해시가 일치했다. 두 번째 세션의 `finalIdleOffVerified=false`는 별도 정지 확인 뒤에도 변경하지 않았다. 이후 [TCP 진단](2026-11-04-http-response-gap.md)은 요청 확인 전 연결 종료와 응답 본문 재조립 지연을 구분했지만 물리적 손실 위치·ARM 실패의 직접 원인은 확정하지 못했다.

## 요청과 실제 출력의 차이

첫 20%·250ms 요청은 예정 PWM −51과 달리 실제 드라이버 쓰기가 −10→−20→−30→−40→−30→−20→0이었고 비영 구간은 322ms였다. 센서 변화는 검출되지 않았다. 같은 25%·350ms 요청 4회도 최대 PWM 크기는 60으로 같았지만 실제 비영 구간은 **434~548ms**였다. 요청 시간을 실제 출력 기간으로 대체하지 않는다.

| 최초 다조건 예정 명령 | 센서 변화량 | 실제 최대 PWM 크기 | 실제 비영 구간 |
| --- | ---: | ---: | ---: |
| 20%·350ms | −0.79° | 51 | 405ms |
| 25%·350ms | −1.32° | 60 | 456ms |
| 30%·350ms | −1.93° | 60 | 466ms |
| 20%·500ms | −2.11° | 51 | 792ms |
| 25%·500ms | −2.02° | 63 | 594ms |
| 30%·500ms | −2.73° | 76 | 666ms |

후속 반복 12건의 실제 비영 구간도 422~769ms였다. 드라이버 쓰기는 소프트웨어 PWM 기록이며 전기적 파형·토크 실측이 아니다. 순차 자세와 명령 조건의 효과를 이 작은 표에서 인과적으로 분리할 수 없다.

## 결론과 남은 검증

수집→원본 검증→데이터셋→학습→고정 모델 비교가 실제 M4 기록으로 연결됐다. 영상 기반 모델도 학습했지만, 이 표현에서는 명령별 평균보다 예측이 좋아지지 않았다. 센서 구간 범위가 0°여도 센서 정확도를 증명하지 않으며, MAE는 정답 센서 라벨에 대한 오차로서 실제 각도 정확도나 예측 신뢰구간이 아니다.

이 평가는 예정된 명령의 결과를 사후 재생으로 비교한 것이다. 실행하지 않은 후보의 결과를 관측하지 않았으므로 후보 선택의 최적성이나 목표 접근 성능은 별도 시험이 필요하다. 물체·집게 상태 추정, 그 상태에 따른 학습 모델의 행동 선택·재관측, 반복 파지·들기와 다른 날짜·구도·하중 검증은 남아 있다. 현재의 오프라인 후보 비교는 제어 적격을 부여하지 않는다.
