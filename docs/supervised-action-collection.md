# 현장 감독하의 단일 관절 수집

이 수집기는 한 관절·한 방향의 짧은 동작 묶음을 실행하고, 영상 기록과 사후 측정을 분리한다. 사용자는 현장을 계속 관찰하며 묶음의 시작·중단·다음 방향을 결정한다. 무인 수집이나 위치 제어기가 아니다.

## 동작과 현재 한계

- 묶음당 1~3개 유한 명령을 한 번에 하나씩 실행한다. 실제 출력 OFF와 3초 관측 대기 뒤 다음 명령을 보낸다. 정확한 자세 맞춤·자동 왕복·명령 재전송은 없다.
- M1·M2·M3·M5 양방향과 M4 아래 방향의 과거 출력 상한을 구분한다. M4는 묶음당1회이며 위 방향은 과거 큰 이동 사례 때문에 비활성이다. 이 상한은 현재 자세에서의 안전한 이동 범위를 보장하지 않는다.
- 아이폰 무손실 압축 프레임과 PTS를 저장한다. 실시간 특징점 추적·정착 판정은 하지 않는다. 한 프레임 누락·느린 저장은 기록하고, 지속 소스 중단·저장/시각 오류에는 새 명령을 막는다.
- 네트워크 결과 불명은 부분 실행일 수 있다. STOP·출력 확인 후 종료하고, 같은 sessionId는 다시 실행하지 않는다. 중간 종료 후 자동 재개하지 않는다.
- 예외적으로 ARM 전 출력 OFF가 확인된 큐 조회(`GET /sequence`)의 `RemoteDisconnected`만 기존 요청 제한 시간 안에서 한 번 재조회한다. 두 시도는 모두 기록하며, 명령 전송·출력 중 조회·정리 과정에는 이 복구를 적용하지 않는다.
- 명목 명령 기간과 실제 출력 기간은 다르다. 드라이버 PWM 이력을 보존하지만 전류·토크 실측이나 실제 관절 회전이라고 해석하지 않는다.
- 2026-11-03까지 신규 경로로 M2 전이 17개를 실물 수집·사후 측정했다. 아래 실측 범위 밖의 관절·구도·장치 상태는 별도 검증이 필요하다. 기존 모델의 실물 성공과 신규 데이터의 학습·평가를 구분한다.

## 첫 실물 수집 결과 (2026-11-03)

M2의 같은 측면 구도에서 부모 링크의 초록 표식 2개와 손목 쪽 강체의 빨강 표식 2개를 사용했다. 전후 상태는 영상상 상대 방향이며 실제 관절각으로 보정하지 않았다.

- 총 13묶음에 계획된 23동작 중 17동작이 실행됐고, 17개 모두 출력 이력·OFF 후 3초 이상 관측·사후 측정 조건을 통과했다. 4묶음의 통신·응답 처리 실패로 나머지 6동작은 RUN 이전에 미실행으로 남았다. 이 실패도 전체 시도 수에 포함한다.
- 완료한 17개는 위 9개·아래 8개다. 출력 명령은 63%, 기간은 450ms 또는 550ms였으며, 실제 PWM 이력과 전후 상태를 함께 보존했다. 짧은 명령이 항상 짧은 실제 출력이나 작은 이동을 만들지는 않았다.
- 마지막 6묶음·12동작은 모두 실행·측정에 성공했다. 일부 표식 검색 영역은 저장 영상에서 조정했으며, 색·정착·출력 증거 기준을 완화하거나 측정 실패 때문에 재구동하지 않았다.
- 최종 수집은 제어기 직접 연결을 사용했다. 앞선 간헐적 연결 종료의 근본 원인이나 장기간 통신 신뢰성이 입증된 것은 아니다.
- 17개 모두 같은 `development` 수집 그룹이다. 아래 오프라인 학습·탐색 평가를 수행했으며 독립 시험 자료는 없다. 과거 명령 시작 후 4초 계약의 32개 전이·기존 모델 평가 수치와 혼합하지 않는다.

## 실제 출력 이력을 반영한 오프라인 학습 (2026-11-03)

`settled_endpoints_after_confirmed_off_v1` 계약의 17개만 사용했다. 기존 측정 파일 9개의 SHA-256, 측정 설정 해시, 색인 행과 원본 측정 행의 일치를 확인했다. 이번 학습에서 영상 재측정·새 촬영·구동은 수행하지 않았다. 출력 이력은 펌웨어의 드라이버 쓰기 기록이며 전기적 PWM 파형·전류·토크의 외부 계측이 아니다.

요청 PWM은 위 +160·아래 −160, 요청 기간은 450·550ms다. 실제 드라이버 기록의 절대 PWM 최대값은 50~100, PWM이 0이 아닌 기간의 합은 588~1,156ms, 절대 PWM 시간적분은 13.68~64.80 PWM·s였다. 각 드라이버 쓰기 값이 다음 쓰기까지 유지된 것으로 적분하며, 해당 모터의 마지막 0 출력까지 확인한다. 이미 PWM이 0인 구간과 중복 OFF 기록까지의 대기시간은 활성 출력 기간에서 제외한다. 요청 기간이나 마지막 HTTP 응답 시각을 실제 출력 기간으로 대신 쓰지 않는다.

고정 릿지 계수 α=1로 두 개의 6입력 모델을 각각 학습했다. 기존 `joint_prediction.fit/predict/scores` 수치 함수만 재사용하고, 옛 데이터 로더·700/900ms 입력 계약·모델 선택·시험 분할은 사용하지 않는다.

| 모델 | 입력 | 사용 가능한 시점 |
|---|---|---|
| 실행 전 예측 | 이전 영상상 상대 방향·속도, 요청 부호 PWM·기간·부호 기간, 명령 방향을 곱한 이전 상대 방향 | 명령 실행 전 |
| 사후 설명 | 이전 영상상 상대 방향·속도, 실제 부호 최대 PWM·출력 기간·부호 PWM 시간적분, 명령 방향을 곱한 이전 상대 방향 | 출력 이력이 확보된 실행 후 |

정답은 OFF 확인 뒤 관측한 상대 방향과 실행 전 상대 방향의 차이다. 사후 상태·속도·정답·실제 출력 이력은 실행 전 모델의 입력에 포함하지 않는다. 이번 17개에서는 요청 PWM 크기가 모두 같으므로 다른 요청 PWM에 대한 반응을 학습했다고 볼 수 없다.

평가는 측정 묶음 하나를 제외하고 나머지 15~16개로 학습하는 진단을 9회 수행했다. 매회 표준화와 기준선의 방향별 평균도 제외된 묶음을 빼고 계산했다. 모든 행은 계속 `development`이며, 아래 값은 동일 수집 그룹 내부의 탐색 점수다. 서로 인접한 묶음의 자세·시간 상관, 같은 구도, 일부 저장영상의 사후 검색 영역 조정이 있으므로 독립 시험이나 미래 시점 예측 검증으로 해석하지 않는다. 하이퍼파라미터 검색·최고 모델 선택은 하지 않았다.

| 방법 | 평가 전이 수 | 평균 절대오차 | 제곱평균제곱근오차 | 변화 방향 일치 |
|---|---:|---:|---:|---:|
| 무변화 기준선 | 17 | 2.804° | 3.058° | 0/17 |
| 학습 부분의 방향별 평균 기준선 | 17 | 1.105° | 1.447° | 17/17 |
| 실행 전 예측 모델 | 17 | 1.353° | 1.718° | 17/17 |
| 실제 출력 기반 사후 설명 모델 | 17 | 0.607° | 0.755° | 17/17 |

점수는 각 묶음 평균의 단순 평균이 아니라 17개 예측 오차를 합쳐 계산했다. 실행 전 모델은 방향별 평균보다 나빴다. 사후 모델의 작은 오차는 실제 출력 이력이 결과 설명에 유용하다는 탐색 근거이며, 명령 선택 전에 0.607°로 예측할 수 있다는 뜻은 아니다. 방향 일치는 단순 방향 기준선도 17/17이어서 세밀한 명령 선택 능력의 증거로 삼지 않는다. 과거 +4초 계약의 MAE 0.665°와 우열을 비교하지 않는다.

마지막으로 17개 전체에 각각 적합한 개발 모델을 저장했다. 이 모델들의 학습자료 MAE는 실행 전 0.855°·사후 0.359°이며 위의 묶음 제외 점수와 구분한다. 두 모델 모두 `controlEligible=false`이고 기존 실물 선택기에는 연결하지 않았다. 독립 그룹 평가, 실제 관절각 보정, 모델 기반 실물 제어는 미검증이다.

재현에는 기존 측정 파일과 아래 형태의 로컬 색인이 필요하다. 공개 저장소에는 비공개 원본·행별 예측·가중치를 포함하지 않는다.

```sh
python3 tools/train_supervised_prediction.py \
  --index .local/supervised/eligible-endpoint-index.json \
  --output-dir .local/supervised/development-run-001
```

색인은 `motionbrain.local_supervised_endpoint_index.v1` 형식으로 계약, 단일 `captureGroups`, `split: development`, 개수·방향별 개수, `independentTestSetAvailable: false`, `legacyCommandPlus4SecondsDataIncluded: false`를 명시한다. `sources`에는 색인 기준 상대 경로 `path`·`sha256`·`configHash`를, `entries`에는 `measurementSource`와 해당 측정 파일의 적격 `row` 전체를 담는다. 선택한 측정 파일의 적격 행을 누락하거나 중복하면 거부한다. 지원 범위는 M2의 영상상 상대 방향이다.

새 출력 디렉터리에 `development-evaluation.json`과 무결성 영수증 `result.json`을 저장하며 기존 실행 결과는 덮어쓰지 않는다. 입력·코드 해시, 실행환경, 묶음별 학습/제외 ID, 표준화·계수, 행별 예측·출력 요약을 함께 남긴다. 다음 검증은 사전에 정한 실행 전 모델·기준선을 별도 수집 그룹에서 비교하는 것이다. 기존 17개를 다시 나누거나 실패 동작을 재전송해 독립 자료로 만들지 않는다.

## 새 그룹 평가를 위한 모델 고정

`tools/freeze_supervised_evaluation.py`는 기존 학습 영수증·측정 색인·코드 해시를 검증하고 전체 17개로 학습한 실행 전 모델을 그대로 복사한다. 새 모델을 학습하거나 후보를 다시 선택하지 않는다. 사후 출력 모델은 고정 묶음에서 제외한다.

2026-11-03에 고정한 비교 대상은 실행 전 모델, 방향별 평균 기준선(위 +2.716722981°·9개, 아래 −2.902127872°·8개), 무변화 0°다. 모델의 계수·표준화와 기준선 평균을 미래 평가자료로 갱신하지 않는다. 아래 명령은 고정 파일만 만들며 촬영·구동·새 자료 채점은 하지 않는다.

```sh
python3 tools/freeze_supervised_evaluation.py \
  --index .local/supervised/eligible-endpoint-index.json \
  --training-run .local/supervised/development-run-001 \
  --output-dir .local/supervised/frozen-evaluation-001
```

`evaluation-bundle.json`에는 모델·기준선, 입력 순서, 측정 계약·출처 지문과 아래 규칙을 저장한다. `result.json`은 그 파일의 SHA-256을 보존한다. 원본·행별 식별 정보가 포함되므로 이 묶음은 로컬에 보관한다.

- **요청 조건:** M2·63%·PWM ±160, 위/아래 × 450/550ms의 4조건이다. 기존 개발자료의 조건별 수는 위550 7개·아래550 6개·위450 2개·아래450 2개다. 실제 출력 최대값이나 활성 출력 기간을 요청 조건으로 대체하지 않는다.
- **주 비교:** 같은 적격 행에서 `실행 전 모델 MAE − 고정 방향평균 MAE`를 계산한다. 음수면 그 새 그룹에서 모델의 오차가 더 작았다는 뜻이다. 임의의 성공 각도·통계적 유의성·제어 가능 판정을 붙이지 않는다. 방향·요청 기간별 개수와 MAE·RMSE·편향·최대 절대오차도 함께 보고한다.
- **관측 범위:** 조건별 개발자료의 이전 상대 방향·속도 범위를 기록한다. 이는 실물 안전 범위가 아니다. 범위를 벗어난 적격 행도 남기고 전체 점수와 범위별 결과를 나눠 보고한다. 명령 조건 밖의 행은 별도 집계하며 오류가 큰 행을 사후에 제거하지 않는다.
- **자료 분리:** 새 이름만 붙인 그룹은 새 시험이 아니다. 모델 고정 이후의 새 촬영 근거와 기존 trial ID·식별자를 제외한 행 내용 지문·수집 보고서·원본 해시의 겹침을 확인해야 한다. 같은 설정을 재사용하는 것과 같은 원본을 재사용하는 것을 구분한다. 현재 도구는 이 심사에 필요한 기존 지문을 저장하며, 미래 자료의 중복 검사·채점기는 아직 포함하지 않는다.
- **측정:** 기존 전후 관측창·최소 프레임 수·최대 간격과 공통 측정 설정을 고정한다. 새 구도의 표식 영역·색 범위는 동작 전 등록 자료로 확정한다. 결과를 본 뒤 설정을 변경했다면 해당 그룹을 개발자료로 전환한다.
- **분모와 종료:** 계획·시도·실행·결과 불명·미전송·미시작·측정 제외·적격 수와 사유를 보존한다. 적격 행만 추린 색인으로 전체 시도를 대신하지 않는다. 총 시도 상한과 조건별 계획 수는 실제 수집 전에 고정하며, 적격 수 달성까지 반복하지 않는다. 부족한 조건을 채우려고 시작 자세로 왕복하거나 실패 명령을 재전송하지 않는다.

현재 고정 묶음의 수집 횟수·현장 운용 범위는 미정이며 실제 실행 계획은 아니다. 새 그룹 하나의 보류 평가도 다른 날짜·구도 일반화나 실물 제어 개선을 입증하지 않는다. 저장자료의 실행 전 창으로 오프라인 평가하는 것과 실제 명령 전에 예측을 산출하는 전체 경로의 검증도 구분한다. 다음 준비는 현재 구도·장치·측정 등록을 확인하고 유한 시도 계획을 고정하는 것이다.

## 준비·오프라인 검증

출력 방식 변경 후보는 [장치가 완료까지 관리하는 유한 출력 프로파일 설계](finite-output-profile.md)에 정리했다. 순수 실행부·드라이버·서비스 제어권과 안전 전이 경계를 오프라인으로 구현했으며, 운영 경로 활성화·실물 검증은 아직 하지 않았다. 아래 기존 수집 명령을 새 방식으로 바꾸거나 기존 17개와 새 프로파일 자료를 자동 혼합하지 않는다.

빌드에는 카메라 접근이 없다. 원본·계획·로그는 Git 제외 경로에 둔다.

```sh
mkdir -p .local/supervised/bin
bash tools/macos/build_action_recorder.sh .local/supervised/bin/mac-action-recorder
python3 tools/collect_supervised_actions.py profiles
```

계획에는 현재 장치 식별자·부팅 ID·구도·자세 배치·촬영 그룹·데이터 분할을 명시한다. 다음은 자리표시자를 바꿔 쓰는 **계획 생성 예시**다. 이 명령은 촬영·구동하지 않는다. 출력과 기간은 현재 현장에 맞게 검토해야 한다.

```sh
python3 tools/collect_supervised_actions.py prepare \
  --session-id session-001 --capture-group group-001 --split development \
  --device-id '<camera-device-id>' --view-id wrist-side --pose-context middle \
  --boot-id '<32-hex-current-boot-id>' --controller-url 'http://<controller-host>' \
  --joint wrist --direction up --percent 63 --durations-ms 550 \
  --helper .local/supervised/bin/mac-action-recorder \
  --output-plan .local/supervised/session-001-plan.json
python3 tools/collect_supervised_actions.py validate \
  --plan .local/supervised/session-001-plan.json \
  --helper .local/supervised/bin/mac-action-recorder
```

계획과 helper 해시를 고정한다. 60초·8fps·최대500프레임의 압축 최악 예산과 추가2GiB 여유 공간을 실행 전 확인한다. helper가 실제1920×1080을 제공하지 않으면 초기 관측에서 중단한다. 이전 날짜의 추적점을 재등록하지 않는다.

## 명시적인 실제 실행

현장 확인과 해당 묶음의 실행 범위를 정한 뒤에만 실행한다. 제어 토큰은 기존 안전한 메모리 전달 방식으로 `MOTIONBRAIN_HTTP_TOKEN`에 제공하며, 파일·쉘 이력·로그에 값을 남기지 않는다.

```sh
python3 tools/collect_supervised_actions.py run \
  --plan .local/supervised/session-001-plan.json \
  --helper .local/supervised/bin/mac-action-recorder \
  --confirm-plan-sha256 '<validated-plan-sha256>' --onsite \
  --output-dir .local/supervised/session-001
```

터미널 Ctrl-C/SIGTERM은 정지·마감 경로로 연결된다. 현장 물리적 정지 수단도 유지한다. STM32 데드맨은 HTTP sequence의 보호 스위치가 아니며 원격조작과 동시에 사용하지 않는다. 동일 제어기를 다른 호스트에서 동시에 조작하지 않는다. 로컬 실행기는 기존 공용 저널 잠금을 공유하지만 다른 장치의 조작까지 배제하지 못한다.

명령 실행 중 호스트가 갑자기 죽으면 pending 저널을 남기고 다음 실행을 차단한다. 미확인 출력을 수동으로 확인·복구하기 전 저널을 삭제하거나 새 경로로 우회하지 않는다. 정상 마감·OFF 확인 뒤에는 새 sessionId와 새 계획으로 다음 묶음을 시작한다. 실패한 명령 ID나 기존 출력 디렉터리를 재사용하지 않는다.

## 사후 측정

`tools/measure_supervised_collection.py`는 장치를 호출하지 않는다. 전후 구간에서 각 프레임의 표식을 독립 검출한다. 색상 범위·관측 영역은 해당 구도에서 정하며, 없는 표식·여러 후보·영역 경계 접촉은 해당 사례의 제외 사유다. 현재 자동 측정은 표식의 상대 방향·거리·한 축 상대 위치를 지원한다. M4 센서 원본은 HTTP 기록에 보존되지만 이 도구의 자동 라벨은 영상 좌표다.

측정 설정의 형태:

```json
{
  "schemaVersion": "motionbrain.endpoint_measurement.v1",
  "width": 1920, "height": 1080,
  "stabilityThreshold": 0.5,
  "points": [
    {"id":"reference", "roi":[100,100,200,200], "hsvLower":[40,100,80], "hsvUpper":[80,255,255], "minAreaPx":20, "maxAreaPx":500},
    {"id":"moving", "roi":[400,100,200,200], "hsvLower":[100,100,80], "hsvUpper":[130,255,255], "minAreaPx":20, "maxAreaPx":500}
  ],
  "representation":{"kind":"projected_position","moving":"moving","reference":"reference","axis":"x"}
}
```

좌표·색상은 형식 예시이며 실물용 확정 설정이 아니다.

```sh
python3 tools/measure_supervised_collection.py \
  --report .local/supervised/session-001/report.json \
  --config .local/supervised/measurement.json \
  --output .local/supervised/session-001-measurement
```

출력은 `measurements.json`과 `measurements.csv`다.

동작 전은 전송 시작 전0.75~0.10초, 결과는 OFF확인 후2.25~3초 구간을 사용한다. 최소3프레임·최대0.3초 간격과 설정한 안정성 기준을 검사한다. 고정3초 대기는 기계적 정착을 보장하지 않는다. 사례별 상태·변화량·원본 프레임·출력 이력과 제외 사유를 남긴다.

단위는 영상상 상대 방향(도) 또는 픽셀이다. 실제3D 관절각으로 표현하지 않는다. 기존 명령 시작+4초 계약과 다른 v3 데이터이며 자동으로 섞거나 학습하지 않는다. 한 촬영 그룹을 학습/검증/시험으로 분할하지 않는다. 다른 관절 배치·카메라 구도는 별도 맥락으로 기록한다.

블록 후반이 실패해도 앞선 사례에 완전한 전후 관측과 출력 근거가 있으면 심사한다. 이전/다음 명령이 측정창을 침범하거나 출력이 불명확하면 해당 사례를 제외한다. 정상 종료 플래그나 고정120개 사례 수를 데이터 생성의 필수 조건으로 삼지 않는다.
