## 4. 최신 구현·검증 수치

### 현재 사용할 선택형 비구동 경로

`--fresh-capture --capture-timing --connection-timing --fresh-age-mode send_start --causal-anchor --shadow-consumption --max-persistence-ms 250`

- 현재 영상: 정확한 fresh 증거에서 **소비 Pi 시각 − 해당 GET의 첫 socket 송신 직전 Pi 시각**이 first-DMA 기준 영상 나이 상한. **100ms** 유지.
- anchor: fresh checkpoint를 한 번 확보하고, 동일 CAM boot에서 그보다 나중에 촬영된 exact 검출 원본만 받는다. 메타데이터 최대 **8회**, 오래된 유효 frame이면 **1초** 간격 조회. HTTP/identity 실패는 즉시 중단. 새 원본 JPEG에 예전 box를 복사하지 않는다.
- anchor 나이 상한: **현재 Pi 시각 − checkpoint 첫 GET 송신 시각**. **15000ms** 유지. 수신 시각으로 수명을 다시 시작하지 않는다.
- 현재 프레임과 anchor 모두 이 선택형 gate에서는 CAM 속도/offset/2µs 여유를 쓰지 않는다. 기존 기본 비교 모드는 호환성을 위해 남아 있으므로 옵션을 생략하고 같은 보장을 주장하면 안 된다.
- 소비는 메모리상의 shadow 기록이다. 실제 actuator callback은 없다. 저장 **250ms**는 소비 후 현재 프레임의 핵심 증거 저장 완료 제한이다. syscall 강제 취소나 anchor 획득 전체 deadline이 아니다. 늦은 저장은 끝까지 join/보존하고 중단한다.
- anchor 만료·증거 불일치·저장 실패/지연이면 shadow 경로는 중단한다. 단순 프레임 나이 초과는 현재 probe에서 거부 기록 후 다음 표본을 수집할 수 있다. 이를 아래 A의 “단일 관측 요청” 계약과 혼동하지 않는다.
- same-boot 단조 timestamp·first-DMA 의미는 전제다. 광학 노출 시각을 교정한 것이 아니며 `controlEligible=false`, `trainingEligible=false`다.

## 6. 다음 작업 A — 유한한 관측 확보의 사용 가능성, 여기까지만

**산출물:** 기존 ROI/consumer/저장 코드를 재사용한 “단일 관측 요청” shadow 실행기와 시도 단위 평가 보고서. 또 다른 detector·펌웨어·수집 저장소를 만들지 않는다.

예상 수정: `learning/fast_probe.py`의 호출 경로를 분리/재사용하고 필요하면 작은 `learning/observation_attempt.py` 추가, 기존 CLI에 선택형 진입점 또는 얇은 도구 추가, 대응 가상 시간 테스트. 기존 코드부터 읽고 중복 기능을 만들지 않는다.

계약:

1. 요청 ID별 유한 capture 횟수·Pi 경과 시간 예산을 **시험 전에 고정**한다. 유효한 관측 1개를 소비하면 해당 요청은 끝난다.
2. **현재 frame의 신선도 초과만** 같은 anchor에서 다음 촬영을 허용한다. 모든 원본·거부 이유를 기록하고 직전 저장 barrier가 성공해야 다음 capture를 시작한다.
3. anchor 만료/외관·identity 손실/조회 실패/저장 실패·지연/중단/시간 역행은 즉시 종결하고 추가 capture0. 새 anchor 자동 갱신·HTTP 오류 자동 재시도·모터 실행 없음.
4. 소비 시100ms·anchor15초·저장250ms를 유지한다. 저장 작업을 억지로 취소해 deadline을 지킨 것처럼 표시하지 않는다. 예산을 넘겨 반환된 I/O는 초과 실패로 기록하고 새 촬영을 시작하지 않는다.
5. 시도 전체의 성공/실패/획득 실패, 모든 촬영 수, 요청→소비 및 요청→저장 종결 시간, 초과 횟수, p50/p95/최대와 실패 이유를 보고한다. anchor 획득 시간은 따로 기록하고 end-to-end 시간에서도 빠뜨리지 않는다. 성공 프레임만 분모로 삼지 않는다.

**다음 구현 때 사용할 제안값(아직 사용자 확정값·기존 합의가 아님):** anchor 확보 후 단일 요청 최대5회 촬영, 3초 운영 예산. 소규모 비구동 평가20시도에서 요청의80%(16/20) 이상이 예산 내 유효 소비와 저장을 마치면 제한 수집 준비를 검토한다. 이는 사용 편의의 탐색 기준이며 물리 안전성/일반화 보장이 아니다. anchor 확보 실패를 포함한 전체 성공률과 전체 대기 시간도 반드시 병기한다. 숫자는 구현 시작 시 예상 비용과 함께 한 번 고정하고, 결과를 본 뒤 통과를 위해 늘리거나 낮추지 않는다. 3초는 강제 I/O 취소 보장이 아니라 초과 실패를 포함해 집계할 운영 예산이다.

**개발 완료 기준:** 횟수·시간 경계, finalization/소비 직전 만료, 저장 지연·실패, 취소, 중복/역순, 마지막 budget에서 성공/거부, 종결 후 추가 capture0 테스트 통과; 원본/hash·terminal 검증; 독립 리뷰; 모터 명령0. 장치 가능 시 고정한 한 평가 묶음을 완료해 시도 단위 보고서를 남긴다. 장치 불가면 실측은 미검증으로 남기고 B를 계속한다.

**이 관문을 끝내는 기준:** 사용 가능 판정이면 관측 지연의 추가 최적화를 멈추고 제한 동작 수집 연결로 넘어간다. 미달이어도 이번 과제는 결과/병목 보고로 종료한다. 같은 미세 최적화를 자동으로 연장하지 말고, 측정 근거에 따른 수집 방식 변경의 범위·비용을 제시해 다음 결정을 받는다. 학습 코드 B를 계속 막지 않는다.

## 7. 병행 작업 B — Mac CPU 오프라인 학습·평가 기반

**산출물:** 검증된 action-transition manifest를 읽는 loader·특징/목표 정의·무변화 기준선과 작은 선형 모델·재현 가능한 평가 CLI. 기존 `learning/dataset.py`, `splits.py`, `schema.py`, `provenance.py`와 `tools/evaluate_policy_*`를 먼저 확인해 실제로 재사용 가능한 부분을 사용한다. 기존 규칙 정책 평가를 학습 dynamics 평가와 혼동하지 않는다.

예상 파일은 아직 없음: `learning/features.py`, `learning/models.py`, `tools/train_visual_dynamics.py`, `tools/evaluate_visual_dynamics.py`, 대응 테스트. 최소 선형 모델까지면 충분하며 MLP/대형 모델을 이번 완료 조건으로 추가하지 않는다.

완료 기준:

- manifest와 원본 provenance/hash·분할을 재검증한다. frame/episode/이미지/명령 누수 차단을 유지하고 train만으로 정규화·모델 fit을 한다. test를 보고 모델/하이퍼파라미터를 고르지 않는다.
- 실제로 관측 가능한 시각 변화·M4 변화·명령/실제 출력 중 무엇을 입력/목표로 쓸지 schema에 맞춰 명시한다. 존재하지 않는 전 관절 정답을 만들지 않는다.
- 같은 고정 분할에서 무변화와 선형 기준선을 비교하고 seed·feature version·split/manifest hash·전처리·모델·평가 분모를 저장한다. 분할에 유효 데이터가 없으면 평가 불가를 표시한다.
- 합성 fixture는 별도 smoke에서만 실행하며 실물 학습/평가 데이터에 섞지 않는다. 현재 적격 실물 데이터가0이므로 production 학습은 명시적으로 거부해야 한다. 합성 수치로 물리 성능 향상을 주장하지 않는다.
- 데이터 누수·합성 혼입·빈 데이터·잘못된 열/NaN·재현성을 검사하고 독립 리뷰 후 작업 단위로 커밋·푸시한다.

A와 B는 독립적으로 검증·되돌릴 수 있는 커밋으로 나눈다. 둘 다 끝낸 뒤에도 새 최적화 목록을 추가하지 말고 실제 행동 수집에 필요한 최소 연결과 실물 관문을 정리한다.
