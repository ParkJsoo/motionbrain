# 실물 치수와 가상 팔의 보정

[문서 색인](README.md) · [프로젝트](../README.md) · [화면 실행](robot-visualization.md)

FK·IK·URDF가 같은 계산 결과를 내는 것과 실제 팔에 맞는 것은 별개다. 초기 치수는 실측으로 순서대로 교체한다. 줄자 판독으로 M4 어깨→M3 팔꿈치 **90mm**, M3 팔꿈치→M2 손목 **약 110mm**, 탁자→M4 어깨 축 높이 **70mm**를 반영했다. 높이는 약 70~75mm라는 판독에서 선택한 모델 기준값이다. 손목 축→집게 끝은 **전체 110mm**이며 중간 구간 45mm를 더하지 않는다. 내부 고정 몸체 원점을 45mm 앞에 두고 나머지 65mm를 `tool0`까지 배분했지만, 이 분할은 독립적으로 보정한 두 길이가 아닌 미측정 프레임 배치다. `tool0`는 측정 당시 끝점 거리를 사용하는 고정 가상 도구 기준이며, 집게 벌어짐에 따라 움직이는 실제 손가락 끝 자체가 아니다.

cm 단위 육안 판독으로 mm 단위 오차는 미확정이다. 손목은 기어박스 케이스 중심과 실제 외부 힌지축을 구분해야 한다. 베이스 수평 편심은 조립도에 근거한 0mm 가정이다. 현재 모델을 충돌 여유·도달 가능성·실물 명령의 근거로 사용하지 않는다.

## 제조사 설명서로 확인되는 범위

OWI-535 **Robotic Arm Edge Assembly and Instruction Manual**의 인쇄 1·31·32쪽을 기준으로 한다. 해당 39쪽 PDF에서는 6·36·37쪽이다.

| 항목 | 제조사 표기 | 보정에서의 의미 |
| --- | --- | --- |
| 수평 작업 반경 / 최대 높이 | 12.6in / 15in = 약 320mm / 381mm | 전체 크기의 타당성 확인용. 개별 링크 길이가 아님 |
| 손목 M2 / 팔꿈치 M3 | 120° / 300° | 가동 범위의 총량. 현재 조립체의 영점·부호 있는 양 끝값은 미확정 |
| 어깨 M4 / 베이스 회전 M5 | 180° / 270° | 같은 이유로 URDF 제한값에 대칭 배분하지 않음 |
| 집게 벌어짐 | 0–1.77in ≈ 45mm | 개략 외형. 모터값→실제 벌어짐·접촉 위치 관계는 별도 측정 |
| 제품 무게 / 최대 인양 | 658g / 100g | 원제품 사양. 카메라·브래킷·센서·배선을 추가한 조립체의 질량·운용 한도로 전용하지 않음 |
| 외형 | 9in L × 6.3in W × 15in H | 그림의 L·W는 베이스 바닥 크기. 팔 링크 길이와 구분 |

설명서에는 관절 중심 간 치수, 질량 중심·관성, 전체 감속비, 센서 영점이 없다. 일부 부품표의 1:1 표시는 전체 조립도가 축척도라는 뜻이 아니다. 작업 반경 하나로 모든 길이를 같은 비율로 축소하거나, 스캔 그림의 픽셀을 실측값으로 확정하지 않는다. 끝단에서 안전 기어가 클릭하는 현상도 자동 홈 탐색 절차로 사용하지 않는다.

인쇄 14~16·32쪽의 조립 구조는 M5 수직 회전축 위에 M4 pitch 축을 놓는 배치와 일관된다. `shoulder_offset_m=0`은 이 조립도에서 추정한 교차축 가정이며 제조사가 명시한 치수나 실측값이 아니다. 수mm 편심·조립 공차는 후속 자세 오차로 확인한다.

Suthar 등의 [2016년 기구학 논문](https://ijra.iaescore.com/index.php/IJRA/article/view/1001)은 Table 1에 D-H 길이 `a`로 44·91·120·94mm를 제시한다. 44mm를 탁자면 기준 어깨 높이로 곧바로 전용할 수 없으며, 좌표계와 실제 관절축을 먼저 대응해야 한다. 이 논문의 검증은 두 소프트웨어의 변환행렬 비교다. 현재 장치의 치수·센서·실물 위치 정확도가 검증됐다는 근거가 아니다.

## 하나의 치수 원본과 파생물

기본 원본은 [`arm_geometry.json`](../ros2_ws/src/motionbrain_ros_bridge/motionbrain_ros_bridge/arm_geometry.json)이다. Python 패키지 resource로 설치되므로 소스 체크아웃이 없는 환경에서도 `ArmModel()`은 같은 기본값을 읽는다. 각 항목의 값·측정 여부·방법·불확실도·근거 해시·실물 구성 식별자를 함께 관리한다. `nominal`은 미측정, `measured`는 근거를 기록한 측정값이다. 측정 오차가 아직 정량화되지 않았으면 `uncertainty_m: null`로 남긴다. `measured`도 다중 자세에서 검증된 보정 정확도를 뜻하지 않는다. 전체 상태는 미측정 항목이 하나라도 있으면 `nominal`을 유지한다.

| 필드 | 정의 |
| --- | --- |
| `base_height_m` | 기준 바닥면에서 M4 어깨 회전축까지 높이. M5 모터 자체의 높이가 아님 |
| `shoulder_offset_m` | M5 수직 회전축에서 M4 축까지의 수평 방사 방향 편심. 0 허용 |
| `upper_arm_m` | M4 어깨 중심→M3 팔꿈치 중심 |
| `forearm_m` | M3 팔꿈치 중심→M2 손목 중심 |
| `wrist_m` / `tool_m` | 손목→고정 집게 몸체 원점 / 몸체 원점→고정 `tool0`의 축 방향 길이 |

현재 해석식은 yaw +Z, pitch −Y, 양의 pitch가 위쪽 상승각, 관절 원점 회전 0인 평면 사슬만 지원한다. 횡방향·높이 방향 링크 편심이나 추가 원점 회전이 필요하면 이 6개 값에 흡수하지 않고 좌표계와 FK·IK를 함께 확장해야 한다. 끝점 관측만으로는 `wrist_m`과 `tool_m`을 따로 식별할 수 없다. 중간 몸체 기준점을 정하거나 우선 두 길이의 합만 확인한다. 고정 `tool0`, 카메라에서 보이는 표면 마커, 집게 개방에 따라 달라지는 실제 접촉점을 혼동하지 않는다.

```bash
# 기본 원본과 체크인된 전체 팔 3개·M4 전용 2개 URDF 비교
python3 tools/calibrate_arm_geometry.py --check

# 수정한 로컬 프로필로 후보만 생성. 기존 소스·실행 중 화면은 덮어쓰지 않음
.local/venvs/visual-tools/bin/python tools/calibrate_arm_geometry.py \
  --profile .local/measurements/arm_geometry.json --output .local/geometry-candidate
```

새 `--profile`에 `measured` 항목이 있으면 기록한 해시와 일치하는 원본 파일을 `--evidence .local/measurements/raw.json` 등으로 함께 지정한다. 여러 원본은 옵션을 반복한다. 원본의 내용이 실제 측정으로서 타당한지는 별도 검토하며, 도구는 파일 해시 일치까지 확인한다. 배포된 기본 프로필을 재현하거나 `--check`로 비교할 때는 비공개 원본이 없어도 실행할 수 있고, 원본 파일을 재확인했다는 상태는 부여하지 않는다.

후보 폴더에는 프로필, 5개 URDF, MuJoCo `model.xml`, Gazebo `world.sdf`, 원본·생성물 해시와 미검증 상태를 담은 manifest가 생긴다. FK·IK 비교에서는 `ArmModel.from_profile(path)`를 명시한다. 도구는 센서 영점·모터 방향·출력 허용·제어 제한·학습 모델·카메라 좌표·질량·접촉을 자동 변경하지 않는다. 잘못된 단위·지원하지 않는 변환·비유한 값·근거 없는 측정 승격은 거부한다.

치수를 채택할 때는 원본과 파생 URDF를 같은 변경으로 검토한다. 기존 Gazebo/MuJoCo 파일은 자동 갱신되지 않으므로 새 URDF에서 다시 생성하고 Viewer를 새 모델로 열어야 한다. 소프트웨어 검사는 다른 치수의 시험 프로필에서도 FK·IK·URDF 위치가 맞는지, 제어 블록이 그대로인지 확인한다. 실제 보정 완료에는 독립적인 여러 자세의 관측과 오차 평가가 추가로 필요하다.

## 실제 보정의 순서

먼저 팔을 움직이지 않은 상태에서 회전축 중심·고정 도구 기준·기준 바닥을 정하고 길이를 확인한다. 다음으로 서로 다른 알려진 자세에서 관절 영점·방향과 카메라 좌표를 확인한다. M4 센서값은 센서 장착 보정과 ROS 관절 영점 변환을 구분한다. 다른 관절의 실측 피드백이 없으면 가상 슬라이더나 추정값임을 표시한다.

그 뒤 질량·하중·PWM별 반응·마찰·백래시를 식별하고, 마지막에 링크 충돌·양턱 접촉·파지·미끄러짐을 검증한다. 기하 치수 하나를 바꾼 것으로 Gazebo/MuJoCo의 임시 위치 구동기와 물리값까지 실제 로봇에 맞았다고 판단하지 않는다.

## 사진과 기존 치수로 근사 자세 맞추기

추가 각도계 없이도 측면 사진의 어깨·팔꿈치·외부 손목 힌지·집게 끝을 지정하고 기존 링크 길이와 비교할 수 있다. [`estimate_arm_photo_reference.py`](../tools/estimate_arm_photo_reference.py)는 이 수동 기준점에서 투영 각도와 길이 비율 오차를 계산한다. 사진 경로·해시·크기, 기준점, 사진에서 전방이 향하는 방향, 수평선 회전 가정과 치수 프로필·해시를 입력한다. 입력 형식은 도구의 `--help`와 [검사 예제](../tests/test_arm_photo_reference.py)를 참고한다.

```bash
python3 tools/estimate_arm_photo_reference.py \
  --input .local/photo-reference.json --output .local/photo-reference-result
```

현재 표시 자세는 측면 근사로 어깨 약 63°, 팔꿈치 상대각 약 −109°, 손목 상대각 약 32°를 사용한다. 베이스 yaw 0과 집게 각도는 보기용 가정이다. 상완·전완의 영상 길이 비율은 실측 90:110과 잘 맞지만 말단까지 같은 축척이 성립하는지는 별도로 확인해야 한다. 모든 구간의 독립 축척과 공통 축척 잔차를 남기며, 불일치를 없애려고 실측 길이를 자동 변경하지 않는다. mm 잔차는 약투영 가정 아래 비율 불일치를 환산한 값이며 실물 위치 정확도의 측정값이 아니다. 집게 끝으로 고른 표면점은 집게 벌어짐과 독립적인 고정 `tool0`와 같다고 보장하지 않는다.

이 계산은 팔이 거의 한 평면에 있고 카메라가 그 옆을 보는 약투영 가정이다. 원근·렌즈 왜곡·수평선 오차·기준점 오차가 남으며 여러 독립 자세에서 검증한 절대 관절각이 아니다. 줄자가 축과 다른 깊이에 있으면 영상에서 같은 높이로 보이는 눈금을 실제 축 높이로 곧바로 쓰지 않는다. 사진에서 한 자세를 맞춘 것으로 M4 센서의 영점·부호를 확정하거나 기존 장착 보정을 다시 적용하지 않는다. 카메라의 내부·외부 행렬도 식별하지 않는다. 기존 `camera_link`는 미보정 호환 프레임이고, 집게 위 카메라 외형의 위치가 실제 좌표 보정을 뜻하지 않는다.

접힌 자세를 표현하기 위해 **표시용 URDF만** 팔꿈치 범위를 nominal ±150°로 둔다. 제조사의 총 가동량 300°를 대칭 배치한 보기용 범위이며 실제 부호 있는 양 끝값이 아니다. 하드웨어·mock URDF와 FK/IK 제어 제한은 기존 ±90°를 유지한다. 따라서 사진 근사 자세가 제어 제한 위반으로 표시되는 것은 의도된 구분이다. 표시 모델의 범위를 실물 명령 허용에 사용하지 않는다.

## 다른 자세의 영상과 M4 센서 변화 대조

[`compare_arm_video_sensor.py`](../tools/compare_arm_video_sensor.py)는 기존 `motionbrain.m4_up_learning_short500.v1` 기록을 오프라인으로 대조한다. 새 장치 연결·명령 선택·모터 구동·재학습·업로드는 없다. 한 장에서 고른 절대각과 달리, 같은 구도에서 전후로 얼마나 회전했는지를 M4 센서 변화와 비교하는 개발용 진단이다.

첫 영상에서 분석자가 지정한 움직이는 부품 영역과 서로 다른 고정 배경 영역 두 개 이상을 사용한다. 특징점은 첫 영상에서만 선택하고 LK 왕복 추적·RANSAC으로 투영 회전을 계산한다. 특징점 수·분포·왕복 오차·강체 적합 잔차·축척·배경 이동을 검사하고 실패하면 각도를 반환하지 않는다. 임계값은 영상 품질용이며 물리 안전이나 각도 정확도의 보증이 아니다. 분석 도중 잃은 특징점을 다시 선택해 성공 처리하지 않는다.

입력 JSON의 `schema`는 `motionbrain.arm_motion_comparison.plan.v1`이다. `regions`에는 `imageSize`, `movingPolygon`, `backgroundPolygons`, `forwardImageSign`을 둔다. `referenceView`에는 `contextSha256`, `controllerBootId`, `configurationSha256`, `videoMirrored`, `videoRotationAngle`을 지정해 서로 다른 관측 계약·부팅·카메라 설정이 자동 혼합되지 않게 한다. `cases`는 `.local` 아래 기록의 상대 `root`와 `resultSha256` 목록이다. `contextSha256`는 기존 `plan_digest(context)`의 정규 JSON 해시다. 실제 입력·영역 좌표·원본 영상은 비공개 자료로 보관한다.

```bash
python3 tools/compare_arm_video_sensor.py \
  --manifest .local/comparison-manifest.json --output .local/comparison-result \
  --series-stride 1
```

원본 결과·범위·프레임 수신 기록·영상·픽셀 해시를 검사하고, PNG 전후 영상이 해당 BGRA 원본의 실제 픽셀과 같은지도 확인한다. 연속 표본 역시 같은 기준 영상과 비교한다. `--series-stride 0`은 전후만 처리하고 양수는 원본 표본 간격이다. 출력은 새 `.local` 폴더에만 쓰며 탈락한 기록과 이유를 분모에 남긴다. 중간 프레임의 센서 근접값이 0.5초 이내에 없으면 미대응으로 남기며 보간하지 않는다. 전후 대조의 유효 여부와 중간 프레임의 품질·센서 대응 실패는 구분한다.

기존 같은 구도의 6개 기록을 탐색적으로 대조했다. 센서 변화가 큰 3건은 약 +1.41~+1.85°이고, 작은 출력의 대조 3건은 센서 변화가 0°였다. 전완 영역은 6건 모두 영상 품질 검사를 통과했고 움직인 3건의 증가 방향이 센서와 같았다. 그 3건에서 투영 변화와 센서 변화의 평균 절대 차이는 약 0.19°다. 상완을 직접 추적한 별도 영역은 5/6건을 통과했고, 나머지 1건은 배경 왕복 추적 부족으로 탈락했다. 통과한 동작 2건의 방향도 같았고 평균 절대 차이는 약 0.15°다. 움직이지 않은 3건의 최대 투영 변화는 두 영역 모두 약 0.007° 이하였지만, 이를 센서 분해능보다 높은 실물 각도 정확도로 해석하지 않는다.

두 영역은 같은 6개 원본을 재분석했으므로 독립 표본 12개가 아니다. 영역을 수동으로 선언한 개발 탐색이며 새로 고정한 평가·전체 자세 일반화·모델 성능 개선의 결과가 아니다. 일부 중간 프레임의 품질 탈락과 센서 시각 미대응도 보존했다. 원래 기록의 학습·평가 구분과 실패 이력은 바꾸지 않는다. 이 도구는 기존 HTTP 원장 전체를 재감사한 것이 아니며 `rawHttpReaudited=false`로 표시한다.

센서값은 호스트가 관측한 시각, 영상은 호스트 PTS를 사용한다. 가장 가까운 센서 관측을 찾았다는 사실이나 PTS 변환 경계가 광학 노출·센서 샘플의 정확한 동기화를 증명하지 않는다. 결과는 좁은 자세 범위의 투영 변화 일관성이며 정밀 M4 영점·방향·카메라 외부 좌표 보정이나 실물 제어 승인이 아니다.

## 촬영별 첫 프레임 기준 등록

`collect_supervised_actions.py`의 `--arm-reference-template`은 기존 단발 수집에 선택적으로 연결한다. 템플릿은 `motionbrain.arm_reference_template.v1` 형식이며 `imageSize`와 상완·전완의 `regions`를 담는다. 각 영역에는 `movingPolygon`, 고정 배경 두 곳 이상의 `backgroundPolygons`, `forwardImageSign`이 필요하다. 실제 영역 좌표는 해당 촬영 구도에서 정해 비공개 자료로 보관한다.

`prepare`에서 원본 템플릿 바이트의 SHA를 계획에 고정하고, `validate`·`run`에서도 같은 템플릿을 지정한다. 수집기는 카메라 준비 직후 같은 촬영의 **첫 프레임(frame0)만** 기준으로 등록한다. 원본 픽셀·시계·특징 품질과 프레임 호스트 PTS에서 **0.5초 이내**인 근접 센서 GET 관측을 검사해 등록한 뒤에야 기존 실행 경로로 진행한다. 이 시각 차이는 광학 노출·센서 샘플 동기화의 보증이 아니다. 등록이 실패하면 모터 명령 전에 미시작으로 남기며, 나중 프레임을 대신 고르지 않는다. 옵션 없는 기존 수집 경로는 그대로다.

촬영 재시작 사이에는 화면 배율·위치가 조금 달라질 수 있으므로 이전 촬영의 기준 프레임을 자동 재사용하지 않는다. 벽면의 미세 질감 대신 고정된 무늬를 선정한 뒤, 같은 촬영의 첫 프레임을 기준으로 약 10초·76프레임에서 품질 검사를 통과했다. 이는 해당 구도의 정지 관측이며 다른 촬영·모든 자세의 안정성을 보장하지 않는다.

```bash
python3 tools/compare_supervised_arm_video.py \
  --run .local/supervised-run --output .local/arm-comparison \
  --arm-reference-template .local/arm-reference-template.json \
  --expected-plan-sha256 '<plan-sha256>' \
  --expected-template-sha256 '<template-file-sha256>'
```

사후 대조는 실제 HTTP RUN·OFF 경계, 전체 출력 이력, 마지막 OFF·빈 큐, 등록 시각과 첫 쓰기 시각, 원본 프레임·센서·계획의 연결을 재검사한다. 사후 프레임은 검증된 정지 구간 안에서 OFF 후 3초 목표에 ±0.5초 이내인 근접 표본을 선택하고 실제 경과 시간을 남긴다. 과거 사전등록 없는 자료는 `--allow-offline-registration`을 명시한 경우만 재구성하며, 사전등록·고정 후 평가로 바꾸지 않는다. 출력은 영상 평면 변화와 센서의 사후 대조이며 실물 각도 정확도나 학습 성능의 검증은 아니다.

## 높이와 센서로 만드는 M4 근사 기준점

[`calibrate_arm_joint_reference.py`](../tools/calibrate_arm_joint_reference.py)는 같은 정지 구간의 전후 GET·사진·수직 높이를 묶어 **읽기 전용 근사 기준점 후보**를 만든다. M3 팔꿈치 축 높이 145mm, 기존 어깨 높이 70mm·상완 90mm를 사용하면 어깨 상승각은 `asin((145−70)/90) ≈ 56.44°`다. 팔꿈치가 어깨보다 앞쪽·위쪽에 있는 분기를 사진으로 확인한다. 이때 M4의 전후 보고값은 모두 192.83°였고, 같은 부팅·전축 OFF·빈 큐·출력 이력 불변을 확인했다.

입력은 `motionbrain.arm_joint_reference_input.v1` 형식의 JSON이다. 기하 프로필·높이 판독·전후 상태·사진·방향 대조 자료의 경로와 해시, 사진 기준점과 호스트 시각 구간을 지정한다. 사진은 전후 상태 조회 사이에 있어야 하며, 부팅·출력·센서 상태가 달라지면 거부한다. 형식 예제는 [검사 코드](../tests/test_arm_joint_reference.py)에 있다.

```bash
python3 tools/calibrate_arm_joint_reference.py \
  --input .local/joint-reference-input.json \
  --output .local/joint-reference-candidate
```

기준쌍은 `sRef=192.83°`, `qRef≈56.44°`이며, 기존 변환식 `q=qRef+sign·rad(angleDeg−sRef)`과 호환된다. `sensor_zero_deg`와 `ros_joint_zero_rad`에는 이 **기준쌍**을 넣는다. 수평 0° 자세의 센서값을 직접 측정한 것은 아니다. 입력 `angleDeg`에는 펌웨어의 장착 오프셋 −24.35°가 이미 적용돼 있으므로 다시 더하지 않는다. 증가 방향의 대응은 좁은 범위의 상대 변화에 근거한 잠정값으로 남긴다.

같은 사진의 어깨 투영각은 약 59.44°로, 높이 기준과 **약 −3.00° 차이**가 있다. 이 잔차를 없애려고 링크 길이나 장착 오프셋을 바꾸지 않는다. cm 단위 치수·높이 판독, 수동 축점, 약투영·수평선 가정의 오차는 정량화되지 않았다. 높이 입력의 상·하한이 같아도 오차 0이나 신뢰구간을 뜻하지 않는다.

결과는 `single_pose_coarse_read_only_anchor`이고 `enabled=false`, `controlEligible=false`다. 기존 ROS 피드백·목표 쓰기 설정·펌웨어·소프트 제한에는 자동 적용하지 않는다. M2·M3는 한 사진에서 추정한 정적 자세이며 센서 영점이 아니다. M1 개방과 M5 yaw도 미측정이다. 따라서 단일 근사 기준점을 얻은 것과 전체 관절의 정밀 영점 보정 완료를 구분한다.
