# M4 장치 목표 가드 준비 코어

[운영 안내](../OPERATIONS.md) · [문서 색인](README.md)

호스트가 HTTP로 각도를 관측하고 STOP을 요청하는 경로와 별도로, 장치에서 목표·센서·기한을 검사하는 경로를 준비한다. 현재 구현은 **순수 상태기계와 호스트 전송 계약**이다. 실제 장치의 정지 개선이나 모델 제어 성공을 검증한 결과는 아니다.

## 구현한 범위

- `src/control/m4_goal_guard.{h,cpp}`는 요청·시작·관측·종료·OFF 확인 상태를 관리한다. 기본 `MOTIONBRAIN_ENABLE_M4_GOAL_GUARD=0`에서는 요청을 받지 않는다.
- 상태기계가 반환하는 정지 결정은 향후 어댑터에 대한 요청이다. 이 코드만으로 센서를 읽거나 모터 출력을 차단하지 않는다.
- nonce는 부팅 내 고정 용량으로 보존한다. 사용한 nonce나 OFF가 확인되지 않은 종료 상태에서는 새 실행을 허용하지 않는다. 최초 OFF 확인은 뒤의 확인으로 덮어쓰지 않는다.
- `learning/m4_device_guard_transport.py`는 명시 요청에서만 사용할 준비 코드다. capability·정책·nonce·queue readback이 맞아야 단발 RUN을 요청하며, 응답 유실 시 재전송하지 않는다. 현재 펌웨어에서는 필요한 capability가 없어 guarded RUN 전에 거절된다.

준비 정책은 출력 UP 50%·DOWN 35%, 요청 기한 1,200ms, 관측 변화 한도 0.9°를 고정한다. 센서 최신성·검사 간격·OFF 확인 시간도 검사한다. 이 수치는 특정 준비 정책의 소프트웨어 계약이며, 모터 정격·하드 실시간 처리·관성까지 포함한 실제 정지거리를 보장하지 않는다.

## 아직 연결하지 않은 범위

실제 HTTP API와 queue readback, `MotionSequence`·AS5600·main loop·드라이버 hard OFF, 운전 중 통신과 정지 채널, 전용 펌웨어 환경은 미구현이다. 수집 actor·원본 감사·모델·전체 실행기 연결도 미완료다. 이 코어를 위한 새 펌웨어를 업로드하거나 실물을 구동하지 않았다.

운전 중 HTTP 조회를 하지 않는 호스트 계약만 준비했으며, 장치의 통신 지연 처리와 취소 의미는 실제 어댑터를 구현할 때 함께 검증해야 한다. 기존 짧은 동작 자료를 새 장치 가드 자료로 자동 전환하지 않는다. 원래 실패·불명확 결과와 원장 차단도 별도로 보존한다.

## 장치 없이 검사

```sh
python3 -m unittest tests.test_m4_goal_guard_native tests.test_m4_device_guard_transport
pio run -e esp32dev
```

네이티브 검사는 컴파일러가 없으면 건너뛴다. 순수 상태기계의 기본 비활성·명시 활성 경우와 모의 호스트 전송을 검사한다. 기본 펌웨어 빌드 통과는 실제 API 연결이나 배포 후보 생성을 뜻하지 않는다.
