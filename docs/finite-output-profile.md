# 장치가 완료까지 관리하는 유한 출력 프로파일 설계

**상태: 순수 실행부·모터 드라이버·서비스 제어권과 안전 전이 경계까지 오프라인 구현. 전역 실행 인스턴스·HTTP API·스케줄러 연결과 실물 동작은 아직 구현하거나 검증하지 않았다.** 기존 sequence·bounded pulse의 의미와 기본 비활성 상태를 바꾸지 않는다. 아래 예시의 PWM·기간·허용 지연은 수학적 설명이며 현장 실행 설정이 아니다.

## 목적과 변경 범위

요청 PWM·명령 기간만 같아도 실제 출력은 램프 갱신과 호스트 STOP 처리 시점에 따라 달라질 수 있다. 정상 동작의 상승·유지·하강·마지막 0 출력을 장치가 하나의 유한 일정으로 관리하고, 호스트의 정상 종료 STOP에 대한 의존을 없애는 것이 목적이다. 호스트 STOP·DISARM·기존 안전 정지는 계속 중단 수단이다. 출력 재현성 개선이나 각도 예측 성능 향상은 아직 입증하지 않았다.

첫 설계 범위는 한 모터·한 방향, 시작 전 출력 0, 마지막 출력 0이다. 동시 모터 제어·프로파일 내 방향 전환·자동 반복·실패 명령 재전송·자동 ARM은 제외한다. M2부터 검토하더라도 기존 양수 전용 pilot 허용이 양방향 실물 실행 허용으로 확대되는 것은 아니다.

기존 `durationMs`를 새 전체 출력 기간으로 재해석하지 않는다. 새 `actionContractVersion`과 `profileVersion`을 사용하고, 기존 자료·도구에는 명시적 호환 처리가 없으면 거부하게 한다. 기존 450/550ms·PWM ±160과 새 프로파일의 같은 숫자는 같은 동작을 뜻하지 않는다.

## 실행 전 고정할 계약

외부 요청은 검토된 프로파일 목록의 ID를 선택한다. 첫 버전에서 임의 점열·무제한 유지시간을 받지 않는다. 장치는 목록에서 전체 정수 점열을 재구성하고 호스트의 정규화 결과와 일치하는지 검사한다. 지원하지 않는 버전·알 수 없는 필드·범위 초과·중복 시간·비정수 값은 조용히 보정하지 않고 거부한다.

| 항목 | 의미 |
| --- | --- |
| `actionContractVersion`, `profileVersion`, `catalogHash` | 동작 의미·프로파일 생성 규칙·허용 목록을 식별한다. |
| `bootId`, `commandId` | 같은 부팅에서 한 논리적 요청을 식별한다. 새 ID로 실패 요청을 포장하지 않는다. |
| `motor`, `direction`, `profileId` | 한 모터·한 부호와 허용 프로파일을 고정한다. |
| `points` | 예정 시작에 대한 정수 `offsetMs`와 실제 적용할 부호 PWM의 목록이다. 마지막 PWM은 0이며 시간은 엄격히 증가한다. |
| `nominalEndOffsetMs`, `startLeadMs` | 마지막 예정 0 시각과 실행 수락부터 예정 시작까지의 준비 기간이다. |
| `timingPolicyVersion`, `maxLatenessMs`, `offConfirmWindowMs` | 각 출력 쓰기의 허용 지연, 실패 정책, 종료 결정 뒤 유한 OFF 확인 기간이다. 장치가 승인한 정책으로 고정하며 요청자가 늘리지 못한다. |
| `canonicalProfileHash` | 위 실행 의미 전체를 정규화한 해시다. 모터·부호·점열·시간 정책까지 포함한다. |

정규화는 고정 필드 순서·정수 표현·UTF-8·고정 직렬화 규칙을 버전으로 정의하고, 호스트와 장치의 공통 시험 벡터로 검증한다. JSON 문자열의 우연한 순서나 표시용 실수 반올림에 의존하지 않는다. ID·부팅·소유권·예약 정보를 포함한 전체 요청 지문은 프로파일 해시와 별도로 보존한다. 해시는 무결성·동일성 비교 수단이며 인증을 대신하지 않는다.

## 시간 의미와 예측 가능한 범위

`preparedAt`(출력 없는 예약), `executeAcceptedAt`, `plannedStartAt`, `firstNonzeroWriteAt`, `plannedOffAt`, `offWriteAt`, `offConfirmedAt`, `hostOffReceiptAt`를 구분한다. 장치 시각과 호스트 시각은 직접 빼지 않는다.

`plannedStartAt = executeAcceptedAt + startLeadMs`를 수락 순간에 고정한다. 첫 쓰기가 늦어져도 기준을 실제 첫 쓰기로 옮기지 않는다. 예정 오프셋이 `s[k]`, 실제 쓰기가 `a[k]`, 허용 지연이 `J`라면 정상 실행은 모든 점에서 다음을 만족해야 한다.

```text
plannedStartAt + s[k] <= a[k] <= plannedStartAt + s[k] + J
0 <= J < 가장 짧은 점 사이 간격
plannedOffAt = plannedStartAt + nominalEndOffsetMs
```

출력 직전 실제 장치 시각을 다시 확인하며, 검사부터 쓰기까지의 지연도 계측 대상이다. 최종 판정은 실제 드라이버 쓰기 기록으로 하며 허용 경계와 같으면 통과, 초과하면 실패다. OFF 뒤 확인이 늦은 것과 OFF 쓰기 자체가 늦은 것을 별도로 기록한다. 허용 마지막 OFF 시각은 `plannedOffAt + J`이며, 별도 물리적 차단 장치의 한도와 같은 의미가 아니다. 추가 차단의 시각 정책이 정상적으로 허용한 마지막 OFF와 충돌하지 않는지도 검토해야 한다. `J`·준비 기간·스케줄러의 최악 지연은 아직 확정하지 않았으므로 활성화 가능한 프로파일 목록도 아직 없다.

지연된 비영 이벤트를 건너뛰거나 여러 단계를 몰아서 실행하지 않는다. 허용 시각을 놓쳤으면 추가 비영 출력 없이 실패 처리와 OFF를 시도한다. 마지막 OFF가 늦었어도 반드시 OFF부터 시도하고 시간 실패로 남긴다. 이미 접수된 안전 정지·취소, 소유권 검증, 시간 실패·종료 판단이 정상 비영 출력보다 앞선다.

단일 장치의 짧은 시간차는 wrap을 고려한 부호 없는 경과시간으로 계산한다. 프로파일·예약 유효기간·비교 구간은 모두 `2^31ms` 미만으로 제한하고, `now >= start + offset` 같은 직접 비교를 사용하지 않는다. 다른 부팅의 시각을 이어 붙이지 않는다. 시계 연속성을 확인할 수 없는 장기 정체·재부팅은 정상 완료가 아니다.

### 수학적 예시: 예정 출력과 실제 출력의 구분

기존 램프의 단위인 PWM 10, 간격 50ms를 설명용 점열에 사용한다. `N`단계로 최대값 `P=10N`까지 올라간 뒤 같은 단위로 0까지 내려가며 최대값에서 추가로 `H`ms 유지한다. 최초 PWM 10의 예정 오프셋은 0이다.

```text
예정 전체 기간 T = (2N - 1) × 50 + H  [ms]
예정 절대 PWM 적분 A = 0.5 × N² + P × H / 1000  [PWM·s]
```

`N=6, H=0`이면 점열은 `10,20,30,40,50,60,50,40,30,20,10,0`, 예정 기간 550ms, 예정 적분 18.00 PWM·s다. 이는 기존 요청 PWM 160·명령 기간 550ms의 대체 설정이 아니다.

모든 쓰기가 일찍 실행되지 않고 각각 `0..J`만큼 늦으며 점 순서가 보존되는 **정상 조건에서만**, 이 예시의 활성 기간은 `T-J .. T+J`, 적분은 `A-PJ/1000 .. A+PJ/1000` 안에 있다. 설명용 `J=10ms`라면 540~560ms와 17.40~18.60 PWM·s다. 10ms를 실물 허용값으로 선택했다는 뜻이 아니다.

시작·종료·중간 지연을 실행 전에는 알 수 없으므로 이 값은 허용 범위이지 실제 파형 예측값이 아니다. 실패·CPU 정체·전원 이상에는 이 수학적 범위를 적용하지 않는다. PWM 적분은 에너지·토크·이동각이 아니며, 같은 적분도 파형·마찰·자세에 따라 다른 결과를 낼 수 있다.

## 수락·소유권·취소 프로토콜

제안은 **출력 없는 예약 후 한 번 실행**하는 두 단계다. 기존 API에 구현됐다는 뜻이 아니다. 단계가 하나 늘지만, 아직 도착하지 않은 실행 요청의 취소와 오래된 최초 요청을 장치에서 차단할 수 있는 경계를 만든다.

1. 호스트는 현재 부팅·소유권 세대와 프로파일 목록을 읽고 프로파일·요청 지문을 저널에 고정한다. 장치는 명령 ID와 전체 계약을 검증한 뒤 출력 없이 기록과 증거 공간을 예약한다. 동시에 하나만 예약하며 실행 큐는 없다. 예약 응답 뒤 실행 직전에 사전 관측 영수증과 예측 입력·출력을 고정한다. 예측과 정답의 사전 상태는 아래 학습 계약에 따라 같은 영수증을 사용한다.
2. 예약 응답에는 장치가 발급한 일회성 실행 토큰을 담는다. 토큰은 부팅·ID·계약 해시·소유권 세대·장치 기준 유효기간에 결합된다. 기록은 토큰 발급보다 먼저 남긴다. 토큰은 기존 인증을 대체하지 않으며 공개 로그에 남기지 않는다.
3. 실행 요청은 해당 예약·토큰·세대·만료·안전·출력 0 상태를 원자적으로 재검증한다. 토큰을 소모하고 시작 기준과 출력 소유권을 고정한 뒤에만 실행할 수 있다. 수락 응답 유실은 미실행 증거가 아니다.
4. 예약 취소·만료·완료·소유권 해제 및 DISARM·안전 정지·소유권 변경은 이전 세대를 무효화한다. 미등록 ID 취소는 `idle`이며 요청한 세대가 현재 세대일 때만 세대를 증가시키는 취소 경계를 남긴다. 다른 ID가 예약·실행·관측 소유권을 가진 상태에서는 거부하며 그 동작을 암묵적으로 취소하지 않는다. 해당 소유권 해제 시 세대가 바뀌므로 대기하던 이전 세대 예약은 거부된다.
5. 동일 ID·동일 전체 계약은 저장된 상태를 반환하며 출력 호출을 반복하지 않는다. 같은 ID·다른 계약은 충돌이다. 만료·취소·완료된 기록도 부팅 중 삭제하지 않는다. 레지스트리 포화는 신규 예약 거부이며 자동 재부팅·삭제로 우회하지 않는다.
6. 호스트는 예약·실행 실패나 응답 유실 후 출력 요청을 자동 재전송하지 않는다. 조회·취소·증거 확인으로 마감한다. 부팅 변경·기록 부재·토큰 유실을 새 ID 실행의 근거로 삼지 않는다.

`prepare(expectedEpoch=E)`는 완전히 idle이며 현재 세대가 E일 때만 수락한다. 미등록 취소도 인증·형식·현재 부팅 검증을 거친다. 이미 종료된 ID의 중복 요청·늦은 취소는 원기록만 반환하며 출력과 세대를 바꾸지 않는다. 현재 출력을 끊는 전역 안전 STOP은 이 과거 ID 조회 의미와 별도다. 단순 조회는 토큰을 공개하거나 발급하거나 만료를 연장하지 않는다. 모든 변경 요청은 기존 인증을 요구한다.

예약 만료 정리 작업이 늦었더라도 실행 수락 지점에서 장치 시각으로 만료를 검사하며, 만료 시각과 같거나 이후면 실행을 거부한다. 실행 시작 전에 안전 조건이 달라지면 예약 당시 통과했더라도 거부한다. 예약 취소와 실행 수락의 순서를 직렬화하여 먼저 확정된 사건이 결과를 결정하게 한다. 세대의 표현 범위를 소진하면 조용히 wrap해 재사용하지 않고 신규 예약을 차단한다.

## 출력 소유권과 스케줄러

비영 PWM을 쓸 수 있는 주체는 한 곳이어야 한다. 프로파일 소유권에는 부팅·명령·세대 식별자가 있으며 모든 쓰기 직전에 소유권과 종료 표시를 검사한다. 기존 램프·시퀀스·수동 HTTP·serial·teleop·각도 제어기가 우회해서 쓸 수 없어야 한다. 정상 프로파일 쓰기는 기존 `setSpeed()` 램프를 두 번 거치지 않는 검증된 드라이버 경계를 사용해야 한다.

취소·종료는 먼저 비영 이벤트를 무효화하고 목표·현재 출력·대기 이벤트를 정리한 뒤 OFF를 적용한다. 늦게 깨어난 callback은 오래된 세대로 출력을 다시 켜지 못한다. `actionOrdinal`·드라이버 상태·출력 로그·완료 기록도 같은 직렬화 정책 안에 둔다. 함수 공개 범위만 바꾸어 다중 작업에서 호출하는 방식은 허용하지 않는다.

동일 실행 안에서도 `nextEventIndex`는 단조 증가해야 한다. 사건의 소유권·인덱스·시간 검증, 실제 쓰기, 소비 표시를 원자적으로 처리한다. 이미 소비한 인덱스의 callback은 비영 쓰기 없이 무시하고 중복 사실을 제한된 진단에 남긴다. 다음 인덱스를 건너뛰는 이벤트는 실패·OFF 처리한다. `k → k+1 → 늦은 k` 순서가 같은 세대라는 이유만으로 과거 PWM을 다시 적용해서는 안 된다.

실행 중 일반 동작 요청은 거부한다. 명시적인 수동 개입은 먼저 프로파일을 중단하고 소유권과 세대를 바꾸는 별도 사건이며, 자동으로 이어서 실행하지 않는다. 안전 정지는 언제나 우선한다. 정상 완료 후에도 사후 관측이 끝날 때까지 출력 금지 상태를 유지한다. 관측 중 다른 출력이 발생하면 침범으로 기록하고 해당 측정을 부적격으로 처리한다. 호스트가 사라졌다고 자동으로 소유권을 풀어 새 동작을 시작하지 않는다.

완료 또는 부분 실행 뒤 OFF가 확인되면 실행 세대를 폐기하고 같은 명령에 새 관측 세대(`observationGeneration`)를 부여한다. 관측 종료 확인은 인증된 별도 요청으로 `bootId + commandId + observationGeneration`을 지정한다. 현재 관측 소유자와 정확히 일치할 때만 원자적으로 해제하고 세대를 증가시킨다. 이미 해제된 과거 명령의 중복 확인은 저장된 결과만 반환하며 현재 소유권에 영향이 없다. 관측 완료 확인은 영상 품질이나 학습 적격 판정 자체를 뜻하지 않는다. 호스트 소실 시 출력 금지를 유지하며, 명시적 복구는 해당 관측을 중단으로 기록하고 현재 OFF·소유권을 확인한 뒤에만 해제한다. 결과 불명으로 부팅 내 차단된 실행을 이 관측 해제 경로로 우회하지 못한다.

새 스케줄러는 HTTP 응답 직렬화·카메라·파일 저장·가변 길이 로그를 수행하지 않는 실행 경로가 후보이다. 공유 잠금·인터럽트 지연·우선순위 역전·다른 모터의 쓰기까지 측정해야 하며, 별도 작업을 만들었다는 사실만으로 정시 실행이 보장되지는 않는다. 구체적인 RTOS/타이머 API와 우선순위는 이 문서에서 확정하지 않는다.

같은 루프에서 늦게 발견해 OFF하는 보장과, 루프/CPU가 멎어도 기한 내 차단하는 보장은 다르다. 후자는 독립 차단 경로와 실물 증거가 필요하다. 소프트웨어의 `outputOff`도 드라이버 상태 확인이며 전기적 출력·관절 정지 실측이 아니다.

## 상태와 증거

| 상태 | 조건 | 이후 처리 |
| --- | --- | --- |
| 예약됨 | 검증·ID·증거 공간 예약, 출력 없음 | 유효한 실행 토큰 한 번만 수락 |
| 실행 중 | 고정된 시작 기준·일정·소유권으로 출력 | 조회가 실행을 진행시키거나 기한을 연장하지 않음 |
| 정지 확인 중 | 완료 예정·취소·실패로 비영 이벤트 무효화 | 무조건 OFF 시도, 신규 동작 차단 |
| 정상 완료 | 모든 이벤트 시간 정책 충족, 마지막 0 쓰기와 소프트웨어 OFF 확인 | 사후 관측용 출력 금지 유지 |
| 취소/만료/실패 | 각 사유를 보존하고 소프트웨어 OFF 확인 | 정상 완료로 승격 금지, 새 실행 자동 시작 금지 |
| 결과 불명 | OFF 또는 실행 결과를 확정할 수 없음 | 부팅 내 실행 차단 유지, 후속 확인은 별도 기록 |

`controlOutcome`, `timingConformant`, `softwareOffConfirmed`, `traceComplete`, `measurementEligible`는 별도 필드다. OFF 확인이 성공했다고 정상 완료·파형 보존·영상 정착이 모두 성공한 것은 아니다. 전기적 OFF·기계적 정착·목표 도달은 별도 실측이 없으면 미확인으로 둔다.

최초 종료 결정·사유·시각은 불변이다. 첫 OFF 시도, 후속 OFF 시도, 후속 확인 시각은 따로 보존한다. 나중에 OFF를 확인해도 최초 결과 불명이나 시간 실패를 정상 완료로 바꾸지 않는다. 완료와 취소가 경합하면 직렬화 지점에서 먼저 확정된 결과를 보존한다. 종료된 ID를 지정한 늦은 취소는 원기록만 반환한다. 현재 출력을 끊는 별도의 전역 안전 STOP은 과거 결과를 변경하지 않는 새 사건으로 기록한다. A가 완료된 뒤 B 실행 중 도착한 `cancel(A)`가 B를 끄면 안 된다.

정지 확인 중 상태에는 최초 종료 결정부터 장치 기준 `offConfirmWindowMs`라는 유한 기한을 둔다. 기한 안에 확인되지 않으면 결과 불명과 부팅 내 실행 차단을 확정한다. 최초 확인 실패의 증거는 유지하고, 이후 확인 성공도 정상 완료로 승격시키지 않는다. 이 기한은 사후 확인·판정의 한도이며 CPU 정체 중 실제 차단을 보장하는 한도가 아니다. 확인 횟수·후속 진단 기록량도 버전 정책으로 제한한다. 후속 OFF 시도는 고정 크기 요약·포화 카운터 등으로 분리하고, 로그 공간이 부족해도 안전 OFF 시도 자체를 막지 않는다. 기한과 기록 한도가 미정인 구현은 활성화하지 않는다.

증거는 명령별 예정 점열·실제 모든 쓰기·부팅·명령 귀속·연속 순번·시계·실제 0 경계를 보존한다. 정상 이벤트와 중단·중복 OFF를 포함한 최악 예산을 예약 때 확보해야 한다. 가용 메모리 안에 들어오지 않는 프로파일은 거부한다. 무제한 반복 진단 로그는 실행 경로에 저장하지 않는다.

기존 링 조회를 보존하더라도 학습용 증거를 그 링 하나에 의존시키지 않는다. 명령별 고정 공간·불변 종료 요약·조회 무결성 검증을 설계한다. 증거 손실은 OFF를 방해하지 않으며, 안전하게 멈췄더라도 `traceComplete=false`로 남긴다. 누락 파형 보간으로 적격 자료를 만들지 않는다. 최종 보존 방식과 메모리 예산이 정해지기 전에는 기능을 활성화하지 않는다.

## 학습·영상 계측 계약

행동 계약·관측 계약·특징 순서/버전·데이터 형식을 각각 식별한다. 실행 전 입력은 이전 상태·속도, 요청 방향, 프로파일 ID/버전/해시, 예정 점열에서 계산한 최대 PWM·기간·적분 등으로 한정한다. 이전 동작 이력은 현재 실행 요청 전 확보한 기록만 사용할 수 있으며, 누락 여부·경과시간도 남긴다. 예약 대기로 이전 관측이 낡을 수 있으므로 관측 나이 한도와 실행 전 재검사도 계약에 포함해야 한다. 한도 초과 시 새 입력으로 기존 요청을 조용히 바꾸지 않고 예약을 취소한다. 미리 알 수 있다는 것이 예측에 유용함을 입증하지는 않으므로 입력 추가는 제한된 후보와 별도 개발 평가로 검토한다.

실제 최대 PWM·활성 기간·적분·각 이벤트 지연·취소·실제 OFF 시각은 사후 정보다. 정상 동작만 남았다는 사실도 실행 전 입력으로 쓰지 않는다. 실행 전 예측 영수증은 출력 요청 전에 저장하고 모델·입력·프로파일의 해시를 묶는다. 결과를 본 뒤 예정 파형이나 입력을 수정하지 않는다.

기존 17개는 동일 development 그룹의 기존 행동 계약이다. [기존 학습·고정 모델](supervised-action-collection.md)은 보존하며 새 프로파일 자료를 기존 로더에 같은 행 형태로 넣지 않는다. 기존 모델을 새 방식에 적용한다면 계약이 달라진 참고 비교로만 표시한다. 새 방식의 독립 시험 모델로 승격하지 않는다. 과거 명령 시작+4초 계약의 32개·MAE 0.665°도 혼합하지 않는다.

사전 관측은 예약 응답 뒤 실행 요청 전에 닫힌 영상 창으로 확정한다. 영수증에는 사용한 프레임 ID/PTS·호스트 가용 시각·계측 설정·산출 상태/속도·해시를 담는다. **예측 입력의 사전 상태와 정답 변화량에서 빼는 사전 상태는 반드시 같은 영수증을 참조한다.** 예약 전 관측으로 예측하고 실행 직전의 다른 창으로 정답을 만드는 조합은 거부한다. 기존 RUN 전송 기준 −0.75~−0.10초 창을 그대로 재계산하지 않으며, 새 사전 창 앵커·폭·품질·나이 정책을 별도 관측 계약으로 고정한다. 실행 전에 특징을 산출하는 경로는 아직 구현·검증 전이다. 저장 영상에서 나중에 계산한 값을 실행 전 실시간 예측으로 표현하지 않는다.

사후 창은 기존의 호스트 OFF 확인 뒤 2.25~3초를 유지하는 후보로 둔다. 새 API의 OFF 확인 응답이 동일한 기준을 제공하는지는 통합 검증해야 한다. 이를 장치 실제 OFF 기준으로 옮기면 시계 매핑과 라벨 계약을 별도로 버전 관리한다. 고정 대기시간은 기계적 정착 보장이 아니므로 프레임 수·간격·안정성·다른 동작 침범 검사도 유지한다. 부분 실행 후 취소된 동작도 관측창 침범 검사에서 빠지지 않아야 한다.

평가는 먼저 새 계약의 개발자료에서 제한된 모델과 기준선을 정하고, 측정·프로파일·입력·모델을 고정한 뒤 별도 그룹을 보류한다. 같은 촬영 그룹을 나눠 독립 시험이라고 하지 않는다. 전체 시도에서 예약 거부·미전송·미시작·부분 실행·취소·시간 실패·결과 불명·증거 누락·측정 제외·적격 수를 보고한다. 정상 적격 자료의 각도 오차는 정상 실행 조건부 성능으로 표시하고 전체 시도의 실행 신뢰도와 함께 보고하며, 실패를 빼서 개선처럼 보이게 하지 않는다. 정상 출력·유효 관측인데 움직임이 작거나 0인 자료도 포함한다. 부분 실행 후 취소·시간 실패의 출력과 관측이 온전하면 정상 학습에서는 제외하되 진단 자료로 보존한다.

## 구현 전 반례와 합격 기준

| 반례 | 요구되는 결과 |
| --- | --- |
| 같은 ID/계약을 중복 수신, 응답 유실 | 출력은 한 번 이하, 기존 기록 조회; 자동 재전송 없음 |
| 같은 ID의 점열·부호·시간 정책 변경 | 충돌, 추가 출력 없음 |
| 취소 후 늦은 최초 예약/실행 도착 | 오래된 세대·취소 토큰 거부, 출력 없음 |
| 예약 뒤 DISARM·안전 상태 변화·부팅 변경 | 실행 거부, 자동 ARM·새 ID 재시도 없음 |
| 예약 만료와 실행 수락 경합 | 직렬화된 한 결과, 만료된 토큰의 출력 없음 |
| 레지스트리/증거 공간 부족 | 출력 전 거부, 자동 삭제·재부팅 없음 |

| 마지막 OFF 시각과 비영 갱신 경합 | 종료 판단 우선, 추가 비영 출력 없음 |
| 취소 뒤 지연 callback | 종료된 세대의 비영 쓰기 없음 |
| 같은 실행의 중복·역순 callback | 소비한 이벤트 재출력 없음, 다음 인덱스 건너뛰기는 실패·OFF |
| OFF 확인 실패 후 후속 확인 성공 | 최초 결과 불명 유지, 후속 증거 별도 보존 |
| 출력 링 유실·순번 누락·귀속 혼합 | 실행 상태와 별도로 증거 불완전, 학습 부적격 |
| 완료 뒤 사후 영상 창 중 다른 출력 | 관측 침범 기록, 측정 부적격 |
| 과거 명령의 늦은 관측 해제·중복 해제 | 현재 관측 세대에 영향 없음, 과거 기록만 반환 |
| OFF 확인이 끝내 오지 않음 | 유한 확인 기한 후 결과 불명·실행 차단, 진단 기록 무한 증가 없음 |
| 시간 wrap·다른 부팅 시각 혼합 | wrap 경계 계산 검증, 부팅 혼합 거부 |
| 허용 지연 초과·공유 잠금 정체·CPU 정체 | 실패/OFF 경로 및 보장 범위 구분; 미측정 정시 차단 주장 금지 |
| 실제 출력 특징을 실행 전 입력으로 전달 | 입력 계약 검사에서 거부 |
| 예측 입력과 정답이 서로 다른 사전 영상 창 사용 | 영수증·해시 동일성 검사에서 거부 |
| 기존 17개 또는 옛 32개와 계약 혼합 | 데이터 로더·평가에서 거부 |

정상 조건뿐 아니라 각 사건의 전후 순서·같은 시각·최종 출력 직전 경계를 검증한다. 소프트웨어 모형, 실제 드라이버를 연결한 native 검증, 펌웨어 빌드, 실물 시각·차단 검증의 결과를 구분한다. 오프라인 통과만으로 현장 실행 가능 상태가 되지 않는다.

## 다음 구현 단위와 미확정 조건

### 순수 오프라인 실행부

[계약 모듈](../src/control/finite_profile_contract.h)과 [실행부](../src/control/finite_profile_executor.h)는 Arduino·HTTP·모터 드라이버에 연결되지 않는 C++11 코드다. `MOTIONBRAIN_ENABLE_FINITE_PROFILE_CORE`는 기본 0이며, 네이티브 테스트에서만 1로 컴파일하고 가상 시계·가상 출력 포트를 제공한다. 이 플래그를 켜는 것만으로 실물 기능이 생기지는 않으며 운영용 플래그나 실행 예시로 사용하지 않는다.

계약 모듈은 버전 1·M2·한 방향·최대 32개 점과 유한 기간을 구조적으로 검증한다. 코드의 PWM 범위와 10,000ms 같은 상한은 저장공간·계산을 제한하기 위한 것으로 승인된 실물 범위가 아니다. 검토된 실물 프로파일 목록은 여전히 없다. 실행부는 호출자가 제공한 신뢰된 목록을 복사하고 요청의 전체 프로파일과 비교하므로, 요청자가 해시만 일치시켜 다른 점열을 실행할 수 없다.

`canonicalProfile()`은 고정 ASCII/UTF-8 필드 순서·정수 십진수·LF로 정규화된 **해시 입력 바이트**를 만든다. SHA-256 계산·목록 배포·네트워크 파싱은 이 실행부에 포함하지 않는다. `catalogHash`는 신뢰된 목록에서 제공하는 식별값으로 형식과 일치를 검사하며 목록 자체의 해시를 계산하지 않는다. 향후 목록 생성 규칙은 해시 필드 자체를 제외한 원문을 명시해 자기 참조를 피해야 한다. 미사용 점 배열의 뒤쪽은 실행 점열과 정규화에 포함하지 않는다.

포트는 실제 쓰기 시각, 소프트웨어 OFF 확인의 대기·확인·실패 구분, 일회성 토큰 발급을 제공한다. 과거 OFF 확인을 현재 출력 상태로 대신하지 않으며 쓰기·확인 시각의 일관성을 검사한다. 자동 OFF 확인은 유한 시간·횟수로 제한하지만, 결과 불명 뒤 명시적 OFF 재시도는 진단 기록 한도로 막지 않는다. 최초 종료·확인과 후속 재시도의 기록을 구분하고 결과 불명 차단은 유지한다.

실제 난수·인증·동시성 잠금·실물 피드백을 제공하는 어댑터는 없다. 모든 실행부 호출은 외부에서 직렬화해야 하며 포트는 실행부를 재진입 호출하면 안 된다. 안전 상태 변화는 호출 시점에 관측한 것만 알 수 있으므로, 후속 어댑터는 DISARM·소유권 변경 등의 사건도 누락 없이 전달해야 한다. 가상 시계에서 사건 순서를 검증하는 것과 실제 다중 작업 환경의 원자성을 검증하는 것은 다르다.

재현 가능한 오프라인 테스트 명령:

```sh
python3 -m unittest discover -s tests -p 'test_finite_profile_native.py'
```

테스트는 실제 계약·실행부 소스를 일반 C++ 컴파일러로 빌드한다. 정상 완료뿐 아니라 예약 만료, ID·세대·토큰 불일치, 취소, 실제 쓰기 지연, 이벤트 중복·역순, OFF 확인 실패, 관측 소유권 해제, 시계 wrap 및 기본 비활성 빌드를 다룬다. 장치 연결·펌웨어 업로드·촬영·학습은 포함하지 않는다. 명령별 파형과 종료 기록의 실물 수집, 호스트 저널, 사전 관측 영수증은 후속 통합 범위다.

### 모터 드라이버 연결 경계

[드라이버 연결부](../src/control/finite_profile_driver_bridge.h)는 순수 실행부의 포트를 실제 `MotorControl`에 연결한다. 네이티브 테스트에서는 같은 드라이버 소스를 가상 Arduino GPIO·LEDC·시계로 실행한다. 전역 실행 인스턴스, HTTP 진입점이나 자동 실행 루프는 추가하지 않았다. 서비스 상태를 읽는 환경 구현체와 기존 진입점의 보호는 아래와 같이 별도로 연결했다.

`MOTIONBRAIN_ENABLE_FINITE_PROFILE_DRIVER`도 기본 0이며, 켜려면 core 플래그도 1이어야 한다. driver만 켠 조합은 컴파일을 거부한다. 기본 두 플래그가 0인 빌드와 core만 켠 빌드에서는 기존 드라이버 동작을 유지한다. 두 플래그를 켠 네이티브 시험은 다음 경계를 검증한다.

- 출력 권한은 전모터 단독 lease로 취득한다. 드라이버 초기화·현재/목표 PWM 0·안전 조건과 다른 제어기의 대기 작업 부재가 필요하다. 드라이버 수명 동안 ID를 재사용하지 않으며 복사로 권한을 복제하지 못하게 한다.
- lease 동안 기존 `forward/reverse/setSpeed/setSpeedAll`, 램프 갱신과 외부 `setActionOrdinal` 변경을 막는다. 새 점별 PWM은 기존 램프를 거치지 않고 직접 쓰므로 이중 램프가 생기지 않는다.
- 계획된 마지막 0은 `DriverWrite`, 강제 정지는 `ForcedOff`로 구분한다. 직접 쓰기의 반환 시각과 해당 드라이버 로그 시각은 같다. 여러 모터를 끄더라도 실행부의 OFF 경계에는 M2의 실제 0 쓰기 시각을 반환하고, 전체 OFF 확인은 그 뒤 별도로 기록한다.
- 공개 정지·0 설정·안전 차단 관측·lease 중 초기화 재호출은 전체 출력을 끄고 해당 권한의 비영 출력을 다시 허용하지 않는다. 다른 모터를 지정한 정지도 활성 M2를 남겨 두지 않는다. 정지는 권한 해제와 다르다.
- 정상 완료 후에는 관측 소유권이 끝날 때까지 드라이버 lease를 유지한다. 외부 정지로 예약/실행 중 권한이 봉인되면 실행부를 취소하고, 실행부 밖의 쓰기가 있었으므로 `traceComplete=false`로 표시한다. 이전 ID·권한의 콜백이나 정지는 새 소유자의 출력을 바꾸지 않는다.
- 연결부 파괴 시에는 자신이 아직 소유한 출력만 끄고 권한을 봉인해 남긴다. 소유권 상실이나 결과 불명은 자동 복구·해제하지 않는다. 드라이버와 환경 객체는 연결부보다 오래 살아 있어야 한다.

외부 환경의 `controllersIdle()`에는 시퀀스·각도 제어기·teleop/deadman·수동 제어권·나중에 실행될 대기 작업이 모두 포함돼야 한다. 현재 환경 구현체는 아래 실제 서비스의 상태를 조회한다. 드라이버의 PWM이 0이라는 사실만으로 모든 제어기가 idle이라고 판단하지 않는다.

모든 드라이버·연결부·환경 호출은 외부 직렬화와 비재진입을 전제로 한다. 호출 사이에 DISARM→ARM처럼 안전 상태가 바뀌었다가 돌아오면 현재 상태 조회만으로 알아낼 수 없다. 아래 연결은 해당 사건 순간에 lease를 봉인하며, ARM이나 다음 상태 조회로 봉인을 해제하지 않는다. 별도 실행 스케줄과 최악 지연, 독립 차단 보장은 아직 없다.

기존 출력 링은 계속 유한하며, 숫자 `actionOrdinal` 하나를 전역 명령 식별자로 해석하지 않는다. 부팅·명령·lease와 출력 순번의 대응, 링 누락 검사 및 호스트 증거 저장은 후속 연결에서 확정해야 한다. 외부 정지로 불완전해진 실행부 기록을 완전한 실제 파형으로 간주하거나 정상 학습에 자동 포함하지 않는다.

```sh
python3 -m unittest discover -s tests -p 'test_finite_profile_driver_native.py'
```

### 서비스 제어권과 안전 전이 경계

[서비스 환경](../src/control/finite_profile_service_environment.h)은 실제 펌웨어의 단일 전역 객체 구성을 조회한다. 초기화된 safety gate·dispatcher·각도 제어기·teleop와 활성 웹 서비스를 요구하고, 기존 MOTOR_RUN 안전 정책을 재사용한다. 다른 객체 구성이나 재진입·다중 작업 호출을 지원한다는 뜻은 아니다.

예약 전에 bounded 실행, 제어 명령 큐, sequence 실행과 저장 항목, 각도 제어기의 정착·보정 상태, teleop 제어·deadman, 웹 수동 lease 및 준비/실행/차단된 routine을 확인한다. 하나라도 남아 있으면 거부한다. 저장된 sequence도 초기 정책에서는 비어 있어야 하며 자동으로 지우지 않는다. 웹 lease는 만료 시각만 지났어도 실제 만료 처리가 끝나기 전까지 남은 제어권으로 본다.

[기존 명령 가드](../src/control/finite_profile_legacy_guard.h)는 예약·실행·사후 관측 동안 대기 작업이 새로 만들어지지 않도록 명령 enqueue, dispatcher와 직접 시작 경로를 보호한다. 경쟁하는 동작·ARM·설정 변경 요청은 기존 실행권을 봉인하고 거부한다. STOP·DISARM·정지/clear/abort 요청은 봉인 후 기존 처리를 허용한다. 큐가 가득 차도 STOP의 봉인이 먼저 수행된다. 조명과 routine dry-run은 허용하며, 이 네 종류만 남은 명령 큐는 경쟁 제어로 보지 않는다. 이미 기록된 bounded 요청의 중복·충돌은 저장된 결과만 반환하며 새 프로파일의 실행권을 중단하지 않는다.

실제 시스템 상태 관리자의 유효한 ARMED 이탈은 상태 변경과 로그 전에 소유 출력만 OFF하고 봉인한다. DISARM→ARM이나 안전 차단→해제 사이에 드라이버 tick이 없어도 옛 실행권은 살아나지 않는다. teleop는 수신된 각 deadman=true 프레임에서 같은 처리를 하므로 한 배치 안의 true→false를 놓치지 않는다. 소유권이 남은 동안 teleop 출력 적용을 건너뛰고 출력 캐시를 초기화한다. 이 봉인은 lease 해제가 아니며 사후 관측과 결과 불명 차단을 우회하지 않는다.

새 가드는 MOTIONBRAIN_ENABLE_FINITE_PROFILE_DRIVER=0에서 동작하지 않는다. 1이어도 신뢰된 프로파일 목록·실행 인스턴스·일회성 토큰 발급원이 자동으로 생성되지는 않는다. 서비스 환경의 토큰 발급원은 준비된 엔트로피를 사용하는 신뢰된 비재진입 함수로 명시적으로 제공해야 하며, 없거나 실패하면 예약하지 않는다. 테스트의 가상 발급원은 운영 난수 구현이 아니다.

모든 호출은 같은 직렬 실행 경계 안에 있어야 한다. 명령 dequeue와 실제 실행 사이에 다른 작업의 prepare를 끼워 넣는 구성은 지원하지 않는다. 이 구현은 현재 서비스 경로의 사건 전달과 출력 권한을 검증하며 RTOS 잠금, 실행 스케줄, CPU 정체 중 차단 또는 전기적 OFF를 보장하지 않는다.

관련 오프라인 시험:

~~~sh
python3 -m unittest discover -s tests -p 'test_finite_profile_environment_native.py'
python3 -m unittest discover -s tests -p 'test_finite_profile_legacy_guard_native.py'
python3 -m unittest discover -s tests -p 'test_finite_profile_safety_native.py'
python3 -m unittest discover -s tests -p 'test_finite_profile_teleop_native.py'
~~~

서비스 환경 시험은 실제 환경·실행부·드라이버·bounded 서비스를 컴파일하고 주변 제어기 상태를 대역으로 제공한다. 안전 전이 시험은 실제 시스템 상태 관리·안전 모니터·드라이버를 가상 IO와 함께 실행한다. teleop 시험은 실제 입력 파서와 드라이버·실행부를 가상 직렬 입력에 연결해 한 배치의 deadman true→false와 관측 소유권·출력 캐시를 검사한다. dispatcher·웹·각도 제어기 진입점은 별도 실물 동작 검증이 남아 있다. 전체 펌웨어 컴파일은 연결 가능성 확인이며 실물 실행 시험이 아니다.

### 남은 통합 순서

1. **순수 계약·가상 시계 실행부:** 위 오프라인 구현과 테스트가 이 단위다. 새 기능은 기본 비활성이며 기존 pulse 의미를 유지한다. 후속 어댑터도 같은 반례와 시간·소유권 조건을 충족해야 한다.
2. **드라이버·서비스 통합:** 드라이버 소유권, 실제 서비스의 제어권·안전 전이 연결을 오프라인 검증했다. 전역 실행 수명·토큰 발급·명령별 증거 수집과 스케줄링 방식·메모리 예산·최악 지연은 결정하고 검증해야 한다.
3. **호스트·계측 연결:** 저널·일회성 실행·불명 결과 마감·영상 창·새 입력/자료 계약을 연결한다. 실제 촬영·구동 전에 별도 검증 범위와 프로파일 한도를 정한다.

아직 결정하지 않은 핵심은 실물에서 허용 가능한 PWM/기간 목록, `J`와 시작 준비 기간, 독립 차단의 필요 범위·구현, 증거 메모리 예산이다. 이 값들을 이번 시뮬레이션이나 기존 17개만으로 안전값처럼 확정하지 않는다. 장치 소프트웨어 출력의 재현성이 좋아져도 백래시·하중·공급 전압·영상 계측 오차가 남으므로 각도 예측 성능은 새 자료로 평가해야 한다.
