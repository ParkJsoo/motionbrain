# 장치가 완료까지 관리하는 유한 출력 프로파일 설계

**상태: 실행부·드라이버·명령별 실제 쓰기 보존·단일 루프 스케줄·인증 HTTP API까지 구현 및 오프라인 검증. 한 프로파일의 명시 활성 시험 빌드로 실물 단발 1/1회 완료를 확인했다. 시간 수치는 장치의 밀리초 단위 드라이버 쓰기 기록이며, 전기적 파형·관절각 검증은 포함하지 않는다.** 기존 sequence·bounded pulse의 의미와 기본 비활성 상태를 바꾸지 않는다. 수학적 예시와 문서 후반의 단발 시운전 프로파일을 구분한다.

## 목적과 변경 범위

요청 PWM·명령 기간만 같아도 실제 출력은 램프 갱신과 호스트 STOP 처리 시점에 따라 달라질 수 있다. 정상 동작의 상승·유지·하강·마지막 0 출력을 장치가 하나의 유한 일정으로 관리하고, 호스트의 정상 종료 STOP에 대한 의존을 없애는 것이 목적이다. 호스트 STOP·DISARM·기존 안전 정지는 계속 중단 수단이다. 출력 재현성 개선이나 각도 예측 성능 향상은 아직 입증하지 않았다.

첫 설계 범위는 한 모터·한 방향, 시작 전 출력 0, 마지막 출력 0이다. 동시 모터 제어·프로파일 내 방향 전환·자동 반복·실패 명령 재전송·자동 ARM은 제외한다. M2부터 검토하더라도 기존 양수 전용 pilot 허용이 양방향 실물 실행 허용으로 확대되는 것은 아니다.

기존 `durationMs`를 새 전체 출력 기간으로 재해석하지 않는다. 새 `actionContractVersion`과 `profileVersion`을 사용하고, 기존 자료·도구에는 명시적 호환 처리가 없으면 거부하게 한다. 기존 450/550ms·PWM ±160과 새 프로파일의 같은 숫자는 같은 동작을 뜻하지 않는다.

## 실행 전 고정할 계약

외부 요청은 검토된 프로파일 목록의 ID를 선택한다. 첫 버전에서 임의 점열·무제한 유지시간을 받지 않는다. 장치는 목록에서 전체 정수 점열을 재구성하고 호스트의 정규화 결과와 일치하는지 검사한다. 지원하지 않는 버전·알 수 없는 필드·범위 초과·중복 시간·비정수 값은 조용히 보정하지 않고 거부한다.

| 항목 | 의미 |
| --- | --- |
| `actionContractVersion`, `profileVersion`, `catalogHash` | 동작 의미·프로파일 생성 규칙·허용 목록을 식별한다. |
| `bootId`, `commandId` | 같은 부팅에서 한 논리적 요청을 식별한다. 새 ID로 실패 요청을 포장하지 않는다. |
| `motor`, `direction`, `profileId` | 한 모터·한 부호와 허용 프로파일을 고정한다. |
| `points` | 예정 시작에 대한 정수 `offsetMs`와 실제 적용할 부호 PWM의 목록이다. 마지막 PWM은 0이며 시간은 엄격히 증가한다. |
| `nominalEndOffsetMs`, `startLeadMs` | 마지막 예정 0 시각과 실행 수락부터 예정 시작까지의 준비 기간이다. |
| `timingPolicyVersion`, `maxLatenessMs`, `offConfirmWindowMs` | 각 출력 쓰기의 허용 지연, 실패 정책, 종료 결정 뒤 유한 OFF 확인 기간이다. 장치가 승인한 정책으로 고정하며 요청자가 늘리지 못한다. |
| `canonicalProfileHash` | 위 실행 의미 전체를 정규화한 해시다. 모터·부호·점열·시간 정책까지 포함한다. |

정규화는 고정 필드 순서·정수 표현·UTF-8·고정 직렬화 규칙을 버전으로 정의하고, 호스트와 장치의 공통 시험 벡터로 검증한다. JSON 문자열의 우연한 순서나 표시용 실수 반올림에 의존하지 않는다. ID·부팅·소유권·예약 정보를 포함한 전체 요청 지문은 프로파일 해시와 별도로 보존한다. 해시는 무결성·동일성 비교 수단이며 인증을 대신하지 않는다.

## 시간 의미와 예측 가능한 범위

`preparedAt`(출력 없는 예약), `executeAcceptedAt`, `plannedStartAt`, `firstNonzeroWriteAt`, `plannedOffAt`, `offWriteAt`, `offConfirmedAt`, `hostOffReceiptAt`를 구분한다. 장치 시각과 호스트 시각은 직접 빼지 않는다.

`plannedStartAt = executeAcceptedAt + startLeadMs`를 수락 순간에 고정한다. 첫 쓰기가 늦어져도 기준을 실제 첫 쓰기로 옮기지 않는다. 예정 오프셋이 `s[k]`, 실제 쓰기가 `a[k]`, 허용 지연이 `J`라면 정상 실행은 모든 점에서 다음을 만족해야 한다.

```text
plannedStartAt + s[k] <= a[k] <= plannedStartAt + s[k] + J
0 <= J < 가장 짧은 점 사이 간격
plannedOffAt = plannedStartAt + nominalEndOffsetMs
```

출력 직전 실제 장치 시각을 다시 확인하며, 검사부터 쓰기까지의 지연도 계측 대상이다. 최종 판정은 실제 드라이버 쓰기 기록으로 하며 허용 경계와 같으면 통과, 초과하면 실패다. OFF 뒤 확인이 늦은 것과 OFF 쓰기 자체가 늦은 것을 별도로 기록한다. 허용 마지막 OFF 시각은 `plannedOffAt + J`이며, 별도 물리적 차단 장치의 한도와 같은 의미가 아니다. 추가 차단의 시각 정책이 정상적으로 허용한 마지막 OFF와 충돌하지 않는지도 검토해야 한다. 단발 시운전 목록의 `J`·준비 기간은 문서 후반에 고정했지만, 최악의 스케줄러 지연과 독립 차단은 아직 입증하지 않았다.

지연된 비영 이벤트를 건너뛰거나 여러 단계를 몰아서 실행하지 않는다. 허용 시각을 놓쳤으면 추가 비영 출력 없이 실패 처리와 OFF를 시도한다. 마지막 OFF가 늦었어도 반드시 OFF부터 시도하고 시간 실패로 남긴다. 이미 접수된 안전 정지·취소, 소유권 검증, 시간 실패·종료 판단이 정상 비영 출력보다 앞선다.

단일 장치의 짧은 시간차는 wrap을 고려한 부호 없는 경과시간으로 계산한다. 프로파일·예약 유효기간·비교 구간은 모두 `2^31ms` 미만으로 제한하고, `now >= start + offset` 같은 직접 비교를 사용하지 않는다. 다른 부팅의 시각을 이어 붙이지 않는다. 시계 연속성을 확인할 수 없는 장기 정체·재부팅은 정상 완료가 아니다.

### 수학적 예시: 예정 출력과 실제 출력의 구분

기존 램프의 단위인 PWM 10, 간격 50ms를 설명용 점열에 사용한다. `N`단계로 최대값 `P=10N`까지 올라간 뒤 같은 단위로 0까지 내려가며 최대값에서 추가로 `H`ms 유지한다. 최초 PWM 10의 예정 오프셋은 0이다.

```text
예정 전체 기간 T = (2N - 1) × 50 + H  [ms]
예정 절대 PWM 적분 A = 0.5 × N² + P × H / 1000  [PWM·s]
```

`N=6, H=0`이면 점열은 `10,20,30,40,50,60,50,40,30,20,10,0`, 예정 기간 550ms, 예정 적분 18.00 PWM·s다. 이는 기존 요청 PWM 160·명령 기간 550ms의 대체 설정이 아니다.

모든 쓰기가 일찍 실행되지 않고 각각 `0..J`만큼 늦으며 점 순서가 보존되는 **정상 조건에서만**, 이 예시의 활성 기간은 `T-J .. T+J`, 적분은 `A-PJ/1000 .. A+PJ/1000` 안에 있다. 설명용 `J=10ms`라면 540~560ms와 17.40~18.60 PWM·s다. 10ms를 실물 허용값으로 선택했다는 뜻이 아니다.

시작·종료·중간 지연을 실행 전에는 알 수 없으므로 이 값은 허용 범위이지 실제 파형 예측값이 아니다. 실패·CPU 정체·전원 이상에는 이 수학적 범위를 적용하지 않는다. PWM 적분은 에너지·토크·이동각이 아니며, 같은 적분도 파형·마찰·자세에 따라 다른 결과를 낼 수 있다.

## 수락·소유권·취소 프로토콜

프로토콜은 **출력 없는 예약 후 한 번 실행**하는 두 단계다. 기존 bounded API와 분리된 finite API로 연결한다. 단계가 하나 늘지만, 아직 도착하지 않은 실행 요청의 취소와 오래된 최초 요청을 장치에서 차단할 수 있는 경계를 만든다.

1. 호스트는 현재 부팅·소유권 세대와 프로파일 목록을 읽고 프로파일·요청 지문을 저널에 고정한다. 장치는 명령 ID와 전체 계약을 검증한 뒤 출력 없이 기록과 증거 공간을 예약한다. 동시에 하나만 예약하며 실행 큐는 없다. 예약 응답 뒤 실행 직전에 사전 관측 영수증과 예측 입력·출력을 고정한다. 예측과 정답의 사전 상태는 아래 학습 계약에 따라 같은 영수증을 사용한다.
2. 예약 응답에는 장치가 발급한 일회성 실행 토큰을 담는다. 토큰은 부팅·ID·계약 해시·소유권 세대·장치 기준 유효기간에 결합된다. 기록은 토큰 발급보다 먼저 남긴다. 토큰은 기존 인증을 대체하지 않으며 공개 로그에 남기지 않는다.
3. 실행 요청은 해당 예약·토큰·세대·만료·안전·출력 0 상태를 원자적으로 재검증한다. 토큰을 소모하고 시작 기준과 출력 소유권을 고정한 뒤에만 실행할 수 있다. 수락 응답 유실은 미실행 증거가 아니다.
4. 예약 취소·만료·완료·소유권 해제 및 DISARM·안전 정지·소유권 변경은 이전 세대를 무효화한다. 미등록 ID 취소는 `idle`이며 요청한 세대가 현재 세대일 때만 세대를 증가시키는 취소 경계를 남긴다. 다른 ID가 예약·실행·관측 소유권을 가진 상태에서는 거부하며 그 동작을 암묵적으로 취소하지 않는다. 해당 소유권 해제 시 세대가 바뀌므로 대기하던 이전 세대 예약은 거부된다.
5. 동일 ID·동일 전체 계약은 저장된 상태를 반환하며 출력 호출을 반복하지 않는다. 같은 ID·다른 계약은 충돌이다. 만료·취소·완료된 기록도 부팅 중 삭제하지 않는다. 레지스트리 포화는 신규 예약 거부이며 자동 재부팅·삭제로 우회하지 않는다.
6. 호스트는 예약·실행 실패나 응답 유실 후 출력 요청을 자동 재전송하지 않는다. 조회·취소·증거 확인으로 마감한다. 부팅 변경·기록 부재·토큰 유실을 새 ID 실행의 근거로 삼지 않는다.

`prepare(expectedEpoch=E)`는 완전히 idle이며 현재 세대가 E일 때만 수락한다. 미등록 취소도 인증·형식·현재 부팅 검증을 거친다. 이미 종료된 ID의 중복 요청·늦은 취소는 원기록만 반환하며 출력과 세대를 바꾸지 않는다. 현재 출력을 끊는 전역 안전 STOP은 이 과거 ID 조회 의미와 별도다. 단순 조회는 토큰을 공개하거나 발급하거나 만료를 연장하지 않는다. 모든 변경 요청은 기존 인증을 요구한다.

예약 만료 정리 작업이 늦었더라도 실행 수락 지점에서 장치 시각으로 만료를 검사하며, 만료 시각과 같거나 이후면 실행을 거부한다. 실행 시작 전에 안전 조건이 달라지면 예약 당시 통과했더라도 거부한다. 예약 취소와 실행 수락의 순서를 직렬화하여 먼저 확정된 사건이 결과를 결정하게 한다. 세대의 표현 범위를 소진하면 조용히 wrap해 재사용하지 않고 신규 예약을 차단한다.

## 출력 소유권과 스케줄러

비영 PWM을 쓸 수 있는 주체는 한 곳이어야 한다. 프로파일 소유권에는 부팅·명령·세대 식별자가 있으며 모든 쓰기 직전에 소유권과 종료 표시를 검사한다. 기존 램프·시퀀스·수동 HTTP·serial·teleop·각도 제어기가 우회해서 쓸 수 없어야 한다. 정상 프로파일 쓰기는 기존 `setSpeed()` 램프를 두 번 거치지 않는 검증된 드라이버 경계를 사용해야 한다.

취소·종료는 먼저 비영 이벤트를 무효화하고 목표·현재 출력·대기 이벤트를 정리한 뒤 OFF를 적용한다. 늦게 깨어난 callback은 오래된 세대로 출력을 다시 켜지 못한다. `actionOrdinal`·드라이버 상태·출력 로그·완료 기록도 같은 직렬화 정책 안에 둔다. 함수 공개 범위만 바꾸어 다중 작업에서 호출하는 방식은 허용하지 않는다.

동일 실행 안에서도 `nextEventIndex`는 단조 증가해야 한다. 사건의 소유권·인덱스·시간 검증, 실제 쓰기, 소비 표시를 원자적으로 처리한다. 이미 소비한 인덱스의 callback은 비영 쓰기 없이 무시하고 중복 사실을 제한된 진단에 남긴다. 다음 인덱스를 건너뛰는 이벤트는 실패·OFF 처리한다. `k → k+1 → 늦은 k` 순서가 같은 세대라는 이유만으로 과거 PWM을 다시 적용해서는 안 된다.

실행 중 일반 동작 요청은 거부한다. 명시적인 수동 개입은 먼저 프로파일을 중단하고 소유권과 세대를 바꾸는 별도 사건이며, 자동으로 이어서 실행하지 않는다. 안전 정지는 언제나 우선한다. 정상 완료 후에도 사후 관측이 끝날 때까지 출력 금지 상태를 유지한다. 관측 중 다른 출력이 발생하면 침범으로 기록하고 해당 측정을 부적격으로 처리한다. 호스트가 사라졌다고 자동으로 소유권을 풀어 새 동작을 시작하지 않는다.

완료 또는 부분 실행 뒤 OFF가 확인되면 실행 세대를 폐기하고 같은 명령에 새 관측 세대(`observationGeneration`)를 부여한다. 관측 종료 확인은 인증된 별도 요청으로 `bootId + commandId + observationGeneration`을 지정한다. 현재 관측 소유자와 정확히 일치할 때만 원자적으로 해제하고 세대를 증가시킨다. 이미 해제된 과거 명령의 중복 확인은 저장된 결과만 반환하며 현재 소유권에 영향이 없다. 관측 완료 확인은 영상 품질이나 학습 적격 판정 자체를 뜻하지 않는다. 호스트 소실 시 출력 금지를 유지하며, 명시적 복구는 해당 관측을 중단으로 기록하고 현재 OFF·소유권을 확인한 뒤에만 해제한다. 결과 불명으로 부팅 내 차단된 실행을 이 관측 해제 경로로 우회하지 못한다.

새 스케줄러는 HTTP 응답 직렬화·카메라·파일 저장·가변 길이 로그를 수행하지 않는 실행 경로가 후보이다. 공유 잠금·인터럽트 지연·우선순위 역전·다른 모터의 쓰기까지 측정해야 하며, 별도 작업을 만들었다는 사실만으로 정시 실행이 보장되지는 않는다. 구체적인 RTOS/타이머 API와 우선순위는 이 문서에서 확정하지 않는다.

같은 루프에서 늦게 발견해 OFF하는 보장과, 루프/CPU가 멎어도 기한 내 차단하는 보장은 다르다. 후자는 독립 차단 경로와 실물 증거가 필요하다. 소프트웨어의 `outputOff`도 드라이버 상태 확인이며 전기적 출력·관절 정지 실측이 아니다.

## 상태와 증거

| 상태 | 조건 | 이후 처리 |
| --- | --- | --- |
| 예약됨 | 검증·ID·증거 공간 예약, 출력 없음 | 유효한 실행 토큰 한 번만 수락 |
| 실행 중 | 고정된 시작 기준·일정·소유권으로 출력 | 조회가 실행을 진행시키거나 기한을 연장하지 않음 |
| 정지 확인 중 | 완료 예정·취소·실패로 비영 이벤트 무효화 | 무조건 OFF 시도, 신규 동작 차단 |
| 정상 완료 | 모든 이벤트 시간 정책 충족, 마지막 0 쓰기와 소프트웨어 OFF 확인 | 사후 관측용 출력 금지 유지 |
| 취소/만료/실패 | 각 사유를 보존하고 소프트웨어 OFF 확인 | 정상 완료로 승격 금지, 새 실행 자동 시작 금지 |
| 결과 불명 | OFF 또는 실행 결과를 확정할 수 없음 | 부팅 내 실행 차단 유지, 후속 확인은 별도 기록 |

`controlOutcome`, `timingConformant`, `softwareOffConfirmed`, `traceComplete`, `measurementEligible`는 별도 필드다. OFF 확인이 성공했다고 정상 완료·파형 보존·영상 정착이 모두 성공한 것은 아니다. 전기적 OFF·기계적 정착·목표 도달은 별도 실측이 없으면 미확인으로 둔다.

최초 종료 결정·사유·시각은 불변이다. 첫 OFF 시도, 후속 OFF 시도, 후속 확인 시각은 따로 보존한다. 나중에 OFF를 확인해도 최초 결과 불명이나 시간 실패를 정상 완료로 바꾸지 않는다. 완료와 취소가 경합하면 직렬화 지점에서 먼저 확정된 결과를 보존한다. 종료된 ID를 지정한 늦은 취소는 원기록만 반환한다. 현재 출력을 끊는 별도의 전역 안전 STOP은 과거 결과를 변경하지 않는 새 사건으로 기록한다. A가 완료된 뒤 B 실행 중 도착한 `cancel(A)`가 B를 끄면 안 된다.

정지 확인 중 상태에는 최초 종료 결정부터 장치 기준 `offConfirmWindowMs`라는 유한 기한을 둔다. 기한 안에 확인되지 않으면 결과 불명과 부팅 내 실행 차단을 확정한다. 최초 확인 실패의 증거는 유지하고, 이후 확인 성공도 정상 완료로 승격시키지 않는다. 이 기한은 사후 확인·판정의 한도이며 CPU 정체 중 실제 차단을 보장하는 한도가 아니다. 확인 횟수·후속 진단 기록량도 버전 정책으로 제한한다. 후속 OFF 시도는 고정 크기 요약·포화 카운터 등으로 분리하고, 로그 공간이 부족해도 안전 OFF 시도 자체를 막지 않는다. 기한과 기록 한도가 미정인 구현은 활성화하지 않는다.

증거는 명령별 예정 점열·실제 모든 쓰기·부팅·명령 귀속·연속 순번·시계·실제 0 경계를 보존한다. 정상 이벤트와 중단·중복 OFF를 포함한 최악 예산을 예약 때 확보해야 한다. 가용 메모리 안에 들어오지 않는 프로파일은 거부한다. 무제한 반복 진단 로그는 실행 경로에 저장하지 않는다.

기존 링 조회를 보존하더라도 학습용 증거를 그 링 하나에 의존시키지 않는다. 명령별 고정 공간·불변 종료 요약·조회 무결성 검증을 설계한다. 증거 손실은 OFF를 방해하지 않으며, 안전하게 멈췄더라도 `traceComplete=false`로 남긴다. 누락 파형 보간으로 적격 자료를 만들지 않는다. 최종 보존 방식과 메모리 예산이 정해지기 전에는 기능을 활성화하지 않는다.

## 학습·영상 계측 계약

행동 계약·관측 계약·특징 순서/버전·데이터 형식을 각각 식별한다. 실행 전 입력은 이전 상태·속도, 요청 방향, 프로파일 ID/버전/해시, 예정 점열에서 계산한 최대 PWM·기간·적분 등으로 한정한다. 이전 동작 이력은 현재 실행 요청 전 확보한 기록만 사용할 수 있으며, 누락 여부·경과시간도 남긴다. 예약 대기로 이전 관측이 낡을 수 있으므로 관측 나이 한도와 실행 전 재검사도 계약에 포함해야 한다. 한도 초과 시 새 입력으로 기존 요청을 조용히 바꾸지 않고 예약을 취소한다. 미리 알 수 있다는 것이 예측에 유용함을 입증하지는 않으므로 입력 추가는 제한된 후보와 별도 개발 평가로 검토한다.

실제 최대 PWM·활성 기간·적분·각 이벤트 지연·취소·실제 OFF 시각은 사후 정보다. 정상 동작만 남았다는 사실도 실행 전 입력으로 쓰지 않는다. 실행 전 예측 영수증은 출력 요청 전에 저장하고 모델·입력·프로파일의 해시를 묶는다. 결과를 본 뒤 예정 파형이나 입력을 수정하지 않는다.

기존 17개는 동일 development 그룹의 기존 행동 계약이다. [기존 학습·고정 모델](supervised-action-collection.md)은 보존하며 새 프로파일 자료를 기존 로더에 같은 행 형태로 넣지 않는다. 기존 모델을 새 방식에 적용한다면 계약이 달라진 참고 비교로만 표시한다. 새 방식의 독립 시험 모델로 승격하지 않는다. 과거 명령 시작+4초 계약의 32개·MAE 0.665°도 혼합하지 않는다.

사전 관측은 예약 응답 뒤 실행 요청 전에 닫힌 영상 창으로 확정한다. **향후 예측 입력의 사전 상태와 정답 변화량에서 빼는 사전 상태는 반드시 같은 영수증을 참조해야 한다.** [유한 프로파일 계측 모듈](../learning/finite_profile_measurement.py)의 `preflight(report, config, capture, anchor)`는 별도로 고정한 호스트 단조 시각 `anchor`의 −0.75~−0.10초 창에서 상대각·속도·품질을 계산한다. 프레임 ID·원본 해시·계측 설정·실행 식별자·예정 프로파일 해시를 영수증에 묶고, 사용한 프레임의 호스트 수신 시각이 앵커를 넘으면 거부한다. 호출자는 적격 영수증을 실행 전에 저장하고, 실제 전송 시작까지 앵커 나이가 2초를 넘으면 실행하지 않는다. 이 2초는 현재 운용 한도이며 상태의 물리적 유효성을 입증한 값은 아니다. 최종 계측도 같은 프레임만 사용하므로 늦게 도착한 과거 영상이나 실제 전송 시각으로 사전 창을 다시 선정하지 않는다. 사전 품질 계산 경로는 소프트웨어 검증을 마쳤고, 2026-11-03 실물 구동과 저장 영상의 연결을 1회 확인했다. 모델 예측 경로는 연결하지 않았으며, 영상 투영각과 실제 관절각의 관계나 측정 변동과 실제 이동의 분리는 검증하지 않았다.

현재 계측 계약 `finite_settled_fixed_before_host_off_receipt_v1`의 사후 창은 정상 완료와 소프트웨어 OFF를 확인한 최초 응답을 호스트가 수신한 `hostOffReceiptAt` 뒤 2.25~3초다. HTTP 전송 시작·응답 수신 시각은 호스트 단조 시계이며 장치의 `offConfirmedAt`과 직접 빼지 않는다. 전송 경유가 있으면 `dispatchBefore`는 호스트의 전체 전송 시작이지 장치 수신 시각이 아니다. 사후 창이 끝나고 출력 금지를 확인할 때까지 관측 소유권을 유지한 뒤 해제한다. 양쪽 창은 각각 최소 3프레임, 프레임 사이와 창 양끝의 최대 간격 0.3초, 동일한 카메라 설정, 상대각 범위 0.5° 이하를 요구한다. 이는 영상에서의 정착 품질 검사이며 고정 대기시간만으로 기계적 정착을 보장하지 않는다. 부분 실행·취소·시간 실패·결과 불명은 정상 계측에서 제외하고, 사후 비영 출력이나 불완전한 출력 증거도 거부한다. 장치 실제 OFF 기준 창으로 바꾸려면 시계 매핑과 관측 계약을 별도로 검증·버전 관리해야 한다.

`measure(report, config, capture)`는 장치에 접근하지 않고 저장 자료 한 명령을 검증한다. 입력 형식은 `motionbrain.finite_profile_capture.v1`이며 `actionContract=finite_profile.v1`, 새 `captureGroup`, `split=development`, 카메라·프레임 정보, `requestedProfile`, `expectedBootId`, `expectedEpoch`, `trial.id`와 사전 영수증·호스트 시각·닫힌 출력 증거를 요구한다. `capture`는 `native-camera` 디렉터리이며 그 부모의 고정 파일 `before-receipt.json`과 `closed-actual-evidence.json`을 읽어 보고서와 내용이 같은지 확인하고 원본 바이트 해시를 남긴다. 사전 영수증의 부팅·명령·세대와 예정 프로파일은 최종 기록의 식별자·프로파일과 일치해야 한다. 영상 원본과 시계 증거도 기존 계측 검증 함수를 재사용해 확인한다.

출력 형식은 기존 데이터셋과 다른 `motionbrain.finite_profile_endpoint_measurement.v1`이다. 상대각 변화는 보정된 절대 관절각이 아닌 영상 투영각으로 기록한다. 예정 활성 기간·PWM 적분과 사후 드라이버 기록의 활성 기간·적분·지연은 구분하며, 사후 정보를 실행 전 입력으로 사용하지 않는다. `eligible`은 이 계측 계약의 통과 여부이며 학습·예측·독립 시험 성능을 뜻하지 않는다. [계측 테스트](../tests/test_finite_profile_measurement.py) 21개가 사전 영수증 고정, 원본 누락·변조, 식별자 교체, 시계 wrap, 출력 침범과 영상 품질 실패를 검증했다. 새 학습은 수행하지 않았다. 아래 실물 전후 영상 1회는 이 계측 계약을 통과했지만 독립 시험 자료나 각도 예측 성능의 근거로 사용하지 않는다.

평가는 먼저 새 계약의 개발자료에서 제한된 모델과 기준선을 정하고, 측정·프로파일·입력·모델을 고정한 뒤 별도 그룹을 보류한다. 같은 촬영 그룹을 나눠 독립 시험이라고 하지 않는다. 전체 시도에서 예약 거부·미전송·미시작·부분 실행·취소·시간 실패·결과 불명·증거 누락·측정 제외·적격 수를 보고한다. 정상 적격 자료의 각도 오차는 정상 실행 조건부 성능으로 표시하고 전체 시도의 실행 신뢰도와 함께 보고하며, 실패를 빼서 개선처럼 보이게 하지 않는다. 정상 출력·유효 관측인데 움직임이 작거나 0인 자료도 포함한다. 부분 실행 후 취소·시간 실패의 출력과 관측이 온전하면 정상 학습에서는 제외하되 진단 자료로 보존한다.

## 다음 구현 단위와 미확정 조건

### 순수 오프라인 실행부

[계약 모듈](../src/control/finite_profile_contract.h)과 [실행부](../src/control/finite_profile_executor.h)는 Arduino·HTTP·모터 드라이버에 연결되지 않는 C++11 코드다. `MOTIONBRAIN_ENABLE_FINITE_PROFILE_CORE`는 기본 0이며, 네이티브 테스트와 명시 활성 시험 빌드에서 1로 컴파일한다. 네이티브 시험은 가상 시계·가상 출력 포트를 제공한다. 이 플래그를 켜는 것만으로 실물 기능이 생기지는 않으며 운영용 플래그나 실행 예시로 사용하지 않는다.

계약 모듈은 버전 1·M2·한 방향·최대 32개 점과 유한 기간을 구조적으로 검증한다. 코드의 PWM 범위와 10,000ms 같은 상한은 저장공간·계산을 제한하기 위한 것으로 승인된 실물 범위가 아니다. 실행부 자체는 실물 한도를 정하지 않으며, 별도 시운전 목록은 문서 후반에 명시한다. 실행부는 호출자가 제공한 신뢰된 목록을 복사하고 요청의 전체 프로파일과 비교하므로, 요청자가 해시만 일치시켜 다른 점열을 실행할 수 없다.

`canonicalProfile()`은 고정 ASCII/UTF-8 필드 순서·정수 십진수·LF로 정규화된 **해시 입력 바이트**를 만든다. SHA-256 계산·목록 배포·네트워크 파싱은 이 실행부에 포함하지 않는다. `catalogHash`는 신뢰된 목록에서 제공하는 식별값으로 형식과 일치를 검사하며 목록 자체의 해시를 계산하지 않는다. 향후 목록 생성 규칙은 해시 필드 자체를 제외한 원문을 명시해 자기 참조를 피해야 한다. 미사용 점 배열의 뒤쪽은 실행 점열과 정규화에 포함하지 않는다.

포트는 실제 쓰기 시각, 소프트웨어 OFF 확인의 대기·확인·실패 구분, 일회성 토큰 발급을 제공한다. 과거 OFF 확인을 현재 출력 상태로 대신하지 않으며 쓰기·확인 시각의 일관성을 검사한다. 자동 OFF 확인은 유한 시간·횟수로 제한하지만, 결과 불명 뒤 명시적 OFF 재시도는 진단 기록 한도로 막지 않는다. 최초 종료·확인과 후속 재시도의 기록을 구분하고 결과 불명 차단은 유지한다.

순수 실행부는 실제 난수·인증·동시성 잠금·실물 피드백을 직접 제공하지 않는다. 별도 런타임은 난수·인증·단일 루프 직렬화를 연결한다. 모든 실행부 호출은 외부에서 직렬화해야 하며 포트는 실행부를 재진입 호출하면 안 된다. 안전 상태 변화는 호출 시점에 관측한 것만 알 수 있으므로, 후속 어댑터는 DISARM·소유권 변경 등의 사건도 누락 없이 전달해야 한다. 가상 시계에서 사건 순서를 검증하는 것과 실제 다중 작업 환경의 원자성을 검증하는 것은 다르다.

재현 가능한 오프라인 테스트 명령:

```sh
python3 -m unittest discover -s tests -p 'test_finite_profile_native.py'
```

테스트는 실제 계약·실행부 소스를 일반 C++ 컴파일러로 빌드한다. 정상 완료뿐 아니라 예약 만료, ID·세대·토큰 불일치, 취소, 실제 쓰기 지연, 이벤트 중복·역순, OFF 확인 실패, 관측 소유권 해제, 시계 wrap 및 기본 비활성 빌드를 다룬다. 장치 연결·펌웨어 업로드·촬영·학습은 포함하지 않는다. 명령별 파형과 종료 기록의 실물 수집, 호스트 저널, 사전 관측 영수증은 후속 통합 범위다.

### 모터 드라이버 연결 경계

[드라이버 연결부](../src/control/finite_profile_driver_bridge.h)는 순수 실행부의 포트를 실제 `MotorControl`에 연결한다. 네이티브 테스트에서는 같은 드라이버 소스를 가상 Arduino GPIO·LEDC·시계로 실행한다. 드라이버 연결부 자체는 전역 실행 인스턴스나 HTTP 진입점을 만들지 않으며 별도 런타임이 이를 소유한다. 서비스 상태를 읽는 환경 구현체와 기존 진입점의 보호는 아래와 같이 별도로 연결했다.

`MOTIONBRAIN_ENABLE_FINITE_PROFILE_DRIVER`도 기본 0이며, 켜려면 core 플래그도 1이어야 한다. driver만 켠 조합은 컴파일을 거부한다. 기본 두 플래그가 0인 빌드와 core만 켠 빌드에서는 기존 드라이버 동작을 유지한다. 두 플래그를 켠 네이티브 시험은 다음 경계를 검증한다.

- 출력 권한은 전모터 단독 lease로 취득한다. 드라이버 초기화·현재/목표 PWM 0·안전 조건과 다른 제어기의 대기 작업 부재가 필요하다. 드라이버 수명 동안 ID를 재사용하지 않으며 복사로 권한을 복제하지 못하게 한다.
- lease 동안 기존 `forward/reverse/setSpeed/setSpeedAll`, 램프 갱신과 외부 `setActionOrdinal` 변경을 막는다. 새 점별 PWM은 기존 램프를 거치지 않고 직접 쓰므로 이중 램프가 생기지 않는다.
- 계획된 마지막 0은 `DriverWrite`, 강제 정지는 `ForcedOff`로 구분한다. 직접 쓰기의 반환 시각과 해당 드라이버 로그 시각은 같다. 여러 모터를 끄더라도 실행부의 OFF 경계에는 M2의 실제 0 쓰기 시각을 반환하고, 전체 OFF 확인은 그 뒤 별도로 기록한다.
- 공개 정지·0 설정·안전 차단 관측·lease 중 초기화 재호출은 전체 출력을 끄고 해당 권한의 비영 출력을 다시 허용하지 않는다. 다른 모터를 지정한 정지도 활성 M2를 남겨 두지 않는다. 정지는 권한 해제와 다르다.
- 정상 완료 후에는 관측 소유권이 끝날 때까지 드라이버 lease를 유지한다. 외부 정지로 예약/실행 중 권한이 봉인되면 실행부를 취소하고, 실행부 밖의 쓰기가 있었으므로 `traceComplete=false`로 표시한다. 이전 ID·권한의 콜백이나 정지는 새 소유자의 출력을 바꾸지 않는다.
- 연결부 파괴 시에는 자신이 아직 소유한 출력만 끄고 권한을 봉인해 남긴다. 소유권 상실이나 결과 불명은 자동 복구·해제하지 않는다. 드라이버와 환경 객체는 연결부보다 오래 살아 있어야 한다.

외부 환경의 `controllersIdle()`에는 시퀀스·각도 제어기·teleop/deadman·수동 제어권·나중에 실행될 대기 작업이 모두 포함돼야 한다. 현재 환경 구현체는 아래 실제 서비스의 상태를 조회한다. 드라이버의 PWM이 0이라는 사실만으로 모든 제어기가 idle이라고 판단하지 않는다.

모든 드라이버·연결부·환경 호출은 외부 직렬화와 비재진입을 전제로 한다. 호출 사이에 DISARM→ARM처럼 안전 상태가 바뀌었다가 돌아오면 현재 상태 조회만으로 알아낼 수 없다. 아래 연결은 해당 사건 순간에 lease를 봉인하며, ARM이나 다음 상태 조회로 봉인을 해제하지 않는다. 운영 타이머의 최악 지연과 독립 차단 보장은 아직 없다.

기존 출력 링은 계속 유한하며, 숫자 `actionOrdinal` 하나를 전역 명령 식별자로 해석하지 않는다. 아래 명령별 보관함은 링과 독립적으로 부팅·명령·lease 및 자체 쓰기 순번을 연결한다. 호스트의 영속 저장·전송 무결성은 후속 범위다. 외부 정지로 불완전해진 실행부 기록을 정상 학습에 자동 포함하지 않는다.

```sh
python3 -m unittest discover -s tests -p 'test_finite_profile_driver_native.py'
```

### 서비스 제어권과 안전 전이 경계

[서비스 환경](../src/control/finite_profile_service_environment.h)은 실제 펌웨어의 단일 전역 객체 구성을 조회한다. 초기화된 safety gate·dispatcher·각도 제어기·teleop와 활성 웹 서비스를 요구하고, 기존 MOTOR_RUN 안전 정책을 재사용한다. 다른 객체 구성이나 재진입·다중 작업 호출을 지원한다는 뜻은 아니다.

예약 전에 bounded 실행, 제어 명령 큐, sequence 실행과 저장 항목, 각도 제어기의 정착·보정 상태, teleop 제어·deadman, 웹 수동 lease 및 준비/실행/차단된 routine을 확인한다. 하나라도 남아 있으면 거부한다. 저장된 sequence도 초기 정책에서는 비어 있어야 하며 자동으로 지우지 않는다. 웹 lease는 만료 시각만 지났어도 실제 만료 처리가 끝나기 전까지 남은 제어권으로 본다.

[기존 명령 가드](../src/control/finite_profile_legacy_guard.h)는 예약·실행·사후 관측 동안 대기 작업이 새로 만들어지지 않도록 명령 enqueue, dispatcher와 직접 시작 경로를 보호한다. 경쟁하는 동작·ARM·설정 변경 요청은 기존 실행권을 봉인하고 거부한다. STOP·DISARM·정지/clear/abort 요청은 봉인 후 기존 처리를 허용한다. 큐가 가득 차도 STOP의 봉인이 먼저 수행된다. 조명과 routine dry-run은 허용하며, 이 네 종류만 남은 명령 큐는 경쟁 제어로 보지 않는다. 이미 기록된 bounded 요청의 중복·충돌은 저장된 결과만 반환하며 새 프로파일의 실행권을 중단하지 않는다.

실제 시스템 상태 관리자의 유효한 ARMED 이탈은 상태 변경과 로그 전에 소유 출력만 OFF하고 봉인한다. DISARM→ARM이나 안전 차단→해제 사이에 드라이버 tick이 없어도 옛 실행권은 살아나지 않는다. teleop는 수신된 각 deadman=true 프레임에서 같은 처리를 하므로 한 배치 안의 true→false를 놓치지 않는다. 소유권이 남은 동안 teleop 출력 적용을 건너뛰고 출력 캐시를 초기화한다. 이 봉인은 lease 해제가 아니며 사후 관측과 결과 불명 차단을 우회하지 않는다.

새 가드는 MOTIONBRAIN_ENABLE_FINITE_PROFILE_DRIVER=0에서 동작하지 않는다. 1이어도 신뢰된 프로파일 목록·실행 인스턴스·일회성 토큰 발급원이 자동으로 생성되지는 않는다. 서비스 환경의 토큰 발급원은 준비된 엔트로피를 사용하는 신뢰된 비재진입 함수로 명시적으로 제공해야 하며, 없거나 실패하면 예약하지 않는다. 테스트의 가상 발급원은 운영 난수 구현이 아니다.

모든 호출은 같은 직렬 실행 경계 안에 있어야 한다. 명령 dequeue와 실제 실행 사이에 다른 작업의 prepare를 끼워 넣는 구성은 지원하지 않는다. 이 구현은 현재 서비스 경로의 사건 전달과 출력 권한을 검증하며 RTOS 잠금, 실행 스케줄, CPU 정체 중 차단 또는 전기적 OFF를 보장하지 않는다.

관련 오프라인 시험:

~~~sh
python3 -m unittest discover -s tests -p 'test_finite_profile_environment_native.py'
python3 -m unittest discover -s tests -p 'test_finite_profile_legacy_guard_native.py'
python3 -m unittest discover -s tests -p 'test_finite_profile_safety_native.py'
python3 -m unittest discover -s tests -p 'test_finite_profile_teleop_native.py'
~~~

서비스 환경 시험은 실제 환경·실행부·드라이버·bounded 서비스를 컴파일하고 주변 제어기 상태를 대역으로 제공한다. 안전 전이 시험은 실제 시스템 상태 관리·안전 모니터·드라이버를 가상 IO와 함께 실행한다. teleop 시험은 실제 입력 파서와 드라이버·실행부를 가상 직렬 입력에 연결해 한 배치의 deadman true→false와 관측 소유권·출력 캐시를 검사한다. dispatcher·웹·각도 제어기 진입점은 별도 실물 동작 검증이 남아 있다. 전체 펌웨어 컴파일은 연결 가능성 확인이며 실물 실행 시험이 아니다.

### 명령별 실제 PWM 쓰기 보존

[드라이버 증거 보관함](../src/motor/finite_profile_output_evidence.h)은 드라이버가 실제 PWM을 쓴 직후의 값·모터·시각·사유를 별도로 저장한다. 같은 값의 반복 쓰기도 생략하지 않는다. 기존 128칸 링의 중복 제거와 덮어쓰기는 그대로 유지되며 이 보관함의 완전성을 결정하지 않는다. 증거는 전기적 PWM 측정이 아니라 소프트웨어 드라이버 쓰기다.

기본 비활성 DRIVER 기능을 켰을 때 32개 명령 각각에 64개 실제 쓰기 공간을 고정 배정한다. 항목은 12바이트, 명령 기록은 964바이트이며 ESP32의 저장소는 인덱스를 포함해 30,856바이트다. 최대 32점 프로파일과 종료의 전모터 0 쓰기 5개는 정상 조건에서 37칸을 사용한다. 이 메모리 한도는 현장 PWM·기간의 안전 한도가 아니다.

예약 응답을 승인하기 전에 해당 명령의 공간을 연결한다. 공간이 없거나 같은 부팅·명령이 이미 보존돼 있으면 실행 토큰을 반환하지 않고 자기 예약·lease만 정리한다. 이전 기록을 자동 축출하거나 같은 ID에 새 출력을 덧붙이지 않는다. 재생성된 bridge가 바인딩에 실패해도 과거 명령의 증거를 자기 결과로 반환하지 않는다.

각 기록은 bootId·commandId·요청 epoch·driver lease·ordinal과 연결되며, 실제 쓰기마다 명령 내 1부터 증가하는 sequence를 가진다. 이 순번은 기존 링의 sequence와 별개다. 실행부 Record의 요청 프로파일/예정점·시각과 outputEvidence의 실제 쓰기를 구분해 조회한다. 저수준 드라이버 시험용 lease에는 기록 없는 사용도 남아 있으나 DriverBridge의 승인 경로는 증거 공간을 필수로 확보한다.

정상 완료만으로 기록을 닫지 않는다. 사후 관측 동안의 추가 OFF와 후속 정지도 계속 기록하고, 해당 lease가 해제될 때 closed와 closedAt을 확정한다. bridge 파괴 시에도 드라이버가 저장소를 소유하므로 강제 OFF를 기록하고 봉인된 lease와 열린 기록을 남긴다. 결과 불명으로 해제할 수 없는 기록도 열린 상태를 유지한다. 보존은 드라이버 객체 수명 동안의 RAM 범위이며 재부팅·전원 소실을 견디는 영속 저장이 아니다.

64칸을 넘으면 앞부분을 보존하고 totalWrites·dropped를 포화 증가시키며 captureComplete=false로 남긴다. 공간이 찬 뒤 추가 비영 출력은 거부하고 OFF를 시도한다. 공간 부족이 OFF를 막지 않으며 이후 누락도 숨기지 않는다. 무제한 정지·재시도의 모든 원본을 유한 메모리에 보존한다는 뜻은 아니다.

core의 traceComplete는 예정 이벤트 영수증의 완전성이고 captureComplete는 실제 쓰기 보관함의 완전성이다. 외부 STOP 뒤 core가 불완전하더라도 raw capture는 완전할 수 있으며, 정상 제어 완료 후 quiet 기록이 넘치면 그 반대도 가능하다. 제어 완료 상태나 어느 한 완전성 필드만으로 학습 적격을 승인하지 않으며, 열린 기록을 최종 원본처럼 취급하지 않는다. 이번 변경은 기존 17개 자료·모델·학습 입력 계약을 바꾸지 않는다.

~~~sh
python3 -m unittest discover -s tests -p 'test_finite_profile_evidence_native.py'
python3 -m unittest discover -s tests -p 'test_finite_profile_capture_native.py'
~~~

시험은 실제 드라이버·실행부를 가상 Arduino IO에 연결해 반복 PWM, 외부 정지, quiet 추가 OFF, 링 덮어쓰기, 기록 포화, 모든 슬롯 보존, 객체 파괴·재생성을 확인한다.

### 실행 스케줄과 실제 기록 연결

[스케줄 어댑터](../src/control/finite_profile_scheduler.h)의 ScheduledDriver는 DriverBridge를 내부에서 소유한다. 실행 요청과 별도로 SchedulerPort의 일회성 알람 등록·취소 경계를 연결하고, 같은 명령의 예정 이벤트 영수증과 실제 outputEvidence를 읽기 전용으로 제공한다. 어댑터 자체에는 전역 인스턴스·HTTP 진입점이 없으며, 아래 별도 런타임이 단일 펌웨어 루프에서 연결한다. RTOS/인터럽트 타이머는 사용하지 않는다. 테스트는 가상 알람과 실제 core·bridge·driver를 함께 실행한다.

한 번에 등록하는 알람은 하나다. 값으로 전달되는 ticket에는 부팅·명령·요청 epoch·driver lease·알람 generation·종류·이벤트 인덱스가 들어간다. 현재 등록과 모두 일치해야 처리한다. 오래된 ticket은 현재 명령을 진행시키는 poll조차 호출하지 않는다. 알람 취소도 전체 ticket을 사용하며, wrapper를 재생성해 generation 숫자가 같아져도 다른 lease의 알람을 건드리지 못한다. 전달받은 ticket은 외부 알람 정리 전에 값으로 복사하므로 포트가 자기 저장소를 초기화해도 처리 중인 이벤트 정보가 바뀌지 않는다.

정상 출력 시각은 처음 수락한 executeAcceptedAt와 startLeadMs, 각 점의 offsetMs로 고정한다. 실제 callback 도착이나 재등록 시각에 맞춰 일정을 뒤로 미루지 않는다. 너무 이른 callback은 비영 출력 없이 원래 시각에 새 generation으로 등록한다. 늦으면 기존 허용 지연 검사로 실패·OFF 처리하며 여러 점을 몰아서 실행하지 않는다.

유지 점검 poll은 예약 만료·안전 변화·다음 점의 허용 시각 초과·OFF 확인만 처리한다. 안전 OFF는 쓸 수 있지만 예정된 비영 PWM은 적용하지 않는다. 정상 점열은 일치하는 ticket의 event 경로로만 전달한다. callback이 사라져도 poll이 계속 호출되면 기한 초과를 발견할 수 있다. 두 경로 또는 CPU가 모두 멎은 동안의 정시 차단을 보장하는 것은 아니다.

취소·등록 실패·객체 파괴는 먼저 ticket을 논리적으로 무효화하고 자기 lease의 OFF를 수행한 뒤 외부 알람을 정리한다. 파괴는 관측 해제나 자동 복구가 아니며 출력 전 예약이라도 봉인된 lease와 열린 capture를 남긴다. 정리 과정의 추가 OFF 쓰기도 실제 기록에 포함된다.

실행 요청 수락과 알람 등록 성공은 별도 결과다. 수락 뒤 등록에 실패하면 이미 소비한 토큰을 복구하지 않고 ScheduleFailed로 종료·OFF 처리한다. 일부 출력이 있었다면 사후 관측 소유권을 유지한다. OFF 확인 중 다음 알람도 등록할 수 없으면 기존 종료 사유·시각을 보존한 채 결과 불명을 확정한다. 나중에 OFF를 확인해도 정상 완료로 승격하지 않는다. 알람 등록 자체가 시간을 소비한 경우에도 수락 기준을 바꾸지 않고 시간을 다시 검사한다.

MOTIONBRAIN_ENABLE_FINITE_PROFILE_SCHEDULER는 기본 0이며 켜려면 driver와 core도 켜야 한다. 이 플래그는 운영 활성화 설정이 아니다. SchedulerPort와 모든 서비스·드라이버 호출은 같은 장치 millis 시계, 외부 직렬화, 비차단·비재진입을 전제로 한다. 알람에는 객체를 가리키는 callback 포인터를 저장하지 않고 값 ticket만 보관한다. 포트·드라이버·환경 객체가 wrapper보다 오래 살아야 하며 파괴된 wrapper에 호출하는 수명 오류를 ticket 검사로 해결할 수는 없다.

~~~sh
python3 -m unittest discover -s tests -p 'test_finite_profile_scheduler_native.py'
python3 -m unittest discover -s tests -p 'test_finite_profile_maintenance_native.py'
~~~

가상 시계 검증은 시간 wrap, 이른/늦은/중복 callback, 취소 뒤 callback, 새 소유자와 과거 ticket, 첫·중간 알람 등록 실패, 알람 처리 시간, OFF 확인 대기와 실패를 포함한다. 최악의 실물 지연·우선순위 역전·인터럽트/잠금 지연·독립 차단 필요성은 여전히 계측·결정 대상이다.

### 단일 프로파일 실물 연결

별도 빌드 환경 `esp32dev_m2_finite_trial`은 core·driver·scheduler·runtime을 명시적으로 켠다. 기본 환경은 계속 비활성이다. 부팅은 실행 준비만 하며 ARM이나 출력, 과거 명령 재개를 하지 않는다. 기존 bounded 서비스와 같은 부팅 ID를 쓰고 Wi-Fi 초기화 뒤 장치 난수로 일회성 토큰을 발급한다.

신뢰된 목록은 M2 위 방향의 한 프로파일 `m2-triangle40-350-v1`만 포함한다. 50ms 간격으로 PWM +10, +20, +30, +40, +30, +20, +10, 0을 요청한다. 예정 출력 기간은 350ms, 시작 준비 기간은 300ms, 점별 허용 지연은 20ms, OFF 확인 창은 100ms, 예약 만료는 10초다. 예정 PWM 시간적분은 8 PWM·s다. 이전 자료보다 작은 입력을 고른 시운전 조건이며 기계적 안전 한도나 각도 변화 보장은 아니다.

목록 해시는 canonicalProfile의 catalogHash 행 전체를 제외한 LF 문자열의 SHA-256이다. 요청은 profileId와 catalogHash를 지정하지만 PWM·기간·점열을 바꾸지 못한다. 조회 응답의 requestedProfile은 요청값이고 actualOutput은 실제 소프트웨어 드라이버 쓰기다. 이 기록은 전기적 파형 계측이나 모터의 물리적 정지 증명이 아니다.

~~~http
GET /finite_profile
POST /finite_profile
GET /finite_profile?bootId=...&commandId=...
~~~

모든 경로는 기존 X-MotionBrain 및 X-MotionBrain-Token 인증 헤더를 요구한다. POST는 form 필드 operation, bootId, commandId, epoch를 받는다. prepare에는 profileId·catalogHash, execute에는 prepare에서 한 번 받은 token이 필요하다. cancel은 요청 epoch, release는 결과의 quietEpoch를 사용한다. 중복 prepare는 토큰을 재발급하지 않는다. 인증값·실행 토큰은 원본 작업 기록으로만 보관하며 공개 예시에 넣지 않는다. 조회 불일치는 실행하지 않았다는 증거가 아니다.

실행 스케줄은 같은 main task의 millis 시계에서 검사한다. 루프마다 유지 점검 후 예정된 ticket을 최대 하나 전달한다. Running의 준비 기간부터 Stopping까지 HTTP 처리·일반 시리얼 명령·Wi-Fi 로그·M4 I2C 진단을 미룬다. STM32와 teleop 입력은 회당 최대128바이트로 제한하고, 새 입력의 안전 상태를 평가한 직후 한 곳에서만 예정 출력을 전달한다. 실행창의 동기 UART 로그는 생략하고 suppressedSerialLogs에 누적 개수만 남겨 깨진 입력의 로그 폭주가 출력을 연장하지 않게 한다. execute 응답 전송이 첫 마감보다 늦어져도 일정을 미루거나 따라잡지 않고 OFF로 실패한다.

이 짧은 창에는 HTTP STOP과 일반 시리얼 STOP도 처리되지 않는다. 센서 안전 감시와 teleop deadman에 의한 소유권 봉인은 계속되며, 시운전에는 즉시 끌 수 있는 모터 전원과 이동 여유 공간이 필요하다. CPU 전체 정체 중 독립적으로 정시 차단하는 하드웨어 보장은 없다. 늦은 출력은 이후 발견해 OFF하므로 허용 지연만으로 최악 출력 기간을 보증하지 않는다.

명령 결과는 요청 시각·예정 시각·실제 이벤트 영수증·raw 쓰기 순번과 시각을 함께 반환한다. 출력 뒤 관측 소유권을 유지하고, 기록을 읽은 뒤 명시적 release로 닫힌 기록을 다시 읽어 호스트 파일에 보존한다. 재부팅을 견디는 장치 저장소나 자동 호스트 재시도는 제공하지 않는다. 한 번의 실행 결과가 불명확하면 재전송하지 않고 마감한다.

## 학습용 첫 수집 설계

2026-11-03에 고정 목록과 호스트 오프라인 검증기를 구현했다. 고정 네 조건 펌웨어의 업로드는 완료했다. **첫 촬영 시도는 ARM 전 사전 계측에서 거부되어 네 조건의 실물 구동은 미검증이다.** 목표는 M2의 명령별 영상 변화를 학습해 후보 명령 선택과 목표 접근으로 연결하는 것이다. 조명과 카메라 구도를 유지하고, 표식 재배치·추가 정지 촬영을 선행 조건으로 두지 않는다. 기존 시운전의 작은 변화만으로 출력 증가가 필요하거나 안전하다고 결론내리지 않는다.

### 후보 네 조건과 선택 이유

최대 PWM은 255 기준 정수 듀티 값이며 퍼센트가 아니다. 같은 50ms 간격·10count 증감의 삼각파 두 수준을 비교한다. U는 위 방향(+), D는 아래 방향(−)이며 실제 방향과 현재 이동 여유는 새 실행 전에 다시 확인한다.

| 조건 | 부호 PWM 점열 | 예정 비영 기간 | 예정 절대 PWM 시간적분 | 실물 확인 상태 |
| --- | --- | ---: | ---: | --- |
| U4 | +10,+20,+30,+40,+30,+20,+10,0 | 350ms | 8 PWM·s | 기존 단발 출력·영상 기록 있음 |
| D4 | −10,−20,−30,−40,−30,−20,−10,0 | 350ms | 8 PWM·s | 새 방향 시운전 필요 |
| U5 | +10,+20,+30,+40,+50,+40,+30,+20,+10,0 | 450ms | 12.5 PWM·s | 새 프로파일 시운전 필요 |
| D5 | −10,−20,−30,−40,−50,−40,−30,−20,−10,0 | 450ms | 12.5 PWM·s | 새 프로파일 시운전 필요 |

각 점의 오프셋은 표의 왼쪽부터 0,50,100,…ms다. 4조건 묶음은 미검증이며 기존 +40 한 조건의 확인을 양방향 검증으로 확대하지 않는다. N5는 N4보다 최대 PWM 25%, 기간 약 28.6%, 적분 56.25%가 함께 증가한다. 따라서 PWM만의 효과를 분리하는 시험이 아니라 두 고정 프로파일의 반응 비교다. 선택한 삼각파군에서 인접한 두 수준이라는 뜻이며, 물리적으로 최선이거나 가장 안전한 증분이라는 뜻은 아니다.

최대 PWM 40을 그대로 두고 정상 최대값 유지 50ms에 100ms를 더하는 후보도 비교했다. 총 450ms·12 PWM·s여서 유지시간 효과를 따로 보기 좋지만, 40이 실제 정지마찰을 넘지 못한다면 유지시간 증가만으로 유용한 차이가 생기지 않을 수 있다. 현재 자료로 이 마찰 가설은 확인되지 않았다. 이 후보는 첫 묶음에서 제외하고, 최대 PWM 60·550ms·18 PWM·s도 첫 범위에 넣지 않는다. 예전 실제 출력 범위와 겹친다는 사실을 새 파형의 동등성·안전 근거로 사용하지 않는다.

| H: 이후 보류 평가 | 8 | 모델·입력·평가 규칙을 고정한 뒤 새로 획득하는 별도 세션의 블록 2개. 조건당 2회이며 작은 후속 확인이다. |

총 24개는 계획한 신규 시도의 상한이지 유효 24행 확보 보장이나 통계적 검정력 기준이 아니다. P→D→H를 한 번에 자동 진행하지 않는다. P에서 얻는 모든 작은 변화·0 근처 변화도 계측과 명령 대응이 유효하면 보존한다. 모두 반응 구별이 불명확하면 동일 후보로 D의 12회를 소진하지 않고, 자료를 검토해 계획을 다시 정한다. 실패·미시작을 대체 명령이나 자동 추가 촬영으로 채우지 않는다.

현재 상태에서 이어서 관측하며 정밀한 시작 자세 맞춤·원위치 복귀용 명령을 추가하지 않는다. 같은 크기의 위·아래 명령도 중력·마찰·유격 때문에 서로 상쇄된다고 가정하지 않는다. 매 명령의 현재 관측과 이동 여유가 계획을 허용하지 않으면 중단하고 남은 슬롯은 미시작으로 보존한다. 순서를 바꾸거나 새로운 복귀 동작을 만들어 계획을 완주하지 않는다. 각 블록 전체를 분할 단위로 유지하며 인접 프레임이나 명령을 무작위로 섞지 않는다. 이전 명령·방향 전환 여부·경과시간과 시작 자세를 기록하고 조건별 분포 차이를 함께 보고한다.

고정 명목 순서는 P=[U4,D4,U5,D5], D1=[U4,D4,D5,U5], D2=[D4,U5,U4,D5], D3=[U5,D5,D4,U4], H1=[D5,U4,U5,D4], H2=[D4,U5,U4,D5]다. 각 개발·보류 블록은 네 조건을 한 번씩 포함하고 같은 방향의 연속 명령도 포함한다. 이 순서는 이력 효과를 완전히 균형화하거나 자세 분포를 같게 만들지 않는다. 현 자세에서 명목 순서를 시작할 수 없다면 해당 단계는 시작하지 않으며, 시작 후 다음 슬롯이 불가능하면 그 블록과 현재 단계를 종료한다. H1/H2를 같은 새 세션에서 얻으면 보류 그룹 하나의 두 블록이며 독립 그룹 두 개가 아니다.

명령당 기존 단발 영상 하나를 기록하고 네 영상을 논리 블록으로 묶는다. 연속 영상 하나에 여러 명령을 넣는 실행기를 새로 만들 필요는 없다. 영상마다 고유 촬영·시계·명령 식별자를 쓰되 블록/세션 관계를 보존한다. 기존 영상당 상한은 60초·최대 8fps·500프레임·4,179,968,000바이트이며 정상 완료 시 계측 후 조기 종료한다. 단계별 최대 저장 예산은 P 약 16.72GB, D 약 50.16GB, H 약 33.44GB다. 이는 최악 허용량의 합이며 실제 촬영 시간이나 압축 크기 예측이 아니다. 단계 시작 전에 해당 단계 예산과 2GiB 여유를 확인하고 부족하면 시작하지 않는다. 기존 원본을 지워 공간을 만들거나 자동으로 추가 촬영하지 않는다.

### 입력·정답·평가 경계

기존 전관측 창인 사전 앵커 −0.75~−0.10초와, 호스트 OFF 확인 영수증 +2.25~+3.00초의 후관측 창을 유지한다. 최소 3프레임·간격 최대 0.3초·창 범위 최대 0.5° 조건을 완화하지 않는다. 후관측 오프셋을 장치 실제 OFF 시각 또는 명령 시작+4초로 바꾸지 않는다. 창이나 추적 설정을 변경하면 새 계약으로 구분한다.

사전 입력에는 실행 전 고정한 현재 투영각·후보 방향·예정 프로파일 특성을 사용한다. 실제 PWM 쓰기·실제 출력 기간·실제 적분·종료 이유·후관측은 사후 설명과 적격성 심사에만 사용한다. 이전 명령 이력도 판단 시점까지 확정된 값만 저장한다. 원본 점열과 시각은 모두 남기되, 두 수준에서 함께 변하는 peak·기간·적분을 각각 독립적인 효과로 추정하지 않는다.

첫 비교는 무변화 예측과 네 명령 조건별 평균, 작은 릿지 모델로 제한한다. 릿지 입력은 현재 투영각·방향·예정 부호 PWM 적분의 세 항목과 절편으로 고정하고, 규제 계수 후보는 0.1·1·10으로 둔다. 목적함수는 잔차 제곱합 + α‖β‖²이며 절편은 규제하지 않는다. 각 fold에서 제외한 한 블록을 뺀 나머지 두 블록의 합집합으로 표준화와 조건별 평균을 계산하며 상수 열은 척도 1로 두고 보류 블록에는 학습부분의 평균·척도를 그대로 적용한다. 조건당 개발 유효 자료 3개(각 블록 1개)가 없는 경우 이 첫 비교는 수행하지 않고 자료와 부족 이유를 보존한다. 이 최소 수는 3블록 비교의 구성 조건이며 성능 보장이 아니다. 개발 블록 하나씩을 통째로 제외하는 탐색 평가에서 같은 행·같은 분모로 비교하며, 평가 블록의 정답이나 전체 자료로 정규화·조건 평균을 구하지 않는다. 세 블록의 보류 예측을 합친 MAE로 후보를 비교하고 동률이면 무변화→조건별 평균→더 큰 규제 계수의 릿지 순으로 선택한다. 선택 결과와 모든 후보 점수를 보존한 뒤 개발 12개 전체에서 평균·척도와 선택 모델을 다시 계산해 고정한다. 릿지가 기준선보다 나쁘면 기준선을 유지하며 학습 모델이 개선됐다고 표현하지 않는다. H에서는 조건별 유효 수와 전체 실패 분모를 함께 보고하며 네 조건 중 하나라도 유효 행이 없으면 전체 조건 평가 미완료로 남긴다. 조건별 1/2만 유효한 경우 등은 유효 관측에 조건부인 평가로 표시하고 8개 완결 평가로 표현하지 않는다. 개발 시작 자세 범위를 벗어난 H 관측은 외삽 여부를 별도 표시하며 유리한 행만 남기지 않는다. GP·신경망·불확실성 기반 자동 탐색은 이 첫 묶음에 추가하지 않는다. 사전 각도를 입력으로 쓰고 after−before를 정답으로 쓰면 같은 전관측 오차가 양쪽에 공유될 수 있으므로 작은 MAE만으로 실제 물리 응답을 잘 배웠다고 주장하지 않는다.

MAE·최대 절대오차·편향과 조건별 결과, 전체 시도/유효/실패/미시작 수를 함께 보고한다. 방향 일치는 작은 변화에서 불안정하므로 보조 지표로만 사용한다. 무명령 최대 차이 0.360°를 통계적 검출 문턱이나 성공 판정으로 사용하지 않는다. 미래 H도 고정 구도의 소규모 새 세션 확인이며 일반적 독립 시험 성능이나 다른 자세·날짜·구도 일반화 보장이 아니다. H를 본 뒤 모델이나 후보를 바꾸면 그 H는 이후 모델의 미열람 시험 자료가 아니다.

기존 17개 development 전이, 과거 +4초 계약 32개·MAE 0.665°, 이전 finite 단발 및 이번 시운전 자료를 D/H에 자동 혼합하지 않는다. P는 후보 선정과 시운전 근거로 별도 보관한다. 첫 평가만으로 자동 제어 적격을 부여하지 않고, 다음 목표 접근 시험의 예측·실제 오차·보류/실패를 따로 확인한다.

### 실행 전에 필요한 최소 연결

단일 프로파일을 고정했던 catalog·runtime·HTTP 선택부를 네 조건의 명시 목록으로 확장했다. 기존 U4 ID·해시와 GET의 단일 profile 필드는 유지하고 profiles 배열에 전체 목록을 반환한다. 공통 core·driver·scheduler의 출력 소유권과 실패 처리는 재사용한다. 임의 PWM·기간·점열 업로드 API는 추가하지 않는다. 호스트의 단발 실행·사전 영수증·닫힌 출력 기록·전후 계측은 재사용하되, 고정된 조건/블록 명세와 실제 목록 해시를 대조하고 불일치 시 실행하지 않아야 한다.

장치의 명령별 보관함은 부팅당 32칸이므로 각 단계 전 기존 예약까지 포함한 남은 용량을 확인한다. GET은 coreRecordsUsed·driverRecordsUsed와 각 RecordCapacity를 읽기 전용으로 제공한다. 가용량은 두 저장소의 남은 수 중 작은 값으로 검사한다. N4는 예정점 8개, N5는 10개이며 정상 경로의 최소 실제 쓰기는 전모터 OFF 5개를 합친 13개·15개다. 사후 추가 0 쓰기는 별도로 검증하며 명령당 64칸 제한을 유지한다. 실패하거나 취소된 예약도 슬롯을 소모할 수 있으며 자동 해제·재부팅으로 용량을 만들지 않는다. 재부팅 전 원본 보존과 이후 새 부팅 확인은 별도 절차다. 시도 상한만으로 출력 기록 공간이 충분하다고 판단하지 않는다.

[호스트 검증기](../learning/finite_profile_plan.py)는 목록·설계 명세·두 보관함 용량·P 단계 순서·첫 두 명령 검토 여부·사전 입력 세 항목을 검사한다. 통신·촬영·ARM·학습은 수행하지 않으며, 호출자는 전송 전 영속 시도 기록과 현재 부팅·물리 여유 확인을 담당한다. 새 목록의 방향·점열·해시·거부 경로와 중단·재시도 금지·입력 누설 방지를 오프라인으로 검증하고 관련 빌드를 확인한 뒤 별도 업로드·실물 절차로 이어간다. 기계적 경계 접근, 표식/ROI 이탈, 예상 밖 동작, 출력 결과 불명, 기록 누락 또는 계측 실패에는 현재 단계를 종료한다. 작은 유효 변화와 계측 실패는 구분한다. CPU 정체 중 독립 차단과 전기적 파형은 여전히 미검증이다. 연구에서 가져온 판단과 적용 한계는 [연구 근거](research/visual-action-learning.md#소규모-수집에서-가져올-판단-2026-11-03)에 정리했다.

### 고정 준비 시간 묶음과 오프라인 학습 연결

후속 묶음은 촬영 시작 후 고정 3초 준비 시간만 추가하고 원시 계측 기준을 유지했다. 이 대기가 최적이거나 안정화를 보장한다고 검증된 것은 아니다. P 4회와 D 12회, 최대 16회 중 첫 촬영은 P1 표식 검출 실패로 ARM 전에 종료했다. 저장 27프레임에서 유효한 네 점 검출은 0회였고, ARM·execute·유효 전이는 각각 0회, 나머지 15회는 미시작이다. 저장 대표 영상의 구도가 이전 영상과 달라 기존 ROI와 맞지 않는 정황이 있으며 조명 원인은 확정하지 않았다. 두 종료 시도는 재전송하거나 자동 대체하지 않는다.

[배치 학습 모듈](../learning/finite_batch_learning.py)은 명시적 인덱스의 16개 슬롯을 읽어 수집 결과 검증→개발 데이터셋→단순 모델 학습·블록 탐색 평가를 연결한다. 장치 통신이나 수집은 수행하지 않는다. 실패 또는 미시작 슬롯 뒤에 추가 시도가 있으면 묶음 전체를 거부한다. 시운전 자료는 학습에서 제외하며 이전 계약이나 다른 수집 그룹을 합치지 않는다.

인덱스는 `motionbrain.finite_batch_index.v1` 형식으로 계약·수집 그룹·고정 3초 준비 정책·계측 설정 참조와 모든 슬롯을 포함한다. 슬롯마다 고유 ID·명령 조건·역할·논리 블록·촬영 경로를 기록하고, 시작한 슬롯에는 결과 및 존재하는 근거 파일의 상대 경로와 SHA-256을 둔다. 미시작 슬롯도 삭제하지 않고 사유를 남긴다. 적격 슬롯에는 결과·촬영 보고서·계측 결과·사전 영수증·닫힌 출력 기록·실행 전 입력이 모두 필요하다. 해시는 원본 연결과 변경 검출용이며 인증 서명은 아니다.

저장한 인덱스에 대한 오프라인 사용 예시는 다음과 같다. 실제 데이터의 학습 전에는 `reaudit_frames=True`로 적격 슬롯의 원본 프레임을 다시 계측한다. 캐시와 불일치하면 유리한 행만 제외하지 않고 오류로 중단한다. 거부된 슬롯은 실패 분모로 보존하며 이 옵션으로 적격 자료가 되지 않는다.

```python
import json
from pathlib import Path
from learning.finite_batch_learning import run

result = run(Path(".local/finite-batch/dataset-index.json"), reaudit_frames=True)
with Path(".local/finite-batch/learning-result.json").open("x") as output:
    json.dump(result, output, ensure_ascii=False, indent=2, allow_nan=False)
```

학습 입력은 현재 영상의 투영각·예정 방향·예정 부호 PWM 적분뿐이다. 실제 출력은 사후 검증·진단에만 남긴다. 개발 유효 행이 없으면 학습하지 않는다. 일부 행만 있으면 전체 적합의 기술적 잔차만 계산하며, 개발 3블록 12행이 모두 있어야 블록 탐색 평가와 후보 선택을 수행한다. 그 점수는 같은 수집 그룹의 모델 선택용이며 독립 시험 성능이 아니다. 잔차 표준편차는 보정된 예측 구간이 아니고 자동 제어 적격도 부여하지 않는다.

2026-11-04 저장 묶음의 오프라인 연결 확인 결과는 계획 16·시도 1·거부 1·미시작 15·학습 행 0이다. 적격 슬롯이 없어 원본 전후 프레임 재계측과 실제 모델 학습·평가는 수행되지 않았다. 합성 자료 테스트는 중단·근거 연결·사후 입력 누설 방지·블록 분할 및 학습 부분만의 표준화를 검증하며 실물 예측 성능을 입증하지 않는다.
